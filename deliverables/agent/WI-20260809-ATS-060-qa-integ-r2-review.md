- **Approved-policy fidelity:** The four Section 2 decisions remain verbatim transcriptions of the approved handoff: separate Terms and Privacy consent, optional independent marketing, verified-only authenticated sessions, bounded `returnTo`, and hybrid server-first logout.
- **Privacy minimization:** The durable consent record is limited to account identity, consent category, immutable document version, and server-generated agreement timestamp. The decision selects neither IP address nor device fingerprint, and it does not add a retention period, schema design, or timestamp representation.
- **Schema approval hold:** The decision record explicitly leaves schema structure unselected and holds it for later explicit schema-change approval. This matches the approved REQ, which separately requires approval for database schema changes.
- **Current versus future boundary:** The record correctly says current registration/entity/schema lack consent fields, and current login, social login, and refresh issuance lack an `isVerified` gate. It records these as observed gaps and assigns all enforcement to future approved work; it does not represent the current product as compliant.
- **Logout implementation boundary:** Current frontend behavior still treats every `401` as terminal and does not ensure awaited/coalesced caller settlement. This is accurately retained as an observed noncompliance to be corrected by the future auth/logout work; it does not weaken the approved future contract.
