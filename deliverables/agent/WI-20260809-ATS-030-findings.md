## Independent Findings

### F-QAFE-030-001 - P2 - NEW - Global playback shortcuts hijack focused controls

- Invariants/lanes: `INV-PLAY`, `INV-TRACK`; `K=FAIL`; adjacent shared-root regression risk across every `MainLayout` route.
- Exact source: `frontend/src/layouts/MainLayout.tsx:13-49`; `frontend/src/store/playerStore.ts` playback navigation actions.
- UI/DOM lane: the document-level handler excludes only `INPUT`, `TEXTAREA`, and `SELECT`. Space and ArrowUp/ArrowDown remain active while focus is on buttons, links, sliders, and contenteditable controls.
- Invocation lane: Space calls the Player toggle and calls `preventDefault`; ArrowUp/ArrowDown call previous/next whenever `trackListContext` is populated. A focused control can therefore lose its native keyboard action or invoke playback navigation in addition to its own behavior.
- Server-response lane: `NOT RUN`; playback stream requests may follow a Track change, but no request was issued.
- Durable-state lane: no server mutation is required; Player/queue/history context is browser-local. Runtime persistence behavior is `NOT RUN`.
- Existing assertion boundary: `frontend/src/layouts/PlayerBar.test.tsx:220-238` proves the seek slider's own Arrow/Home/End behavior, and `frontend/src/test/coverage/shellCatalogRouterGaps.coverage.test.tsx:630-648` exercises that local slider handler. Neither mounts `MainLayout` with focus on another button, link, range, dialog control, or contenteditable target, so neither disproves the document-level collision.
- Impact: keyboard users can accidentally change or pause a Track while operating unrelated navigation, dialog, or media controls.
- Bounded remediation/testing: ignore events from all interactive/contenteditable targets, respect modifier keys and default-prevented events, and scope navigation shortcuts to an explicitly active playback surface. Add focused-button/link/range/dialog tests plus one positive non-interactive shortcut test.

### F-QAFE-030-002 - P1 - NEW - Queued 401 replays are not marked as retried

- Invariants/lanes: shared auth; duplicate/stale-response lane; route-departure and logout-fallback risk.
- Exact source: `frontend/src/api/client.ts:100-149`; existing assertions at `frontend/src/api/client.test.ts` under `client auth refresh exclusions`.
- UI/DOM lane: an eventual refresh failure clears the visible identity and redirects, but concurrent outcomes were not executed.
- Invocation lane: the initiating request receives `_retry=true`; requests queued while `isRefreshing` is true are replayed without setting `_retry`. If the rotated access token also receives `401`, each queued replay can enter refresh again sequentially instead of terminating after the one bounded refresh attempt.
- Server-response lane: `NOT RUN`; the risk requires delayed concurrent `401` responses and a second rejected token.
- Durable-state lane: local tokens can rotate and later be cleared; no server-side durable mutation is implied. Exact local-storage transitions under the race are `NOT RUN`.
- Existing assertion boundary: the current test proves one refresh, token rotation, one request replay, storage-write failure, and a single refresh failure. It does not race multiple queued requests or reject their replays with another `401`.
- Impact: one expired session can create repeated refresh traffic, non-deterministic request completion, and delayed forced logout.
- Bounded remediation/testing: mark every queued request as retried before replay or centralize one-attempt metadata; add deferred three-request tests asserting one refresh maximum, one terminal failure per request, one session clear, and no replay loop.

### F-QAFE-030-004 - P2 - NEW - Shared logout callers navigate before the logout transaction settles

- Invariants/lanes: shared auth/logout fallback; duplicate invocation; route departure.
- Exact source: `frontend/src/layouts/Header.tsx:189-192,300-303`; `frontend/src/layouts/AdminLayout.tsx:51-59`; `frontend/src/store/authStore.ts:141-151`; `frontend/src/api/auth.ts:159-168`.
- UI/DOM lane: Header and ADMIN logout controls have no shared pending/disabled/error state.
- Invocation lane: callers invoke async `logout()` without awaiting it and navigate immediately. A repeated action can overlap the POST while the old local session remains until the request resolves or fails.
- Server-response lane: the store treats a server `401` as confirmed and clears local state in `finally`; no response was exercised.
