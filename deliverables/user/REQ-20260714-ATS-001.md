[SUCCESS CRITERIA (DoD)]
- P1 13건 각각에 설계-코드-테스트-문서 증거가 있고 감사 종료 조건을 충족한다.
- Provider 실패 후 로컬 실패 원장이 롤백되지 않으며 동일 결제 명령은 하나의 최종 결과로 수렴한다.
- 갱신은 계약·결제 주기별 독립 트랜잭션으로 처리되고 이전 주기 주문을 재사용하지 않는다.
- 동시 환불 요청이 원 결제 가능 금액을 초과 예약하지 않는다.
- Java 결제 감사 action/target 값과 실행 MySQL DDL이 일치하고 disposable MySQL에서 Hibernate validate를 통과한다.
- 업로드된 이미지·기업 문서는 허용 콘텐츠만 저장/다운로드되며 HTML/SVG/polyglot 또는 위조 MIME이 활성 콘텐츠로 공개되지 않는다.
- 로그아웃·비밀번호 변경·재설정 후 기존 refresh token으로 재발급할 수 없다.
- 파일 작업 실패나 DB 롤백 후 고아 파일·손실된 참조가 남지 않으며 재시도 가능한 복구 증거가 있다.
- CSV의 `=`, `+`, `-`, `@` 시작 셀이 spreadsheet formula로 실행되지 않는다.
- 신규 소셜 로그인은 토큰을 확정한 뒤 사용자 정보를 조회하고 실패 시 부분 로그인 상태를 남기지 않는다.
- Cloudflare HTTPS URL에서 SPA, `/api`, `/uploads`, 로그인, 음원 재생, 원본 차단, Toss test billing callback, 주요 관리자 흐름이 검증된다.
- 외부 인수환경은 wildcard CORS/Host 허용, 기본 bootstrap 비밀번호, secret 로그 노출 없이 실행된다.
- 백엔드/프론트 전체 테스트, 컴파일/typecheck, lint/scoped Prettier, 양쪽 build, 문서 validator와 `git diff --check`가 통과한다.
- 클라이언트에게 전달할 쉬운 한글 체크리스트와 실행 URL·제약사항이 준비된다.

[RISKS / OPEN QUESTIONS]
- Risks:
  - 결제 잠금·고유 제약은 기존 데이터와 충돌할 수 있어 disposable MySQL 검증 전 실제 DB에 적용할 수 없다.
  - Provider 성공 후 로컬 실패 보상은 외부 부작용과 DB 트랜잭션을 분리해야 하므로 회귀 위험이 높다.
  - 이미지 재인코딩과 문서 시그니처 검사는 파일 호환성 및 처리 비용에 영향을 줄 수 있다.
  - 신뢰 프록시 헤더를 잘못 허용하면 IP 위조가 가능하고, 너무 좁게 허용하면 모든 클라이언트가 같은 rate-limit key를 공유할 수 있다.
  - Quick Tunnel URL 변경으로 Toss callback이 매 실행마다 달라진다.
- Questions resolved by approved defaults:
  - Cloudflare는 프론트 5173 한 개만 공개하고 `/api`, `/uploads`는 Vite same-origin proxy를 사용한다.
  - Toss callback URL은 터널 발급 후 acceptance launcher가 환경변수로 주입한다.
  - 실제 DB 적용·데이터 초기화는 구현과 분리하여 별도 승인받는다.
  - 전체 P2/P3와 운영 이력 증명은 이번 종료 조건에 포함하지 않는다.
