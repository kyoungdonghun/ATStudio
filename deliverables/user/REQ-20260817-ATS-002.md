[GOAL / WHY]

- 이전의 일회성 DB 패치 시도는 두 번 모두 DB 연결과 DDL 전에 중단되었다. 첫 번째는 임시 PowerShell 래퍼가 예약 자동 변수 `$Host`에 할당한 결함이고, 두 번째는 원시 컴파일 진단을 인간이 열람하지 않아 원인이 분류되지 않은 Java 러너 컴파일 실패다. 어느 실패도 DB 연결이나 DDL에 도달하지 않았다.
- 현재 DB, 기존 비공개 번들, 비밀값을 먼저 건드리지 않는 소스 전용 컴파일ㆍ러너 준비성 진단으로 도구 체인 상태를 판정한다. 그 진단이 정제된 `PASS`일 때에만, 이미 확정된 동일 번들을 메모리에서 엄격히 범위 검증한 뒤 승인된 패치를 정확히 한 번 실행ㆍ검증한다.

[SUCCESS CRITERIA (DoD)]

- WI-001은 DB, 비공개 번들, 비밀값을 읽거나 사용하지 않는다. 비예약 변수명만 사용하는 외부 휘발성 PowerShell 래퍼가 최소 Java 골격의 `javac`와 MySQL Connector/J 클래스패스를 확인하고, 원시 진단을 검토하지 않은 정제 결과 코드로 `PASS` 또는 `FAIL`을 판정한다.
- WI-001 종료 시 모든 임시 산출물은 삭제되며, `PASS`가 아닐 경우 WI-002는 차단된다. 차단 상태에서는 DB 연결, 번들 접근, 컴파일 재시도, 수리 또는 다른 작업을 시작하지 않는다.
- WI-002는 WI-001의 `PASS` 뒤에만, 별도로 새로 컴파일되어 성공이 확인된 외부 휘발성 러너를 사용한다. 동일한 사전 확정 비공개 번들의 모든 형식ㆍ완전성ㆍ엄격 범위 조건은 메모리 안에서만 검증한다.
- WI-002의 유일한 허용 DB 동작은 연결 1회, 예상 객체 부재 확인 1회, 지정 패치 정확히 1회, 사후 구조 델타 확인 1회다. 사전 확인이 기대 결과가 아니거나 어떤 조건이 실패ㆍ모호ㆍ불일치하면 패치 전에 즉시 중단한다.
- WI-002 성공은 예상 객체 `PRESENT`, 제거 수 `0`, 예상 밖 추가 수 `0`의 정제된 증거로만 인정한다. 모든 증거에는 상태 코드, 범위 판정, 객체 상태, 추가ㆍ제거 수만 남긴다.

[CONSTRAINTS / POLICIES]

- Work tracking unit: WI. 본 REQ의 실행은 사용자 상시 승인에 근거하지만, 범위ㆍ정책ㆍ설계 판단을 바꾸지 않는다.
- Fail closed: 조건이 알 수 없거나, 거짓이거나, 불완전하거나, 모호하거나, 일치하지 않으면 즉시 중단한다. 추정, 완화, 대체 입력, 자동 수리, 우회, 재시도는 허용하지 않는다.
- WI-001은 source-only 진단이다. DB 연결, 비공개 번들 접근, 비밀 접근, SQL 실행은 금지한다.
- WI-002는 WI-001의 정제된 `PASS` 결과가 유일한 시작 조건이다. 이전에 컴파일된 러너나 이전 임시 산출물을 재사용하지 않는다.
- 비공개 번들과 DB 대상은 인간에게 불투명하게 유지한다. 값, 식별자, 위치, 내용, 연결 정보, 자격 증명, 원시 오류ㆍ출력을 명령, 로그, 산출물에 포함하지 않는다.
- 패치 실행은 단발이다. 어떤 실패도 반복ㆍ수리ㆍ롤백ㆍ보상ㆍ삭제ㆍ`DROP`ㆍ추가 SQL을 정당화하지 않는다.
