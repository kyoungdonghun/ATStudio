[GOAL / WHY]
- ATStudio의 기존 화이트리스트 채널 기능을 현재 클라이언트 요구에 맞게 확정한다.
- 사용자는 YouTube 채널 정보를 여러 개 저장하고, 구독 플랜 한도 내에서 화이트리스트 등록 요청 대상을 관리할 수 있어야 한다.
- 운영자는 사용자가 요청한 채널 정보를 확인하고, 외부 등록 대행/YouTube 처리용 CSV를 내보낸 뒤, 수동 처리 결과를 시스템에 기록할 수 있어야 한다.
- 회원가입 시 YouTube 채널 정보는 필수값이 아니다. 다만 가입 이후 언제든지 개인정보/화이트리스트 관리 화면에서 추가·수정할 수 있어야 한다.

[SCOPE]
- In:
  - 기존 `whitelist_channels` 도메인을 사용자 1:N YouTube 채널 목록으로 확장한다.
  - 채널별 입력 정보에 `channelName`, `youtubeHandle`, `channelUrl`, `youtubeChannelId`를 포함한다.
  - 사용자가 대표 채널을 하나 설정할 수 있게 한다.
  - 사용자가 채널을 저장만 할지, 화이트리스트 등록 요청 대상으로 올릴지 선택할 수 있게 한다.
  - 플랜별 `subscriptions.max_whitelist_channels` 기준으로 화이트리스트 등록 요청/처리 가능 개수를 제한한다.
  - 관리자 화면에서 화이트리스트 채널 목록과 처리 상태를 조회한다.
  - 관리자가 등록 요청 채널을 CSV로 내보낼 수 있게 한다.
  - CSV export batch/item 이력을 남겨, 어떤 채널이 언제 누구에 의해 외부 처리 대상으로 전달됐는지 추적한다.
  - 관리자가 수동 처리 결과를 상태로 기록한다.
  - API spec, DB schema, use case, UI flow, client scenario 문서를 현행화한다.
- Out:
  - YouTube API/OAuth를 통한 채널 소유 인증.
  - YouTube 또는 외부 등록 대행 사이트로의 자동 API 등록.
  - Content ID/저작권 관리 시스템과의 직접 연동.
  - 회원가입 시 YouTube 채널 정보 필수화.
  - `users` 테이블에 대표 YouTube 채널을 단일 필드로 저장하는 구조.
  - 다운그레이드 시 적용 채널을 강제로 재선택하게 하는 고급 UX. 단, 후속 확장을 고려해 상태/한도 구조는 설계한다.

[DOMAIN DECISIONS]
- 화이트리스트 채널은 사용자 기본 프로필 필드가 아니라, 사용자에게 종속된 별도 채널 목록 도메인이다.
- `users : whitelist_channels = 1 : N` 구조를 유지·확장한다.
- 대표 채널(`isPrimary`)은 기본 표시/운영자 식별 편의를 위한 개념이며, 반드시 화이트리스트 적용 채널과 같을 필요는 없다.
- 플랜 한도는 저장된 전체 채널 수가 아니라, 화이트리스트 적용 요청 또는 처리 중인 채널 수를 기준으로 계산한다.
- 실제 외부 등록 행위는 운영자가 시스템 밖에서 수동으로 처리한다.
- 시스템은 수동 처리를 돕기 위해 CSV export와 상태 추적을 제공한다.
- `REVISION_REQUESTED` 상태도 사용자가 이미 요청한 슬롯으로 보아 플랜 한도에 포함한다.
- CSV에는 외부 등록 실무 식별을 위해 `userEmail`을 포함한다.
- 사용자가 채널을 삭제할 때는 외부 처리 전 상태와 외부 처리 후 상태를 구분한다.

[PROPOSED STATUS MODEL]
- `DRAFT`: 사용자가 저장만 한 채널. 플랜 한도에 포함하지 않는다.
- `PENDING`: 사용자가 화이트리스트 등록을 요청한 채널. 플랜 한도에 포함한다.
- `EXPORTED`: 관리자가 CSV로 내보내 외부 처리 대상으로 전달한 채널. 플랜 한도에 포함한다.
- `REGISTERED`: 운영자가 실제 등록 완료로 표시한 채널. 플랜 한도에 포함한다.
- `REVISION_REQUESTED`: 운영자가 사용자 수정을 요청한 채널. 플랜 한도에 포함한다.
- `REJECTED`: 운영자가 반려한 채널. 플랜 한도에 포함하지 않는다.
- `CANCELLED`: 사용자가 외부 처리 전 등록 요청을 취소한 상태. 플랜 한도에 포함하지 않는다.
- `REMOVAL_REQUESTED`: 이미 외부 처리되었거나 등록 완료된 채널에 대해 사용자가 등록 해제를 요청한 상태. 플랜 한도에 포함한다.

[DELETION / REMOVAL POLICY]
- `DRAFT`: 사용자가 즉시 삭제할 수 있다.
- `PENDING`: 사용자가 요청을 취소하고 삭제할 수 있다. 삭제 대신 이력 보존이 필요한 경우 `CANCELLED`로 전환한다.
- `REVISION_REQUESTED`: 사용자가 요청을 취소하고 삭제할 수 있다. 삭제 대신 이력 보존이 필요한 경우 `CANCELLED`로 전환한다.
- `REJECTED`: 사용자가 삭제할 수 있다.
- `EXPORTED`: 사용자가 즉시 삭제할 수 없다. 이미 외부 처리 대상으로 전달되었을 수 있으므로 `REMOVAL_REQUESTED`로 전환한다.
- `REGISTERED`: 사용자가 즉시 삭제할 수 없다. 실제 외부 등록 해제가 필요하므로 `REMOVAL_REQUESTED`로 전환한다.
- `REMOVAL_REQUESTED`: 운영자가 외부 해제를 완료한 뒤 최종 상태를 확정한다.
- 구현 시 실제 물리 삭제와 이력 보존 상태 전환 중 어떤 방식을 쓸지는 DB/API 설계 WI에서 확정하되, 외부 처리 이후 채널은 즉시 물리 삭제하지 않는다.

[CSV EXPORT REQUIREMENT]
- 관리자 페이지에서 상태 필터 기준으로 화이트리스트 채널을 CSV로 내보낼 수 있어야 한다.
- 기본 export 대상은 `PENDING` 상태 채널이다.
- Export 후 `PENDING` 대상 채널은 `EXPORTED` 상태로 전환한다.
- `REMOVAL_REQUESTED` 등 `PENDING`이 아닌 상태의 CSV export는 외부 처리/검토용 스냅샷만 남기고 기존 상태를 유지한다.
- CSV 기본 컬럼 후보:
  - `requestId`
  - `userId`
  - `userEmail`
  - `userNickname`
  - `channelName`
  - `youtubeHandle`
  - `channelUrl`
  - `youtubeChannelId`
  - `requestedAt`
  - `planName`
  - `billingCycle`
  - `exportedAt`
- `userEmail`은 CSV 기본 컬럼에 포함한다.
- Export 이력 테이블 후보:
  - `whitelist_export_batches`: 파일명, 건수, 실행 관리자, 실행 시각, 메모.
  - `whitelist_export_items`: batch와 whitelist channel 매핑, export 당시 상태/스냅샷.

[SUCCESS CRITERIA (DoD)]
- 사용자는 화이트리스트 채널을 추가·수정·삭제할 수 있다.
- 사용자는 대표 채널을 하나 설정할 수 있다.
- 사용자는 채널별로 화이트리스트 등록 요청을 할 수 있다.
- 플랜 한도를 초과하는 등록 요청은 차단되고, 현재 플랜의 허용 개수가 안내된다.
- 개인정보 수정 또는 사용자 계정 영역에서 채널 관리로 접근할 수 있다.
- 관리자 화면에서 사용자별 채널 정보와 처리 상태를 볼 수 있다.
- 관리자는 등록 요청 채널을 CSV로 export할 수 있다.
- CSV export 이력이 저장된다.
- 관리자는 채널 상태를 `REGISTERED`, `REVISION_REQUESTED`, `REJECTED`, `REMOVAL_REQUESTED` 등으로 변경할 수 있다.
- API/DB/화면/문서가 동일한 필드명과 상태 모델을 설명한다.
- 백엔드 테스트, 프론트 typecheck/lint/build, 문서 validation이 통과한다.

[RISKS / DECISIONS]
- Risks:
  - 이미 `REGISTERED` 된 채널을 사용자가 수정할 때 상태를 자동으로 `PENDING`으로 되돌릴지 정책이 필요하다.
  - CSV에 이메일을 포함하므로 외부 전달 범위와 운영 보관 정책을 주의해야 한다.
  - 다운그레이드로 플랜 한도가 줄어든 경우 어떤 채널을 유지할지 후속 UX가 필요할 수 있다.
- Decisions:
  - `REVISION_REQUESTED`는 플랜 한도에 포함한다.
  - CSV 컬럼에 `userEmail`을 포함한다.
  - `EXPORTED`, `REGISTERED` 상태의 채널은 사용자 즉시 삭제 대신 해제 요청 흐름으로 전환한다.
