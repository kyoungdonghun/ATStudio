# WI-20260809-ATS-067 완료 요약

## 최종 결과

WI-067의 정산 CSV 안전성 강화, 정산 누락 대사 범위 제한, 운영자 메모
전송 변경, 현재 MySQL 기준선 실측과 독립 검증을 완료했습니다. 별도 승인된
MySQL 단계는 **RUN-PASS-CLEANED**이며, 사용한 관측용·증명용 데이터베이스는
모두 정확한 대상 삭제를 마쳤습니다.

QA-INTEG와 PG 검토는 모두 **ACCEPT**이고 미해결 중요도 1·2 항목은 없습니다.
백엔드와 프론트엔드의 최종 전체 품질 검사도 통과했습니다.

## 반영된 동작

- 파일명·확장자·파일 형식·5 MiB 크기 제한을 작업 기록 생성 전에 검사합니다.
- UTF-8만 엄격하게 허용하고, 맨 앞의 바이트 순서 표시는 하나만 제거합니다.
  잘못된 바이트나 CSV 인용부호·헤더·열 너비는 묵시적으로 보정하지 않습니다.
- 데이터 행은 최대 1,000개입니다. Provider는 `TOSS`, 통화는 `KRW`만
  허용하며, 식별자는 잘라 저장하지 않습니다.
- 금액은 반올림하지 않는 소수 둘째 자리 기준으로 검증하고, 날짜 형식과
  지급일 순서를 엄격히 확인합니다.
- 정산 누락 대사는 기본 30일, 최대 90일, 최대 5,000건입니다. 5,001건이면
  변경 전에 전체 요청을 거절합니다.
- 처리는 동기 방식이며 자동 재시도·폴링·진행 원장을 추가하지 않았습니다.
  대사 오류 상세는 앞의 200건과 정확한 생략 건수를 함께 반환합니다.
- 운영자 메모는 주소 질의 문자열이 아니라 선택적 멀티파트 본문으로만
  전송합니다. 기존 500자 제한은 유지합니다.
- 같은 작업 키의 재요청은 파일을 다시 처리하지 않으며, 건수 보존과 정확한
  중복 판정, 읽기 전용 복구 규칙을 유지합니다.

## MySQL 실측 및 정리

관측용 `ats_disposable_20260813_wi067obs`에 현재 스키마와 초기 데이터를
적용한 결과는 다음과 같습니다.

| 항목 | 현재 기준값 |
|---|---:|
| 테이블 | 42 |
| 열 | 506 |
| 인덱스 행 | 173 |
| 외래 키 | 90 |
| 요금제 / 요금제 키 | 6 / 6 |
| 금지 테이블 / 열 | 0 / 0 |
| SHA-256 | `acf28c935bf6107a8f2af431c971ebe0cd3539dba1aa1a941d966dde4a2a7a65` |

최초 관측은 기대값이 기록되기 전이므로 설계대로 차단되었고 자동 정리와
후속 정확 대상 삭제가 모두 통과했습니다. 실측값만 도구에 반영한 뒤 보호
검사 20개 전부와 사전 점검의 `RECORDED` 상태가 통과했습니다.

별도 증명용 `ats_disposable_20260813_wi067prf`는 생성, 독립 검증, 기준값
완전 일치를 통과했습니다. 스키마 자동 변경 없이 검증 모드로 실행한 MySQL
동시성 시험 3건도 실패·오류·건너뜀 없이 모두 통과했고, 마지막 정확 대상
삭제까지 완료했습니다.

이 과정에서 기존 데이터베이스, 실제 Provider, 결제, 환불, 메일 경로를
사용하지 않았고 비밀값도 출력하지 않았습니다. 과거의
41/493/168/89 기준과 `c581...` 해시는 역사적 선행 기록일 뿐 현재 기준이
아닙니다.

## 회귀 및 전체 품질 결과

- H2 정산 가져오기 8건과 무시 처리 2건이 모두 통과했습니다.
- 기본 환경에서는 선택 실행 방식인 MySQL 시험 3건이 설계대로 건너뛰었습니다.
- 백엔드 전체 명령은 성공했습니다. 1,542건 중 실패 0건, 건너뜀 19건이며,
  커버리지는 명령어 86.72%, 분기 71.877%, 줄 87.04%, 메서드 84.56%,
  클래스 94.799%입니다. 커버리지 기준 검사와 조립도 통과했습니다.
- 프론트엔드는 73개 파일, 827개 시험, 실패 0건입니다. 커버리지는 구문
  88.28%, 분기 79.53%, 함수 87.88%, 줄 90.5%이며, 타입 검사·린트·서식·
  빌드가 모두 통과했습니다.
- 문서 검증은 최상위 기준 문서, 내부 링크, 추적성 식별자 557개, 문서
  인덱스를 모두 통과했고 공백 오류 검사도 통과했습니다.
- 저장소에 없는 `format:check` 명령을 한 번 잘못 시도했지만, 즉시 실제
  명령인 `npm run format`으로 교정해 통과했습니다. 제품·코드·시험 실패는
  아닙니다.

## 남아 있는 범위

이번 완료는 새로 만든 일회용 MySQL 기준선과 정산 동시성 증거입니다. 기존
데이터를 유지하는 이전, 실제 Toss 검증, 운영 배포·감시, 수동 운영자·고객
인수, 최종 출시 승인은 포함하지 않습니다. 따라서 SR-93 전체 운영 준비
상태는 계속 **OPEN**이며, 인수 체크리스트의 사람 수동 항목도 체크하지
않았습니다.
