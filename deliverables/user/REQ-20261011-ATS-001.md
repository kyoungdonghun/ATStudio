# REQ-20261011-ATS-001: 배포 파일 확인과 운영 DB 구조 검증

[REQ]
Project: ATS
Owner: MA
Status: approved / completed (승인된 파일 확인·읽기 전용 구조 검사·정리·문서 통합 완료; 전체 production HOLD 유지)
Approval: 사용자 "그러면 그렇게 진행하자."
추가 승인: "이번 작업 중 임시 활성화 승인", "기존 DB 암호의 제한적 사용·읽기 전용 구조 검증 승인".

[GOAL / WHY]
- 준비된 JAR와 React 산출물이 현재 배포 후보와 일치하는지 확인하고, 실제 앱 기동 전에 운영 DB와 엔티티 구조의 호환성을 검증한다.
- 기존 JDBC PASS와 HTTPS PASS를 보존한다. 이미 만든 DB/계정/비밀값은 다시 만들지 않는다.

[SCOPE]
- 로컬 배포 후보 및 소스 해시 대조, 필요한 최소 검증 도구/테스트와 제한 배포 절차 준비.
- 기존 JAR의 라이브러리와 엔티티만 사용하는 격리 Hibernate/구조 읽기 검증. Spring 앱/컴포넌트/스케줄러/음원 작업자/웹 서버는 실행하지 않는다.
- 검토를 통과한 정확한 검증 산출물만 기존 서버에 비공개로 전달. 별도 승인된 기존 DB 암호는 프로그램 내부에서만 읽고 출력하지 않는다.
- MySQL을 검사 중 loopback 전용으로만 켜고 종료 후 다시 중지/마스크한다. 기존 제한 Nginx/인증서/예약은 유지한다.
- 최신 런타임 설정과의 연결에 필요한 공개 설정 후보/잔여 단계 기록. 실제 비밀 설정 변경과 전체 앱 기동은 별도 승인/안전 검토 후속 단계다.
- 제외: 구매, 라이브러리 추가/업그레이드, DB DDL/DML/계정/권한/비밀번호 변경, TEST 데이터 이관, 백업 업로드/삭제, 메일/결제/OAuth 호출, 전체 공개, 커밋/푸시, 기존 자료 삭제, 재부팅.
