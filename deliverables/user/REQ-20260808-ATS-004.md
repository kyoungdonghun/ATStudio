[APPROVED POLICY BASELINE]
- 태그 이름은 trim, 내부 whitespace 1개, Unicode NFC로 정규화한다.
- 태그 허용 문자는 한글·영문·숫자·공백과 승인된 `- & / ' ’ ( )`로 제한한다.
- `#`는 저장 이름이 아니라 Usage 화면 표시 접두사로 사용하고, V1의 전역 이름 유일성은 유지한다.
- 관리자 역할 변경은 모든 강등 요청이 공유하는 직렬화 guard를 사용한다. 자기 강등과 마지막 관리자 강등을 금지하고 강등 시 Refresh Token을 제거한다.
- 관리자 0명 복구는 공개 API가 아닌 오프라인 운영 절차로 둔다.
- 관리자 구독 변경은 외부 결제 없는 로컬 권한 보정으로 구현하며 미리보기, 운영 사유, 명시적 확인, 감사 기록을 요구한다.
- 업무 날짜 기준은 `Asia/Seoul`의 서버 Clock으로 통일한다.
- 신규·교체 음원 썸네일은 1:1 필수, 2048x2048 권장이다. 기존 비정사각형 이미지는 보존하고 관리자에게 교체 필요를 표시한다.
- 기존 mp3spi 디코딩 경로를 우선 재사용하여 duration과 waveform을 한 분석 결과로 만든다. 분석 실패 시 추정값이나 0을 저장하지 않는다.
- 기존 duration 보정은 읽기 전용 dry-run 보고서까지만 자동 진행하고 backfill은 별도 승인한다.
- 버퍼링 안내는 2초 이상 지속될 때만 표시하고, 지속 버퍼링과 실제 재생 오류를 구분한다.
- 집계 응답은 공통 PlayableTrack 계약을 우선 사용하고, 로컬 재생기록은 batch hydration으로 보강한다.
- 홈은 Usage를 첫 범주로 유지하되 결과가 0건이면 첫 결과 보유 범주를 기본 표시하고 Usage 빈 탭은 숨기지 않는다.

[SUCCESS CRITERIA (DoD)]
- SR-94~101의 완료 조건이 구현·테스트·문서에서 추적 가능하다.
- 마지막 관리자 수는 자기·동시 요청을 포함해 항상 1명 이상 유지된다.
- 모순된 관리자 구독 상태가 저장되지 않고 로컬 보정과 외부 결제 동작의 경계가 명확하다.
- MP3 CBR/VBR과 WAV의 실제 duration과 waveform이 단일 분석 결과로 저장되며 오디오 교체도 함께 갱신된다.
- 태그 생성·수정·직접 API 호출이 같은 정규화·검증·중복 계약을 사용한다.
- 모든 재생 진입점의 duration/waveform이 보강되고 짧은 정상 버퍼링은 장애 문구를 노출하지 않는다.
- 신규 썸네일의 업로드 결과가 미리보기와 일치하고 기존 파일은 임의 변경되지 않는다.
- 홈과 음원 목록이 네 Tag 유형의 URL·API·선택 상태를 동일하게 유지한다.
- 백엔드 전체 테스트·커버리지, 프론트 테스트·커버리지·typecheck·ESLint·Prettier·build, 문서 검증, 통합 회귀 검증이 통과한다.
- 실제 DB backfill은 실행되지 않고 승인 가능한 dry-run 산출물만 제공된다.
