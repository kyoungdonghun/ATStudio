[GOAL / WHY]
- 결제 대사 불일치가 `payment_reconciliation_incidents`에 저장되고 관리자 API로 상태 변경까지 가능해졌지만, 현재 운영자는 API를 직접 호출해야 한다.
- 기존 관리자 결제 조회 화면에 incident 운영 탭을 추가해 `OPEN` 이슈 확인, 상태 변경, 처리 메모 입력을 화면에서 수행할 수 있게 한다.

[SCOPE]
- In:
  - 기존 `/admin/payments` 화면에 결제 대사 incident 탭을 추가한다.
  - incident 목록을 상태별로 조회할 수 있게 한다.
  - `OPEN`, `ACKNOWLEDGED`, `RESOLVED`, `IGNORED` 상태 변경과 메모 입력을 제공한다.
  - incident의 issue type, severity, orderId, provider, purpose, local/provider status, amount, occurrence count, last detected time, note 등 support-safe 필드를 표시한다.
  - frontend API client 타입과 호출 함수를 추가한다.
  - SR-93, UI 문서, WI summary/evidence를 현행화한다.
- Out:
  - 환불, 결제 취소, 구독 권한 보정 등 결제/구독 상태를 직접 변경하는 admin mutation.
  - Toss webhook.
  - Slack/SMS/in-app 알림.
  - 멀티서버 scheduler lock.
  - 멀티 PG 확장.
  - 신규 백엔드 endpoint 또는 DB schema 변경.

[SUCCESS CRITERIA (DoD)]
- `/admin/payments`에서 incident 탭을 통해 persisted reconciliation incidents를 조회할 수 있다.
- 상태 필터가 `전체`, `OPEN`, `ACKNOWLEDGED`, `RESOLVED`, `IGNORED`를 지원한다.
- 각 incident row에서 상태 변경과 메모 저장이 가능하다.
- 화면과 API 타입은 raw billing key, authKey, customerKey, Toss secret, raw card data, raw provider payload를 표시하지 않는다.
- `npm run typecheck`, `npm run lint`, `npm run build`, 문서 검증이 통과한다.

[CONSTRAINTS / POLICIES]
- Work tracking unit: WI
- REQ 승인 이후 구현한다.
- 관리자 UI는 결제/구독 상태를 변경하지 않고 incident workflow 상태만 변경한다.
- 기존 관리자 화면의 조용하고 밀도 있는 운영 UI 톤을 유지한다.
- React SPA 활성 상태를 기준으로 구현한다.
