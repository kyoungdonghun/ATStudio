[GOAL / WHY]
- 기업회원 인증 기능은 이미 신청/상태조회/관리자 심사 API와 일부 화면이 존재하지만, 실제 운영 흐름으로 보기에는 심사 문서 열람, 보완요청 재제출, 관리자 상세 검토, 민감 서류 접근 제어가 부족하다.
- 현재 문서는 "보완요청/반려 후 UI 재신청 없음"을 전제로 하지만, 백엔드 상태 전이와 테스트에는 `REVISION_REQUESTED -> PENDING` 재신청 흐름이 일부 반영되어 있어 정책과 구현이 어긋나 있다.
- 목표는 기업회원이 구독 결제 전 필요한 서류를 제출하고, 관리자가 안전하게 검토/승인/보완요청/반려할 수 있는 프로세스로 확정하는 것이다.

[SCOPE]
- In:
  - 기업회원 인증 현행 코드, API, DB, 프론트 화면, 설계/시나리오 문서 정합성 점검.
  - 보완요청/반려/승인 상태 정책 확정:
    - 추천 정책: `REVISION_REQUESTED`는 같은 신청 건에 서류를 다시 제출해 `PENDING`으로 복귀.
    - 추천 정책: `REJECTED`는 기존 기록을 보존하고 새 신청 가능.
    - 추천 정책: `APPROVED`는 결제 가능 상태로 고정하고 일반 사용자 재신청은 막음.
  - 기업 인증 서류 파일 메타데이터 관리 추가 검토 및 구현.
  - 관리자 인증 상세 화면에서 신청자 정보, 제출 문서, 관리자 메모, 승인/보완요청/반려 액션을 처리.
  - 사용자 인증 현황 화면에서 상태별 안내와 재제출/새 신청/결제 이동 CTA를 제공.
  - 기업 구독 결제 진입 시 미승인 상태를 명확히 안내하고 인증 화면으로 연결.
  - 기업 인증 문서 저장/다운로드 접근 제어 보강. 민감 서류는 공개 정적 URL 직접 노출을 피하고 인증된 API로 제한.
  - API spec, DB schema, usecase, UI flow, client scenario, 테스트 체크리스트 현행화.
  - 기존 로컬/운영 DB 수동 반영이 필요한 경우 manual SQL 패치 작성.
- Out:
  - 사업자등록번호 정부/외부기관 실시간 검증 API 연동.
  - OCR, 자동 서류 판독, 자동 승인.
  - S3 등 외부 오브젝트 스토리지 이전.
  - 이메일/SMS 자동 알림.
  - 관리자에 의한 승인 취소/인증 만료/기업정보 변경 재심사 정책.
  - 결제 수단 추가 또는 PG 확장.

[SUCCESS CRITERIA (DoD)]
- 기업회원은 인증 신청이 없으면 서류를 제출할 수 있고, `PENDING`이면 중복 제출이 막힌다.
- `REVISION_REQUESTED` 상태에서는 관리자 메모를 확인하고 서류를 다시 제출할 수 있으며, 제출 후 상태가 `PENDING`으로 돌아간다.
- `REJECTED` 상태에서는 기존 기록을 보존한 채 새 신청을 시작할 수 있다.
- `APPROVED` 상태에서는 인증 코드/승인일이 표시되고 기업 구독 결제 진입이 가능하다.
- 관리자는 인증 목록에서 상세로 들어가 제출 문서와 신청자 정보를 확인한 뒤 승인/보완요청/반려를 처리할 수 있다.
- 기업 인증 서류는 관리자 또는 해당 사용자에게만 허용된 방식으로 접근된다.
- API/DB/프론트 타입/문서가 같은 상태 모델과 응답 계약을 설명한다.
- 백엔드 테스트, 프론트 typecheck/lint/test/build, docs validation, diff check가 통과한다.
