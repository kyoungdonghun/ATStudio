# REQ-20260909-ATS-005: WAV 원본 보존 및 128kbps MP3 재생 파일 생성

[REQ]
Project: ATS
Status: completed (source implementation; later TEST application is tracked in REQ006)
Approval: 사용자가 원본/재생 파일 분리, 기록되는 변환 대기 작업, 실패 복구 및 검증 계획에 "좋아. 업로드제한은 100mb으로 늘리자. 인코더를 정할 수 있다면 128kbps정도면 될꺼같네."라고 승인했다.

현재 상태 안내 (WI029, 2026-09-09): 아래 WI025/026의 미배포·별도 승인 대기 표현은 당시 기록으로 보존한다. 이후 별도 승인된 [REQ006 마감](REQ-20260909-ATS-006.md)과 [WI028 검증](../agent/WI-20260909-ATS-028-evidence-pack.md)이 실제 기존 TEST DB 적용 및 한정 브라우저 검증의 기준이다. 브라우저 OS 저장 UNKNOWN, fresh-bootstrap manifest UNRECORDED, 운영 HOLD는 유지한다.

[GOAL / WHY]
- WAV 원본을 그대로 내려받을 수 있게 보존하면서 사이트 전체 길이 재생에는 128kbps MP3를 사용해 전송량을 줄인다.
- 업로드, 교체, 재시작에서 DB와 파일이 어긋나거나 처리 중인 파일이 공개되는 상황을 방지한다.

[SCOPE]
- In: 신규 WAV 업로드 및 WAV 교체, MP3 CBR 128kbps 변환, 파일당 100MB 상한, 파일 참조/작업 상태 저장, 단일 변환 작업자, 관리자 상태/재시도, 파일 복구/무결성 검사, 회귀 검증, 운영/DB 설치 문서.
- In: 기존 audio_file은 원본 참조로 보존하고 별도 재생 파일 참조를 추가한다. 현재 저장소 루트 아래 보호된 음원 경로를 재사용한다. 실제 파일 이동 없이 소스와 신규 설치/기존 DB 적용 SQL을 준비한다.
- Out: 짧은 미리듣기, 구독/다운로드 권한/횟수 정책 변경, 기존 MP3 재인코딩, 과거 음원 일괄 변환/삭제, 기존 누락 파일 복구, 별도 DB/스토리지 서버/Redis 도입, 원본 백업 인계 폴더 변경.
- Out: 실행 중인 서버 재시작/배포, 실제 DB DDL/행 변경, 운영 파일 생성/교체, 결제/환불/메일 등 외부 부작용, 커밋/푸시. 테스트는 임시 저장소 및 자동 테스트 DB에서 수행한다.

[SUCCESS CRITERIA]
- 파일 크기 상한은 기존 단위와 동일하게 100 * 1024 * 1024 bytes이며 UI는 100MB로 표시한다. 전체 요청 상한에는 썸네일 및 multipart 오버헤드 여유를 둔다. 다른 첨부 도메인의 상한은 유지한다.
- WAV 원본 바이트를 보존하고 전체 길이의 128kbps MP3를 한 번 생성한다. MP3가 그대로 지원하는 샘플레이트/채널 수는 보존하며, 96kHz 또는 다채널처럼 포맷 변환에 필요한 경우에만 재생용 파일을 호환 샘플레이트와 최대 2채널로 변환한다. 원본 변경, 임의 볼륨 정규화 또는 길이 제한은 없다.
- MP3 업로드 및 과거 원본 참조는 기존 동작을 유지한다. 과거 자료에 대한 자동 일괄 작업은 없다.
- 신규 WAV는 처리 준비 전 공개/활성화가 차단된다. 기존 수동 활성화 절차를 보존하며 작업자가 임의로 곡을 활성화하지 않는다.
- 교체 작업 완료 전에는 기존 원본/재생/메타데이터를 유지한다. 최종 전환은 최신 작업임을 확인한 후 처리하며 중복 작업, 삭제/수정 경합과 오래된 작업 결과를 통제한다.
- 파일 변경 저널, 참조 검사, 무결성 검사가 새 원본/재생/대기 파일을 모두 보호한다. 정상 트랜잭션 롤백 및 프로세스 중단 후 복구를 검증한다.
- FFmpeg 실행은 쉘 문자열 조합 없이 제한된 로컬 파일과 고정 옵션을 사용하고 시간/동시 실행/출력 크기를 제한한다. 미설치·실패는 안전한 관리자 오류이며 거짓 완료 또는 무제한 원본 재생 우회가 아니다.
- 목록/앨범/플레이리스트의 재생·seek·파형·다음곡, 다운로드 원본 해시/권한, 경계 크기, 손상 WAV, 교체 실패, 재시작/재시도를 검증한다. 실제 수행하지 못한 브라우저/운영 환경 검증은 완료로 표시하지 않는다.

[WI026 현재 검수 마감 기록]
- 위 WI025 기록은 당시 수신 상태로 보존한다. 이후 CR이 전체 실패 XML과 소스를 대조했고, MP3 저장 mock 누락이 아니라 분석을 잠금 이전으로 옮긴 뒤 테스트 대기 지점이 잠금 이전에 남아 있던 것이 원인임을 확인했다.
