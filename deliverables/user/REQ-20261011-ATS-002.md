[GOAL / WHY]
- 자동 작업과 외부 연동을 점검하고, 외부 공개 없이 첫 앱 기동을 준비한다.
- 현재 소스와 JAR의 일치를 확인하고 필요한 최소 안전장치 변경을 반영한 새 JAR를 별도 경로에 준비한다.

[SCOPE]
- 포함: 로컬 자동 작업 차단 코드 및 공개 실행 설정, 외부 통신 차단용 비공개 기동 후보, 합성 회귀시험, 독립 보안 검토, 새 배포 후보 빌드 및 소스/산출물 해시, 현재 문서 통합.
- 제외: 서버 접속/SSH 에이전트 활성화, 실제 비밀값 사용/생성, DB 변경, 실제 앱 실행, 서버 적용/공개, 메일/OAuth/결제 호출, 구매/설치, 백업 업로드/삭제, 기존 파일 삭제, 커밋/푸시, 라이브러리 추가/교체.
- 테스트는 모의 의존성과 합성값만 사용한다. 실제 전체 앱/운영 DB를 켜지 않는다. 기존 JAR/SPA/역사적 manifest와 해시는 그대로 보존한다.

[QUALITY GATES]
- 코드의 자동 실행 진입점과 설정의 실제 매핑 확인. 단순 방화벽/빈 키를 모든 작업 차단으로 간주하지 않는다.
- 실패/누락 설정과 기본 동작의 회귀시험, 독립 보안 검토. 실제 Linux 차단 검증은 후속 대상 작업이다.
- 기존 JAR/증거 해시 보존, 새 빌드의 입력/출력 기록. 프론트엔드 미변경이면 기존 SPA 재사용 경계 명시.

[RISKS / OPEN QUESTIONS]
- 로컬 설정 검사는 Linux 네트워크 제한의 실제 효력을 증명하지 않는다. 첫 실제 기동 전에 별도 승인/대상 점검이 필요하다.
- 앱 기동은 읽기 전용 DB 검사와 다르다. 기동 중 디렉터리/로그 생성 등 로컬 부수효과와 복구 기준선을 다음 단계에서 승인한다.
- 대안: 현재 JAR를 그대로 유지하고 기동을 보류할 수 있으나, 자동 작업 차단을 보장하지 못한다. 최소 차단 코드를 추가하는 승인안으로 진행한다.

[APPROVAL POINTS]
- 로컬 준비만 승인됨. 실서버 적용/비밀 사용/기동은 이 REQ로 승인되지 않는다.
