# REQ-20260929-ATS-001

## [REQ]

- REQ ID: REQ-20260929-ATS-001
- Project: ATS
- Owner: MA
- Status: approved / completed (WI001 문서 수정 및 WI002 독립 검증 완료)
- 승인 근거: 이전에 제안한 최신 상태표, 과거 기록 구분, 운영 안내 정정, 근거 확인 순서 보강에 대해 사용자가 "일단 그러면은 너가 그런 판단을 할 때 보는 문서들 뭐 판단할 때 사용하는 것들 일단 한번 최신화 한번 해봐"라고 지시했다. 이 승인은 문서 작업에만 적용한다.

## [GOAL / WHY]

- 이미 검증된 Gmail 및 미디어 기능을 미검증으로 오판하지 않도록, 다음 운영 배포 판단의 근거와 확인 순서를 최신화한다.
- 이전 답변의 오류는 최신 완료 증거를 확인하지 않은 판단 오류다. 문서 정비가 그 책임을 대체하지 않는다.

## [SCOPE]

- In: 기존 문서 진입점의 최신 상태표와 근거 링크, 실제 검증일/환경/미확인 사항 분리, Gmail 완료 기록 연결, FFmpeg 및 복구 안내의 현재 코드 불일치 수정, 후속 세션의 근거 확인 절차, 문서 검증과 작업 기록.
- 대상: AGENTS.md, CLAUDE.md, README.md, docs/index.md, docs/payment/index.md, scripts/reconstruction/README.md, docs/templates/ma-session-kickoff-prompt.md. 중복 상태 문서 신설 대신 기존 진입점을 이용한다.
- Out: 서버 요금 재산정/추천/구매/배포, 코드와 환경 설정 변경, 이메일 발송, 결제/환불, DB 접근/변경, 서비스 재시작, 브랜치 삭제, 커밋/푸시, 전역 메모리 수정.
- 과거 WI/SR/원본 로그 및 해시 보존 대상은 변경하지 않는다. 과거 pending 문구의 후속 완료 근거를 현재 진입점에서 연결한다.

## [SUCCESS CRITERIA (DoD)]

- 최신 문서 입구에서 기능, 마지막 실제 검증일, 환경, 남은 확인, 근거를 구분한다.
- 2026-09-08 Gmail 실제 수신 및 재설정 링크 열기와 새 VPS 검증 필요를 별개로 표시한다.
- 현재 WAV 원본 보존/128kbps MP3 생성 경로의 외부 FFmpeg 요구를 코드와 일치시킨다.
- 2026-09-09 미디어 및 사용자 휴대폰 인수 증거를 보존하고, 생산 환경 HOLD/복구 한계를 유지한다.
- 문서 수정일을 새 실행 검증일처럼 표현하지 않는다. 과거 가정/견적은 현재 용량·트래픽·요금 확정 근거로 사용하지 않는다.
- 문서 검증과 독립 검토를 완료하고, 실행하지 않은 검증 범위를 명시한다.

## [CONSTRAINTS / POLICIES]

- 작업 단위는 WI. MA는 승인 정규화와 WI 패킷 작성/위임/검증을 수행하고 실제 문서 수정은 docops에 위임한다.
- 문서는 영어, REQ 및 대화는 한국어. 민감값/메일주소/개인 설정 본문을 출력하거나 기록하지 않는다.
- 원본 증거 및 테스트 날짜를 보존한다. 없는 테스트를 만들지 않는다.

## [RISKS / OPEN QUESTIONS]

- 최신화는 문서와 소스의 대조이지 새 메일 발송, 새 휴대폰 테스트, 새 서버 운영 검증이 아니다.
- 과거 환경의 성공은 보존하되 새 서버에서 동일하게 작동한다고 단정하지 않는다.
- 과거 실패 기록의 삭제 대신 최신 완료 증거로 연결한다. 전체 저장소 문서를 일괄 재작성하지 않는다.
- Alternative Suggestion: 별도 운영 상태 문서를 중복 생성하기보다 기존 docs/index.md를 공통 판단 진입점으로 사용한다.

## [APPROVAL POINTS]

- 사용자 실행 지시로 위 문서 최신화 범위를 승인 처리했다. 추가 실행 승인 요청 없음.
- 서버 전체 재평가 및 실제 환경 테스트는 이후 별도 요청으로 진행한다.
