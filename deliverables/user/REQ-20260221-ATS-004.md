[GOAL / WHY]
- Playlist 도메인(Section 3) 8개 API 전체 구현
- 구독자가 트랙을 모아 나만의 재생목록을 만들고 순서를 관리할 수 있는 핵심 기능
- Playlist/PlaylistTrack 엔티티와 StorageService 등 필요한 인프라가 이미 완비되어 있어 순수 비즈니스 로직 + 라우팅 구현에 집중 가능

---

[SCOPE]
- In:
  - **3.1** `POST /api/playlists` — 플레이리스트 생성 (multipart: title, description?, thumbnail?)
  - **3.2** `GET /api/playlists` — 내 플레이리스트 목록 (trackCount 포함)
  - **3.3** `GET /api/playlists/{playlistId}` — 상세 조회 (tracks + trackOrder)
  - **3.4** `POST /api/playlists/{playlistId}/tracks` — 트랙 추가 (409 중복 방지)
  - **3.5** `PUT /api/playlists/{playlistId}` — 정보 수정 (multipart: 각 필드 선택적, thumbnail null이면 기존값 유지)
  - **3.6** `PUT /api/playlists/{playlistId}/tracks` — 트랙 순서 일괄 변경 (bulk)
  - **3.7** `DELETE /api/playlists/{playlistId}/tracks/{trackId}` — 트랙 제거
  - **3.8** `DELETE /api/playlists/{playlistId}` — 플레이리스트 삭제 (isActive=false 소프트)
  - PlaylistRepository, PlaylistTrackRepository 인터페이스 신규 작성
  - PlaylistService, PlaylistController, 관련 DTO 신규 작성
  - Playlist 엔티티에 `update()` 메서드 추가
  - 서비스 단위 테스트 + 컨트롤러 권한 테스트
- Out:
  - 구독 결제/생성 로직 (Section 6) — 별도 REQ
  - 플레이리스트 공유/공개 기능 — API 명세에 없음
  - 트랙 스트리밍 연동 (기존 TrackController 그대로 사용)

---

- 8개 엔드포인트 모두 명세서 응답 형식 충족 (201/200/204 상태코드)
- 구독자 전용 체크: 비구독자 → 403 반환
- 소유자 전용 체크(3.3~3.8): 타인 플레이리스트 접근 → 403 반환
- 트랙 중복 추가(3.4) → 409 Conflict
- 순서 변경(3.6): tracks 배열 기준으로 trackOrder 정확히 반영
- `gradlew.bat test` → 전체 테스트 통과, 0 failures
