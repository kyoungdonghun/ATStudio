# WI-20260808-ATS-005 썸네일 처리·사례 조사 요약
## TL;DR

- 현재 잘림의 직접 원인은 **리사이즈 왜곡이 아니라 정사각형 표시 영역의 `object-fit: cover`**다. 실환경 트랙 1의 썸네일은 564×1404px 세로 이미지로 저장되어 있고, 화면은 이를 정사각형으로 비율 보존 확대 후 넘치는 위·아래 영역을 자른다.
- 트랙 업로드는 파일 크기만 검사하고 비율 안내·미리보기·비율 검증이 없다. 트랙 이미지는 원본 파일을 그대로 저장하며, 플레이리스트에 적용되는 기존 `CanonicalImageService`의 비율 보존 축소도 사용하지 않는다.
- **단일 운영자 환경의 1차안은 복잡한 크롭 편집기가 아니라 1:1 업로드 계약**이 적합하다. 필수 조건은 정사각형 비율과 서버 검증, 권고 조건은 2048×2048px JPEG/PNG 및 현행 10MB 이하, UX는 실제 카드와 같은 정사각형 `cover` 미리보기와 제출 전 명확한 오류 안내다.
- 서버의 비율 보존 축소는 용량·보안 정규화를 위해 병행할 수 있지만 세로 이미지를 정사각형으로 만들지는 않는다. 강제 `fill` 늘림은 왜곡되므로 사용하지 않는다.

## 현재 원인

1. 업로드 화면은 `accept="image/*"`와 10MB 파일 크기 검사만 제공한다. 이미지 비율·해상도 안내, 선택 직후 미리보기, 정사각형 검증은 없다.
2. `TrackService`는 썸네일을 `tracks/thumbnail`에 원본 파일 그대로 저장한다. 로컬 저장소도 입력 스트림을 그대로 복사한다.
3. 트랙 상세, 목록 행, 플레이어, 관리자 트랙 목록 등은 고정된 정사각형 또는 작은 박스에 `object-fit: cover`를 사용한다.
4. 실환경 트랙 1은 564×1404px(가로/세로 0.402)의 세로 이미지다. 설명에도 `이미지의 비율 관련 ux 확인(세로로 김)`이라고 기록되어 있어 관찰과 저장 파일이 일치한다.

따라서 현상은 다음과 같다.

`세로 원본 저장 → 정사각형 컨테이너 → cover가 비율을 유지한 채 영역을 채움 → 위·아래가 잘림`

## 외부 관행과 의미

| 방식 | 비율 보존 | 전체 이미지 노출 | 정사각형 카드 결과 | 판단 |
|------|-----------|------------------|----------------------|------|
| 비율 보존 축소 | 예 | 예 | 원본 비율은 그대로여서 별도 표시 정책 필요 | 저장·전송 최적화에 적합 |
| `cover` / fill crop | 예 | 아니오 | 빈 공간 없이 정렬되지만 일부 잘림 | 카드 UI에 적합, 미리보기 필요 |
| `contain` / fit | 예 | 예 | 비율이 다르면 여백 발생 | 원본 전체 노출이 우선일 때 적합 |
| `fill` 강제 늘림 | 아니오 | 형식상 예 | 빈 공간은 없지만 이미지가 찌그러짐 | 권고하지 않음 |

- MDN은 `cover`가 비율을 유지하면서 박스를 채우고 비율이 다르면 잘리며, `contain`은 비율을 유지하고 전체를 보여 주는 대신 레터박스/필러박스가 생기고, `fill`은 비율이 다르면 늘어나 왜곡된다고 설명한다.
- Shopify Help는 나란히 표시하는 대표 이미지의 크기를 일정하게 보이게 하려면 일관된 종횡비를 사용해야 한다고 안내한다. 정사각형 제품 이미지에는 2048×2048px이 일반적으로 가장 잘 표시된다는 권고도 제시한다.
- Cloudinary는 `fill` 계열을 비왜곡 크롭, `fit`을 비율 보존 박스 맞춤, `pad`를 비율 보존과 여백 추가로 구분하며, 원본 비율과 다른 출력 비율에는 명시적인 크롭 정책이 필요하다고 설명한다.

공식 자료:

- [MDN: object-fit](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/object-fit)
- [Shopify Help: Product media types](https://help.shopify.com/en/manual/products/product-media/product-media-types)
- [Cloudinary: Resizing and cropping images](https://cloudinary.com/documentation/resizing_and_cropping)

## 권고안

### 1차 최소안 — 권고

- **필수:** 트랙 썸네일 비율을 1:1로 정의하고 백엔드가 최종 검증한다.
- **권고:** 2048×2048px JPEG/PNG, 10MB 이하로 안내한다. 2048px은 Shopify의 정사각형 이미지 권고 및 기존 정규화 서비스의 최대 출력 변 길이와 맞지만, 이번 조사만으로 모든 파일에 강제할 필수 픽셀값은 아니다.
- 파일 선택 직후 실제 트랙 카드와 동일한 정사각형 `cover` 미리보기를 보여 준다.
- 1:1이 아니면 예상 잘림을 즉시 보여 주고 제출을 막는 명확한 오류를 제공한다. 프론트 검사는 UX용이며 백엔드가 동일 조건을 최종 강제한다.
- 기존 이미지 정규화 서비스를 트랙 썸네일에도 적용해 JPEG/PNG 검증, 비율 보존 축소, 무업스케일 정책을 일관화한다. 이는 크롭 해결책이 아니라 저장 안전성과 용량 최적화다.
- 현재 `cover` 표시 방식은 정사각형 계약이 지켜지는 한 유지한다. `contain`으로 일괄 변경하면 잘림은 사라지지만 기존 카드 전체에 여백과 시각적 불일치가 생긴다.

### 후속 확장안

- 비정사각형 원본을 반복적으로 받아야 하는 요구가 확인되면 단순 크롭 위치 선택 또는 1:1 크롭 도구를 추가한다.
- 완전 자동 중앙 크롭은 피사체·텍스트를 자를 수 있으므로, 도입 시 미리보기 또는 초점 위치 저장을 함께 설계한다.
- 원본 전체 노출이 도메인 요구로 바뀌면 `contain` 또는 서버 패딩을 별도 디자인 결정으로 검토한다.

## SR-68과의 관계

- SR-68은 앨범 이미지가 레이아웃을 깨뜨리지 않도록 고정 영역·반응형 크기·`cover` 표시를 요구한 문서다.
- 후속 SR-98은 **트랙 썸네일의 업로드 계약, 저장 경로의 정규화 차이, 실제 표시와 같은 미리보기, 비율 검증**을 새 범위로 다뤄야 한다.

## 필요한 회귀 검증

- 정사각형 JPEG/PNG 업로드 성공 및 저장 후 비율 유지
- 세로·가로 비정사각형 이미지의 프론트 경고와 백엔드 거부
- 2048px 초과 이미지의 비율 보존 축소 및 작은 이미지 무업스케일
- 상세·목록·플레이어·관리자 화면에서 동일한 미리보기 결과
- 기존 비정사각형 썸네일의 마이그레이션 또는 예외 표시 정책
