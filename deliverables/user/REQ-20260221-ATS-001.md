[GOAL / WHY]
- Auth 시스템 완료 후 플랫폼의 핵심 콘텐츠 도메인인 **Track(음악 트랙)** 기능을 구현한다.
- 트랙이 있어야 구독/결제/다운로드/플레이리스트 등 나머지 기능이 연결되므로 다음 우선순위 기능이다.
- 크리에이터(ADMIN)가 트랙을 등록·관리하고, 구매자(PUBLIC/구독자)가 목록·상세·스트리밍을 이용할 수 있게 한다.

---

[SCOPE]

**In:**
- **Track CRUD**: 등록(1.1), 목록/검색(1.2), 상세(1.3), 수정(1.6), 소프트 삭제(1.7)
- **Tag CRUD**: 생성(2.1), 목록(2.2)
- **Track-Tag 연결**: 트랙 등록/수정 시 태그 id 리스트로 연결
- **목록 검색/필터**: keyword, genre/mood/instrument 태그, bpmMin/bpmMax, tonality, sort(latest/popular), 페이지네이션
- **스트리밍(1.4)**: preview_file 우선 서빙, NULL이면 audio_file 폴백 (PUBLIC)
- **다운로드(1.5)**: 구독자 전용, 일일 한도 체크, 다운로드 기록 저장, 라이선스 자동 발급
- **파일 업로드**: multipart/form-data (audioFile 필수, thumbnail 선택)
- **권한**: ADMIN 전용(등록/수정/삭제), PUBLIC(목록/상세/스트리밍), 구독자 전용(다운로드)
- **테스트**: TrackService, TagService 단위 테스트 + 핵심 Repository 테스트

**Out:**
- preview_file 비동기 자동 생성 (별도 REQ)
- 재생 횟수(play_histories) 기록 — 별도 프론트 호출로 처리 (별도 REQ)
- Like, Playlist 기능 (별도 REQ)
- Tag 수정/삭제 (필요 시 향후 추가)
- React 프론트엔드 UI

[SUCCESS CRITERIA (DoD)]
- 모든 Track API 7종 (1.1~1.7) 엔드포인트가 api-spec.md v5 명세 준수
- 모든 Tag API 2종 (2.1~2.2) 정상 동작
- Track-Tag 연결: 등록/수정 시 TagId 리스트로 연결, 상세 조회 시 tags 포함 반환
- 소프트 삭제: DELETE → is_active=0, 목록 조회 시 is_active=1 필터 적용
- 다운로드: 구독 미보유 → 403, 일일 한도 초과 → 403, 성공 시 라이선스 자동 발급
- ADMIN 전용 엔드포인트: ADMIN 미보유 시 403
- `gradlew test` 전체 통과 (기존 163개 + 신규)
- 빌드 에러 없음
