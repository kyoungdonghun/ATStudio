[GOAL / WHY]
- 전체 시스템 감사에서 확정된 P0 세 건을 수정하여 유료 원본 음원, 인증 토큰/개인정보, 탈퇴 회원의 결제 통제권을 복구한다.
- 단순 정상 흐름 테스트가 아니라 익명 정적 자원 접근, SMTP 실패 로그, 탈퇴 직후 갱신 스케줄러까지 집중 검증한다.

[SCOPE]
- In:
  - 현재 미커밋 문서·감사 산출물 기준선 정리와 전용 수정 브랜치 분리
  - 공개 Track 응답 및 정적 자원 경로에서 원본 음원 노출 제거
  - 기존 원본 음원의 비공개 저장 구조와 호환/이관 전략
  - SMTP 실패 로그에서 수신자, 본문, URL, 토큰 등 민감정보 제거
  - 탈퇴 즉시 로컬 자동갱신 차단, 갱신 조회의 탈퇴 회원 제외, 빌링키 해지 실패 보상 기록
  - 세 결함의 단위·통합·보안 회귀 테스트
  - 관련 설계/API/운영/감사 문서 현행화
- Out:
  - 자동 환불 정책 및 환불 실행
  - 결제 멱등성, 갱신 배치 트랜잭션, 환불 동시성 등 나머지 P1 개편
  - 플레이리스트/기업 문서/CSV/세션 보안 P1 개편
  - 프론트 전반 UX, Prettier 일괄 정리, 커버리지 도구 도입

[SUCCESS CRITERIA (DoD)]
- 익명 사용자는 원본 음원 저장 경로나 원본 파일을 직접 조회할 수 없다.
- 공개 미리듣기와 정상 구독자 다운로드는 유지되고, 다운로드 한도·이력·라이선스 발급을 우회할 수 없다.
- 이메일 발송 예외 로그에 이메일 주소, 본문, 인증/재설정 URL 또는 토큰이 포함되지 않는다.
- 탈퇴 완료 후 갱신 대상에서 제외되며 Provider 자동결제 호출이 0회임을 테스트로 증명한다.
- 빌링키 Provider 해지 실패 시에도 로컬 갱신 차단은 유지되고 운영자가 재처리 가능한 비민감 기록이 남는다.
- 백엔드 전체 테스트, 프론트 영향 검증, 컴파일, 빌드, 문서 검증과 `git diff --check` 결과가 기록된다.
- 설계-코드-테스트-문서가 동일한 최종 정책을 설명한다.

[CONSTRAINTS / POLICIES]
- Work tracking unit: WI
- 현재 문서/PDF/감사 산출물과 신규 기능 수정은 서로 다른 기준선 커밋으로 분리한다.
- `cloudflared`/Vite 로그와 PID 등 런타임 파일은 커밋하지 않는다.
- 기존 사용자 변경을 되돌리거나 덮어쓰지 않는다.
- 실제 운영 DB, Toss live Provider, 실사용 이메일을 호출하지 않는다.
- 원본 파일 이관이나 DB 변경은 실행 가능한 스크립트와 롤백 절차를 먼저 만들며 실제 데이터 적용은 별도 승인을 받는다.
- 탈퇴 시 자동갱신은 즉시 중단하되 자동 환불은 하지 않고 기존 관리자 환불 절차로 분리한다.
- 비밀번호 재설정 API는 계정 존재 여부와 메일 발송 성공 여부를 외부에 노출하지 않는다.
