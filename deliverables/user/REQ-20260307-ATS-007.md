- T-2: 구독 변경 확인 모달(PlanCompareModal)이 proratedAmount를 미리 보여줘야 하나, 조회 전용 API 없음
- T-3: 다운그레이드 시 즉시 적용 대신 다음 결제일부터 적용해야 하나, 예약 컬럼이 없어 현재 즉시 적용됨

[SCOPE]

In:
- T-1: `DownloadCountResponse`에 `nextResetAt` 필드 추가 (내일 00:00 KST)
- T-2: `GET /api/utils/subscription-change-preview` 신규 엔드포인트
  - 파라미터: `subscriptionId` (Long), `billingCycle` (MONTHLY | YEARLY)
  - 응답: `changeType` (UPGRADE | DOWNGRADE), `proratedAmount`, `effectiveDate`, `newPlanName`
  - UPGRADE: proratedAmount = 신플랜가격 - 현재플랜환불액, effectiveDate = 오늘
  - DOWNGRADE: proratedAmount = 0, effectiveDate = 현재 expiresAt
  - 판정 기준: 월 정가(priceMonthly) 비교 — 신플랜 >= 현재플랜 → UPGRADE, 신플랜 < 현재플랜 → DOWNGRADE
- T-3: `user_subscriptions` 테이블에 `pending_subscription_id` (BIGINT FK nullable), `pending_billing_cycle` (VARCHAR 10 nullable) 컬럼 추가
  - `UserSubscription` 엔티티 필드 추가 + `schedulePendingChange()` 메서드 추가
  - `changeSubscription()` 서비스 로직 분기:
    - UPGRADE: 기존 로직 유지 (즉시 적용 + 결제)
    - DOWNGRADE: pending 필드에 저장, 현재 구독 유지, 결제 없음
  - `UserSubscriptionResponse`에 pending 정보 필드 추가 (pendingSubscriptionId, pendingBillingCycle)

Out:
- 다운그레이드 예약 적용 스케줄러 (pendingChange를 실제 반영하는 배치) — 별도 REQ
- PG 결제 연동 실구현 (PaymentService는 현재 mock) — 보류 유지
- T-1 시간대 파라미터 설정 기능 (항상 UTC+9 고정)
