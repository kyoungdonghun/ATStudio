# REQ-20261010-ATS-009: 앱 DB 연결 검증과 운영 설정 준비

[REQ]
REQ ID: REQ-20261010-ATS-009
Project: ATS
Owner: MA
Status: completed within approved scope; native JDBC PASS, cleanup and documentation validation complete; production HOLD
Approval: 2026-10-10 사용자 "오케이 그럼 앱의 DB 연결 검증이랑 운영 설정 이어서 진행해줘. 추가 결제나 내가 직접 입력해야 하는 건 먼저 알려주고, 도메인 구매도 순서에 맞춰 챙겨줘."

[GOAL / WHY]
- 기존 운영 DB에 실제 배포 JAR의 JDBC 드라이버로 인증·읽기가 가능한지 확인한다.
- 완성된 운영 설정과 아직 선택/검증이 필요한 항목을 구분하고, 공개 전에 필요한 다음 순서를 정리한다.

[SCOPE]
- 로컬 검증 프로그램·회귀 테스트·운영 절차 준비 및 독립 보안 검토.
- 승인된 기존 JAR의 드라이버만 재사용하고 새로운 의존성/설치는 추가하지 않는다.
- 별도 승인 후 MA만 기존 서버에서 DB 비밀값을 프로그램 내부로 읽어 읽기 전용 JDBC 검사. 화면/로그/명령행/저장소로 값을 출력하거나 반입하지 않는다.
- 검사는 앱 전체를 기동하지 않는다. MySQL은 검사 중에만 loopback으로 기동하고 중지·재마스킹한다.
- 별도 승인 후 작업 중 PC SSH 에이전트를 임시 사용하고 정확한 키만 해제, Stopped/Disabled 복구.
- 현재 공개 소스/템플릿/이전 실제 적용 증거 기반 운영 설정 점검표를 작성한다. 도메인·메일 등의 미선택 값은 임의 확정하지 않는다.
- 제외: DB/계정/권한/시크릿 수정·재생성, 데이터 쓰기·삭제, 앱 전체 기동/공개 포트/메일·결제·외부 Provider, 새 유료 상품/도메인 구매, DNS 변경, 커밋/푸시.
- Hibernate 전체 검증과 canonical fresh manifest는 JDBC 성공과 별개다. 이번 검사로 완료라고 간주하거나 기존 UNRECORDED를 바꾸지 않는다.

[SUCCESS CRITERIA (DoD)]
- [x] 비밀값 보호·고정 대상·읽기 전용·오류 출력 제한이 있는 최소 검사 프로그램과 테스트.
- [x] 기존 JAR/드라이버/검사 바이트 동일성 및 독립 검토.
- [x] 명시 승인된 실제 JDBC 검증 및 서비스/에이전트 정리, 또는 정확한 미실행 사유.
- [x] 운영 설정 항목별 현재 근거·남은 결정·적용 순서 정리와 최신 문서 갱신.

[CONSTRAINTS / POLICIES]
- MA는 오케스트레이션 및 명시 승인된 기존 대상 작업, 구현은 WI 위임.
- 기존 파일/DB/키 보존, apply_patch, 작업별 소유 경로, 신규 의존성 금지.
- 기존 Gmail 수신 성공은 유효한 이전 환경 증거이며 새 서버 SMTP 성공은 별도다.
- atmusic.co.kr 구매는 DNS/HTTPS 전에 확인. 아직 소유/가용/가격/구매를 확정하지 않는다.
- 월7만원은 예산이며 비용 상한이 아니다. 추가 비용/직접 입력/예상치 못한 블로커는 먼저 알린다.

[QUALITY GATES]
- 현재 브랜치/HEAD/dirty 변경 및 JAR·드라이버 해시 확인.
- 고정 loopback DB/계정, 보안 파일 경로, 로그·예외·명령행 비밀값 비노출, JDBC 읽기 전용 세션 및 SELECT 한정.
- 전체 Spring 앱·작업자·스케줄러·메일을 실행하지 않는다.
- PG PASS와 민감정보 사용/임시 접속 승인 전 원격 검증 금지.
- 실패 시 고정 오류 코드와 비밀값 없는 사실만 기록. 설정을 임의로 완화하거나 계정/키를 교체하지 않는다.
- 서비스 정리와 에이전트 복구가 완료되어야 실제 작업 종료로 보고.

[RISKS / OPEN QUESTIONS]
- 운영 도메인 소유와 메일 공급자/계정은 아직 확정 증거가 없다.
- JDBC 인증 성공이 Hibernate·앱 전체 동작·부하·백업복원 성공은 아니다.
- 대안: 원격 승인이 없거나 검증이 막히면 로컬 검증 도구/설정 점검표를 보존하고 실제 작업만 대기한다.

[APPROVAL POINTS]
- 로컬 준비는 위 사용자 진행 지시로 승인.
- 이번 창의 임시 SSH 에이전트는 "이번 작업 중 임시 활성화 승인", 기존 DB 암호의 프로그램 내부 사용 및 읽기 검사는 "기존 DB 암호의 제한적 사용·읽기 전용 검증 승인"으로 명시 승인되었다. 비밀값 출력/계정 변경/앱 전체 기동은 포함하지 않는다.
- 운영 설정의 실제 외부 값 적용·앱 기동·공개·추가 결제는 구체적 범위 확인 후 별도 진행.
