# REQ-20261010-ATS-003: 서버 구매 전 SSH 및 방화벽 준비

[REQ]
REQ ID: REQ-20261010-ATS-003
Project: ATS
Owner: MA
Status: complete / 서버 구매 전 SSH 및 방화벽 준비 범위만 종료
Approval: 사용자가 "오케이 그럼 관리용 SSH만 지금 내 회선으로 제한해서 진행해줘. SSH 키랑 방화벽 준비하고, 서버 결제는 아직 하지 말고."라고 승인했다.

[GOAL / WHY]
- 서버 결제 없이 프로젝트 전용 SSH 접속 수단과 현재 관리자 회선에 한정된 무료 방화벽을 준비한다.

[SCOPE]
- In: 공식 요금/지원 방식 확인, 비밀정보 없는 작업 기록, 로컬 SSH 키 준비 도구, 사용자 직접 암호 입력, 공개키와 새 미연결 방화벽 정책의 준비/검증.
- In: SSH 인바운드 TCP 22만 현재 회선 한 개로 제한. 최초 설치용 최소 아웃바운드 정책을 검토한다. 기존 키/정책은 변경하지 않는다.
- Out: 서버 생성/결제, 유료 보안/네트워크 상품, 도메인, 기존 서버 접속/재설정, 전체 인터넷에 SSH/DB/백엔드 공개, 웹 일반 공개, 비밀정보 수집/공유, commit/push.
- 비밀키는 저장소 밖 현재 사용자 전용 디렉터리에 보관하며 암호는 사용자가 로컬에서 직접 입력한다. 공개키 실제 등록은 정확한 키 지문을 확인하고 등록 시점의 확인 절차를 따른다.

[SUCCESS CRITERIA (DoD)]
- 새 프로젝트 전용 암호화 키 생성과 보관 권한을 검증하고, 공개키만 등록 또는 사용자 입력 대기 상태를 정확히 구분한다.
- 무료 ELCAP의 현재 회선 /32 SSH 허용, 다른 인바운드 미허용, 아웃바운드 최소 포트와 전체 허용 금지 조건을 확인한다.
- 등록/미등록 및 미적용 상태를 구분하고 서버가 생성/과금되지 않았음을 확인한다.

[QUALITY GATES]
- MA가 키 준비 도구를 독립 검토한 후 사용자 암호 입력 절차를 시작한다.
- 읽기 전용 사전 점검, PowerShell 문법, 기존 파일 덮어쓰기 방지, 키/암호 비출력 및 실제 생성 상태 검증.
- 정적 검사나 방화벽 생성은 실제 서버 연결/보안 검증 성공이 아니다.

[RISKS / APPROVAL POINTS]
- 회선 IP 변경 시 허용 규칙 갱신이 필요하다. 기존 콘솔 복구 수단은 유지한다.
- 공개 웹 접속(80/443)은 SSH와 별개이며 아직 공개하지 않는다.
- 대안: 공급자 발급 초기 비밀번호만 사용하는 방식보다 프로젝트 전용 암호화 SSH 키를 우선한다. 무료 ELCAP에 서버 자체 방화벽을 추후 병행한다.
- 사용자 비밀 입력이나 등록 시점 확인을 기다리면 완료로 표시하지 않는다.
