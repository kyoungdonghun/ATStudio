[GOAL / WHY]
- V1 기준선에서 뒤늦게 발견된 구형 환경변수, 개인 PC 절대경로, 문서 생성 도구 경로 잔여를 제거한다.
- 수정 후 동일한 전수조사를 반복하는 대신, 이식성·재현성·현재 상태 정합성을 중심으로 한 최종 감사를 1회 수행하고 독립 재검수로 종료한다.
- 검증된 공식 브랜치를 원격에 보존한 뒤 클라이언트 인수테스트, 이전 브랜치 삭제 결정, 운영 준비 확인으로 진행할 수 있게 한다.

[SCOPE]
- In:
  - acceptance 환경변수 allowlist에서 사용되지 않는 `APP_PAYMENT_PROVIDER`, `TOSS_CONFIRM_URL` 제거 및 회귀 테스트
  - 데모 시드 도구의 폐기된 개인 credentials 기본 경로 제거 및 명시적 입력 계약 고정
  - 클라이언트 PDF provenance의 사용자별 Python/Poppler 경로 하드코딩 제거 및 이식 가능한 기록 방식 적용
  - 관련 문서 현행화
  - 전체 백엔드·프론트·문서 품질 검증
  - V1 최종 감사와 독립 재검수
  - 검증 완료 후 공식 브랜치 커밋 및 원격 푸시
- Out:
  - 클라이언트 인수테스트 실행과 Cloudflare 공개 환경 재기동
  - 이전 원격 브랜치 삭제
  - 운영 서버 배포 및 SR-93 운영 gate 실행
  - 제품 기능·결제 정책·DB 스키마 변경

[SUCCESS CRITERIA (DoD)]
- acceptance allowlist와 실제 `application*.yml` 환경변수 계약 사이에 사용되지 않는 구형 결제 변수가 없다.
- 데모 시드 도구는 직접 실행과 wrapper 실행 모두 credentials 경로를 명시적으로 받아야 하며 개인 경로를 기본값으로 사용하지 않는다.
- PDF 생성 매니페스트는 실행 PC에 관계없이 사실과 일치하는 tool provenance를 기록한다.
- 프로젝트 소스에 승인되지 않은 사용자별 절대경로 및 폐기 acceptance runtime 경로가 없다.
- 백엔드·프론트·문서 전체 품질 gate가 통과한다.
- 최종 감사에서 P0/P1 잔여가 0건이고, 발견 사항은 실제 결함·의도된 이력·운영 gate로 분리된다.
- 독립 재검수가 PASS를 반환한다.
- 공식 브랜치가 커밋되고 원격에 upstream과 함께 푸시된다.
