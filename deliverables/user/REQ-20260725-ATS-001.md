[GOAL / WHY]
- 실제 Gmail 이메일 인증 인수테스트에서 첫 인증은 성공했지만 React 개발 환경의 `StrictMode`가 인증 effect를 중복 실행하여 성공 화면이 "유효하지 않은 인증 링크" 실패 화면으로 덮이는 결함을 수정한다.
- 서버의 이메일 인증 토큰 단일 사용 정책은 유지하면서, 동일한 인증 화면 생명주기에서는 같은 토큰을 한 번만 전송하도록 보장한다.

[SCOPE]
- In:
  - `EmailVerifyPage`의 동일 화면 생명주기 중 인증 API 중복 호출 차단
  - React `StrictMode`에서 인증 API가 한 번만 호출되고 성공 화면이 유지되는 회귀 테스트
  - 기존 토큰 없음, provider 실패, 성공 화면 동작 회귀 검증
  - 프론트 typecheck, ESLint, Prettier, 테스트, build 검증
  - 실제 Gmail 인증 링크 재검증
- Out:
  - `StrictMode` 제거
  - 백엔드 이메일 인증 토큰의 단일 사용 및 만료 정책 변경
  - SMTP 계정, 메일 템플릿, DB 스키마 변경
  - 비밀번호 재설정 및 소셜 로그인 동작 변경

[SUCCESS CRITERIA (DoD)]
- `StrictMode`로 렌더링해도 동일 토큰에 대한 `verifyEmail` 호출은 정확히 1회다.
- 첫 인증 성공 후 성공 화면이 실패 화면으로 덮이지 않는다.
- 토큰 없음과 실제 서버 실패는 기존 안내를 유지한다.
- 백엔드 토큰 단일 사용 정책과 메일 전송 설정은 변경되지 않는다.
- 프론트 typecheck, ESLint, Prettier, 전체 테스트와 build가 통과한다.
- 새 Gmail 테스트 계정의 메일 링크에서 성공 화면과 `isVerified=true`가 일치한다.

[CONSTRAINTS / POLICIES]

- 현재 실행 중인 acceptance 환경과 저장소 밖 SMTP 보안 파일을 보존한다.

- 관련 없는 인증, 라우터, API 계약 또는 UI 스타일은 수정하지 않는다.
