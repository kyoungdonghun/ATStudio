[GOAL / WHY]
- 소규모 공개 운영이 가능한 배포 기반을 만든다. 제한 접근 배포는 실제 운영 검증 단계이지 지인 몇 명만 동작하면 완료하는 목표가 아니다.
- 코드 검증/체크리스트/문서 최신화의 기존 성과를 유지하고 실제 VPS 설정, 보안 경계, 복구 및 부하 검증으로 연결한다.
- 비용 및 용량 부족 징후는 측정 근거, 영향, 대안, 추가 비용과 함께 즉시 보고하며 무승인 증설하지 않는다.

[SCOPE]
- In: 단일 Linux VPS에 Nginx/React 정적 빌드, Java 17, MySQL 8, FFmpeg를 운영하는 배포 템플릿과 절차.
- In: loopback backend/DB, SSH 제한, HTTPS/갱신, 실제 사용자 IP, 보호 파일 경로, 요청/동시 전송 제한, 외부 비밀값, 운영 origin 및 최소 권한.
- In: 로컬 WAV 원본과 128kbps MP3 파생본 유지. Object Storage는 외부 백업 목적. 새 운영 DB 초기 구성 검증은 정확한 대상 승인 후 수행.
- In: DB/파일/설정/키의 일관된 백업, 보관량/기간/암호화/업체 밖 사본, 격리 복원 계획 및 대상 확정 후 검증.
- In: 로그 제한, CPU/메모리/디스크/전송량 관측, 장애/백업 실패 알림, 시간대, 단일 scheduler/변환 worker, 재부팅 및 rollback.
- In: 구매 전 오프라인 검증 도구. 이후 승인된 대상에서 기능 및 비용 제한된 동시 사용/부하 검증.
- Out: 구매/결제/유료 증설, 현재 runtime 재시작, 기존 DB/파일 삭제, 무승인 DB 생성/DDL, 실제 시크릿 취급, 무승인 외부 메일/결제 호출.
- Out: CDN, 별도 DB/LB, Object Storage로 주 음원 저장소 변경, 메일 업체 임의 전환, 연간 안내 기능, LIVE 결제/환불, 일반 공개.
- 서버 개통 후 원격 적용은 상품/호스트/도메인/변경 범위를 재확인한다. 파괴적 작업과 DB/비밀값 처리, 외부 발송은 별도 명시 확인한다.

[SUCCESS CRITERIA (DoD)]
- A. 구매 전: 설정 템플릿, 운영/복구/검증 절차, 부작용 없는 로컬 검증 도구, 회귀 테스트 및 독립 보안 검토를 완료한다.
- A. 설정 누락은 숨기지 않고 차단하며 secret 값을 출력하지 않는다. 정적 검사 PASS를 Linux 실행/운영 PASS로 오인하지 않는다.
- B. 대상 확정 후: strict integrity/새 DB 기동, HTTPS/IP/보호 파일 경계, 기능/메일/재부팅/알림/복원을 실제 대상에서 확인한다.
- B. 소규모 혼합 부하의 처리량, p95 지연, 오류, CPU/RAM/디스크/전송량/변환 대기열을 기록하고 지원 가능한 조건을 보고한다.
- C. 일반 공개 및 실결제는 별도 승인이다. A 완료만으로 전체 REQ 또는 production GO를 닫지 않는다.

[CONSTRAINTS / POLICIES]
- 기존 dirty 파일과 역사적 증거를 보존한다. 제품 코드 변경은 실제 배포 결함이 확인된 최소 범위만 별도 WI로 추적한다.
- 현재 단계는 저장소 신규 배포 자산 및 독립 검증만 수행한다. DB 접속, 애플리케이션 기동/종료, 공개 터널 부하, 이메일 발송을 하지 않는다.
- 기존 Gmail 수신과 WAV/MP3 및 휴대폰 TEST 증거는 유지한다. 새 대상 검증만 추가한다.
- 가격/약관을 이번 작업에서 확정하지 않는다. 트래픽 정산, inbound 적용 기준, 공격 과금/차단 및 비용 상한 미확정 사항을 구매 gate에 남긴다.
- 최초 SSH/방화벽 적용과 DB 초기화는 안전한 복구 경로 및 정확한 대상 확인 후 별도 수행한다.
- 추가 라이브러리 설치/새 인프라 채택 없이 기존 도구 및 표준 라이브러리를 우선한다.

### B단계 착수 입력과 승인

1. 정확한 업체·상품·OS·호스트·도메인·운영 계정 대상을 정하고 구매 승인을 별도로 확인한다. 허용 전송량, 월중 시작 정산/초기화, inbound 및 50Mbps 적용, 공격 과금/자동 차단과 비용 상한은 미확정 gate로 유지한다. 가격·약관 재조사는 이번 마감에서 하지 않았다.
2. SSH fingerprint·접근 범위·복구 콘솔과 되돌릴 경로를 확인한 뒤 정확한 원격 변경을 승인한다. JWT/필수 billing keyring 등 외부 비밀값 설정, 새 DB/DDL·fresh manifest 검증 및 첫 ADMIN 준비는 대상별 별도 확인 후 수행한다. TEST bootstrap이나 원격용이 아닌 disposable 도구로 우회하지 않는다.
3. 백업 목적지·암호화/키 소유자·보관/스테이징 용량·cold downtime, 복원 격리 대상, 알림/메일 수신자 및 기간·바이트가 제한된 부하 범위를 확정한다. 외부 발송과 민감/파괴적 작업은 각각 승인하고 대상별 B WI를 생성한다. 일반 공개와 LIVE 결제/환불은 계속 별도 승인이다.
