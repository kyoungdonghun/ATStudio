# REQ-20261106-ATS-003 — 검토된 변경의 안전한 커밋·푸시

[REQ]
- Project: ATS
- Owner: MA
- 승인: 사용자가 서버 작업을 퇴근 후로 보류하고, 현재까지 변경을 민감정보 검사한 뒤 필요한 파일만 선택하여 커밋·푸시까지 진행하도록 명시적으로 승인했다. 꼭 필요한 판단·직접 로그인만 요청한다.

[GOAL / WHY]
- 검토 완료한 애플리케이션·운영 도구·재현 가능한 문서를 Git에 보존하고 기존 GitHub 원격에 정상적인 fast-forward push 후 동일 HEAD를 확인한다.

[SCOPE]
- 포함: 읽기 전용 현황/원격·훅 확인, 기존 검사기 재사용, 비밀/PII 검토, 필요한 파일·문서/안전한 요약 선별, 최소 보안 보완, 기존 증거 대조와 필요한 품질 검사, 범위별 커밋·비강제 푸시·최종 확인.
- 제외: 실서버·클라우드 접속/실행, UAC·SSH agent 변경, 실제 백업/복원/DB/메일/결제/비용, 배포, 원시 비공개 증거·개인 입력·키·음원·빌드 산출물 게시, 무관한 미추적 파일 정리/삭제, Git 이력 재작성/force push.

[SUCCESS CRITERIA (DoD)]
- 원본·기존 실패 증거와 무관한 작업 트리를 보존하고, 포함/제외 파일 및 근거를 해시로 기록한다.
- PG가 검사 결과를 판정하고 EO가 공유 범위를 확인한다. 패턴 무검출을 완전한 비밀 부재 보장으로 표현하지 않는다.
- 검토한 파일 내용과 staged blob을 비교하고 민감정보 검사를 최종 staged/commit 대상에 적용한다.
- 관련 기존 시험 결과와 source identity를 재사용한다. 새로운 수정만 필요한 집중 검증을 수행한다.
- 목적별 커밋과 원격 동일 HEAD 확인. 원격 diverge/인증 문제는 실제 상태를 확인하며 무작정 재시도하지 않는다.

[EXECUTION STRATEGY]
| 작업 | 담당 | 스킬/근거 |
|---|---|---|
| 민감정보 검사·최종 후보 판정 | pg | 기존 scan_commit_candidates_wi004.py, create-wi-evidence-pack |
| 작업/파일 선별·검증 증거·공유 적합성·문서 통합 | eo/docops | create-wi-handoff-packet, lint, validate-docs, create-wi-evidence-pack |
| 승인된 파일 stage·commit·push·원격 확인 | MA | security-policy Git execution role, WI006 검토 manifest |

[QUALITY GATES]
- 개인정보·secret 원문을 도구 출력/문서/커밋에 표시하지 않는다. 스캐너 출력은 종류·위치·해시만 사용한다.
- 오래된 원문 증거를 통째로 수정하지 않는다. 민감하거나 모호한 원문은 로컬에 남기고 필요한 안전한 요약/재현 자산을 선별한다.
- branch/upstream/history/hook/CI 효과와 remote divergence 확인; 외부 서버 효과를 유발하는 배포 workflow가 있다면 그 효과는 별도 범위다.
- 새 비용·범위 밖 효과·직접 로그인 이외의 통상 보완은 재확인 없이 수행한다.
