[GOAL / WHY]

- WI-011의 단일 wrapper `Inventory` 실행은 증적 수집 gate가 출력 그룹을 하나로 잘못 가정해 실제 `Inventory` 결과를 보존하지 못했다. 이는 Inventory 또는 DB 실패의 증거가 아니라 증적 수집 결함이다.
- 지원 wrapper의 실제 계약인 `Preflight` 완전 안전 필드 그룹 1개 후 실제 `Inventory` 그룹 1개를 엄격히 해석하여, 읽기 전용 Inventory 증거를 한 번만 다시 수집한다.

[SCOPE]

- In:
  - `qa-integ` 단일 WI에서 메모리 내 strict parser와 새 guard-valid companion name 1개를 사용한다. companion name은 wrapper preconnection guard 입력일 뿐 조회 대상도 기록 대상도 아니다.
  - 지원 PowerShell wrapper를 `Inventory`로 정확히 1회 실행한다. wrapper 내부의 첫 `Preflight` 그룹은 별도 Preflight 실행이 아니다.
  - parser는 순서대로 정확히 2개 완전 그룹만 허용한다.
    - 그룹 1: `action=preflight`, 표준 preflight safe fields, `status=PASS`, 그리고 wrapper 요청이 `Inventory`였음을 전제로 한 허용된 requested-Inventory 의미론.
    - 그룹 2: `action=inventory`, 표준 공통 safe fields와 `inventory.count` 1개, 그 count와 일치하는 `inventory.state` 1개, `status=PASS`.
  - 표준 safe fields는 현재 지원 도구가 내는 action, database-pattern PASS, loopback host class, schema-to-seed order, 43-table source count와 PASS check, manifest expectation, 두 source hash 및 Inventory의 count/state로 한정한다. 허용되지 않은 field/value, 누락, 중복, 순서 위반은 거부한다.
  - count가 0이면 `NO_POSSIBLE_ORPHAN`, 양수이면 `POSSIBLE_ORPHAN_EXISTS`만 정제 증거에 기록하고 즉시 종료한다.
- Out:
  - 코드, 스크립트, README, 다른 문서, 기존 WI-011 산출물의 변경. WI-011은 역사 기록으로 보존하며 새 정확한 증거만 parser 계약 정정을 참조할 수 있다.
  - 별도 Preflight, Observe, Create, Validate, Drop, 추가 Inventory 재시도, 다른 DB query, 삭제ㆍcleanupㆍDDLㆍDMLㆍschema/seed/patch/manifest 동작.
  - 원시 stream, DB/schema 이름, connection 정보, credential/secret, bundle 세부 정보의 캡처ㆍ출력ㆍ기록.
  - browser, application, external-service, Git 동작.

[SUCCESS CRITERIA (DoD)]

- 새 companion name 1개만 생성하고, 지원 wrapper `Inventory`를 정확히 1회 실행한다.
- strict parser는 wrapper 요청 `Inventory`에 결속된 완전한 preflight 그룹과 완전한 Inventory 그룹을 순서대로 정확히 2개만 허용하며, 두 그룹의 terminal `status`가 모두 `PASS`일 때만 결과를 수용한다.
- parser는 raw stream을 저장하지 않는다. 정제 증거에는 허용된 최종 count/state 또는 일반 안전 block `INVENTORY_EVIDENCE_GATE_BLOCKED`만 남기며, 금지 정보는 남기지 않는다.
- 어느 그룹이 malformed이거나 terminal state가 `PASS`가 아니면 재시도하지 않고 일반 안전 block만 기록 후 종료한다.
- 수용된 count/state는 `0`/`NO_POSSIBLE_ORPHAN` 또는 양수/`POSSIBLE_ORPHAN_EXISTS`의 한 쌍뿐이며, 어느 경우에도 삭제나 cleanup 없이 종료한다.
