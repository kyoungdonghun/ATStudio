[GOAL / WHY]
- 구매된 기존 서버에 새 운영 데이터 기반과 검증된 배포 산출물을 준비한다.
- 테스트 데이터/키를 재사용하지 않고, 과거 검증과 이번 실제 적용을 구분한다.

[SCOPE]
- 현재 승인된 Ubuntu24.04 기존 서버 1대만 대상. 새로운 유료 상품/서버 구매 없음.
- 로컬: 현재 dirty 소스의 해시·변경집합을 기록하고 새 JAR/React 산출물 빌드, DB 초기화 및 비밀값 보호 절차/테스트 준비, 독립 검토.
- 사용자가 구체적 질문에 "위 새 DB·전용 계정·시크릿 생성 승인"으로 승인했다. 정확한 새 DB atstudio_prod 및 전용 계정 atstudio_app만 생성. 동일 이름이 있으면 중지, 기존 데이터 삭제/덮어쓰기/이관 금지.
- 현재 fresh-only schema.sql 및 seed.sql의 기본 요금제 6개만 초기화. 사용자/ADMIN/음원/결제 데이터는 생성하지 않는다. 앱에는 해당 DB의 SELECT/INSERT/UPDATE/DELETE만 부여하고 DDL/global/FILE/GRANT 권한은 부여하지 않는다.
- DB 비밀번호, Base64 JWT 서명키, 독립 내부 결제정보 암호화 키를 서버에서 각각 난수로 생성하고 root 전용 파일에 보관. 비밀값/파생 인증값 출력, 저장소 반입, 외부 전송, 기존 키 교체 금지. 생성/SQL 실행은 검토된 절차와 실제 대상 검증 후에만 한다.
- "이번 작업 중 임시 활성화 승인"으로 PC ssh-agent 임시 사용 승인. 사용자가 직접 기존 키 암호 입력, 작업 후 정확한 키만 제거하고 Stopped/Disabled 복구.
- MySQL은 승인된 초기화·검증 때만 loopback으로 기동한다. 이번 종료 시 중지·재마스킹한다. 자동 기동·앱 실행·Nginx/공개 포트 확대·메일/Provider 호출·첫 ADMIN 생성은 별도 게이트다.
- 도메인 atmusic.co.kr 구매는 DNS/HTTPS 이전 필수 미완료 항목. 이번에는 구매/DNS 변경/ACME 발급을 자동 실행하지 않는다.
- 제외: 기존 DB 변형/삭제, 테스트 DB·사용자 이관, 임의 disposable DB 생성/삭제, production 공개, 새 라이브러리/유료 서비스/도메인 결제, 재부팅, 커밋/푸시.
