[GOAL / WHY]
- **목표**: 6.x Subscription 섹션 10개 API 구현 — 마지막 미착수 섹션으로, 완료 시 전체 79개 API 중 79/79 (100%) 달성
- **왜**: 구독 플랜 조회, 신청, 관리, 취소 기능은 ATStudio 수익 모델의 핵심. 기존 엔티티(Subscription, UserSubscription, SubscriptionPayment)가 이미 정의되어 있어 Service/Controller/DTO 구현만 남은 상태
- **결제 방침**: 실제 PG 연동 없이 Mock 결제 처리. POST /api/user-subscriptions 호출 시 즉시 ACTIVE 상태로 전환, SubscriptionPayment 레코드만 기록. PaymentService 인터페이스로 추상화하여 추후 PG 연동 교체 용이하게 설계

[SCOPE]
- In:
  - 6.1 `GET /api/subscriptions` — 구독 플랜 목록 조회 (PUBLIC, userType 필터)
  - 6.2 `GET /api/subscriptions/{subscriptionId}` — 구독 플랜 상세 조회 (PUBLIC)
  - 6.3 `POST /api/user-subscriptions` — 구독 신청 (AUTH, Mock 결제, COMPANY_CERTIFICATION_REQUIRED 체크)
  - 6.4 `GET /api/user-subscriptions/me` — 내 구독 조회 (AUTH)
  - 6.5 `GET /api/user-subscriptions` — 전체 구독 목록 (ADMIN, 페이지네이션)
  - 6.6 `GET /api/user-subscriptions/{userSubscriptionId}` — 구독 상세 (ADMIN)
  - 6.7 `PUT /api/user-subscriptions/me` — 업/다운그레이드 (AUTH, proratedAmount 일할 계산)
  - 6.8 `PUT /api/user-subscriptions/{userSubscriptionId}` — 관리자 구독 수정 (ADMIN)
  - 6.9 `DELETE /api/user-subscriptions/{userSubscriptionId}` — 관리자 구독 취소 (ADMIN)
  - 6.10 `DELETE /api/user-subscriptions/me` — 셀프 구독 취소 (AUTH, 즉시 CANCELLED)
  - 위 10개 API에 대한 단위 테스트 + 컨트롤러 테스트 작성

- Out:
  - 실제 PG(결제 대행사) 연동 (카카오페이, 토스 등) — 추후 별도 REQ
  - 구독 갱신 자동화 (배치/스케줄러) — 추후 별도 REQ
  - 구독 플랜 CRUD 관리 (관리자 플랜 생성/수정/삭제) — 기존 설계 범위 외
  - 결제 환불 처리 — 추후 별도 REQ

[SUCCESS CRITERIA (DoD)]
