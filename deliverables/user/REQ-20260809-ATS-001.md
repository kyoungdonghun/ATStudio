[GOAL / WHY]

- AT.M의 일부 화면이 아니라 모든 활성 화면, 사용자 행동, 역할, API 연결부를 대상으로 UI/UX 전수 인수검사를 수행한다.
- 프로젝트 문서, 현행 코드와 데이터 계약, 일반적인 웹 UX·개발 원칙, 실제 브라우저 증거를 함께 사용하여 기능 결함, 문서 불일치, 정책 판단 필요 사항을 구분한다.
- 웨이브폼처럼 동일 기능이 앨범·음원 목록·상세·플레이리스트 등 서로 다른 진입점에서 다르게 실패하는 문제와, 구독·결제·CSV처럼 화면만으로 판정할 수 없는 복잡한 흐름을 API·DB 증거까지 연결해 검증한다.
- 단계마다 사용자 승인을 요구하지 않고 자율 진행하되, 정책 변경·파괴적 데이터 작업·실제 외부 부작용·보안·아키텍처·배포 판단만 사용자에게 에스컬레이션한다.

[SCOPE]

- In:
  - 활성 React 라우트, 메뉴, 모달, 사용자 행동, 프론트 API, 백엔드 엔드포인트, 주요 DB 상태 전이 인벤토리
  - 비회원, 일반 회원, 창작자, 기업 회원, 관리자 역할별 접근·표시·행동 검사
  - 로딩, 정상, 빈 상태, 실패, 권한 없음, 만료, 중복 제출, 결과 불명 상태 검사
  - 데스크톱, 좁은 화면, 모바일 UI/UX와 키보드·포커스·기본 접근성 검사
  - 공개·인증·계정·기업 인증·화이트리스트·카탈로그·검색·재생·회원 기능·창작자 기능·구독·결제·관리자 운영·CSV·메일 관련 흐름
  - 화면·콘솔·네트워크·API·DB 증거를 연결한 판정과 독립 재검수
  - 명백한 결함 수정, 인접 영향 범위 회귀검사, 문서 현행화, 전체 재검사
- Out:
  - 실제 운영 결제·환불·취소와 운영 사용자 데이터 변경
  - 별도 승인 없는 DB 스키마 변경, 기존 데이터 일괄 삭제, 마이그레이션
  - 제품 정책 변경, 기능 추가·제거, 신규 라이브러리·아키텍처 도입
  - 운영 배포, 브랜치 병합·삭제, 최종 클라이언트 승인 대체
  - 사람의 미적 취향, 실제 모바일 기기 감각, 실제 청취 품질에 대한 최종 판단 대체

[SUCCESS CRITERIA (DoD)]

- 모든 활성 라우트와 주요 사용자 행동이 `PASS`, `FAIL`, `BLOCKED`, `N/A` 중 하나로 분류되고 미분류 항목이 없다.
- 문서 → 화면 → 행동 → API → DB 추적표와 역할 × 상태 × 데이터 × 뷰포트 × 중단 조건 마스터 행렬이 완성된다.
- 동일 기능의 모든 진입점이 별도 사례로 검증되고, 공통 API·DTO·Store 변경의 인접 영향 범위가 기록된다.
- 핵심 상태 전이와 복잡 흐름은 UI 문구, 요청, Provider 또는 대체 경계, 로컬 저장, 새로고침 후 화면을 연결해 판정한다.
- 설명되지 않은 브라우저 콘솔 오류, 네트워크 실패, 화면·API·DB 모순을 결함 또는 잔여 위험으로 모두 분류한다.
- 명백한 P0/P1 결함이 0건이고, 해결하지 않은 P2/P3·외부 경계·정책 항목은 근거와 다음 조치가 기록된다.
- 명백한 결함 수정 후 집중 검사, 인접 회귀검사, 전체 재검사를 통과한다.
- 백엔드 테스트·커버리지, 프론트 테스트·커버리지·typecheck·ESLint·Prettier·build, 문서 검증, diff 검사가 통과한다.
- 현재 동작 문서와 실제 구현이 일치하고 최종 감사 보고서와 사용자 인수테스트 체크리스트가 완성된다.

[CONSTRAINTS / POLICIES]

- Work tracking unit: WI
- 감사 기준선은 `codex/v1-release-rehearsal-fixes`의 `e343c20`이며, 초기 감사 완료 전 제품 코드를 수정하지 않는다.
- 의도적 미추적 파일 `output/client-demo-screenshots-20260716-140514.zip`은 범위 밖이며 수정·삭제·스테이징하지 않는다.
- 비추적·무시된 비밀 설정 파일과 환경변수 값을 읽거나 출력하지 않는다.
- 테스트 계정의 정상적인 생성·수정 흐름은 허용하지만, DB 스키마 변경·기존 데이터 삭제·운영 데이터 변경은 별도 승인을 받는다.
- Toss 테스트 경계는 실제 금전 부작용 없이 검증한다. 실제 결제·환불·Provider 취소는 별도 승인 전 실행하지 않는다.
- 메일은 로컬 수신기 또는 승인된 전용 수신 주소만 사용하며 실제 외부 발송이 필요하면 실행 전에 보고한다.
- 일반적 UX 관행은 프로젝트의 명시적 정책보다 우선하지 않는다. 충돌은 자동 수정하지 않고 정책 항목으로 분류한다.
- 하나의 Subagent만 순차 사용하고 `fork_context=false`를 유지하며 완료 즉시 종료한다.
- 조사 결과와 증거는 파일로 남겨 대화 컨텍스트와 브라우저 세션 부하를 제한한다.
