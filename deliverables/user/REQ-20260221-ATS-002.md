  - **Notice** (5개): POST /api/notices (ADMIN 생성), GET /api/notices (목록·고정 우선), GET /{id} (상세), PUT /{id} (ADMIN 수정), DELETE /{id} (ADMIN 삭제)
  - 각 도메인 Service + Controller + DTO 구현
  - 서비스 단위 테스트 + 컨트롤러 권한 테스트

[RISKS / OPEN QUESTIONS]
- **Risks**:
  - play_count 동시성: 여러 사용자가 동시에 재생 기록을 저장할 경우 `@Transactional`로만으로는 increment 경쟁 발생 가능 → `@Modifying @Query("UPDATE Track t SET t.playCount = t.playCount + 1 WHERE t.id = :id")` 사용 필요
  - Likes/DownloadQueue 중복 추가: 복합 PK 제약으로 DataIntegrityViolationException 발생 → GlobalExceptionHandler에서 DATA_INTEGRITY_VIOLATION으로 이미 처리됨 (409 반환)
- **Questions**: 없음 (api-spec v5, db-schema v4 확정 기준으로 실행 가능)
