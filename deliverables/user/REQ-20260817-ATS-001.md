[GOAL / WHY]

- 이전 일회성 DB 패치 복구가 DB 연결이나 DDL 전에 차단된 원인을 바로잡는다. 기존 사설 번들은 datasource 범위상 구조적으로 유효했으나, 임시 PowerShell 사전점검이 예약 자동 변수 `$Host`에 값을 할당해 `SessionStateUnauthorizedAccessException`이 발생했고 이를 `PREFLIGHT_BUNDLE_INVALID`로 잘못 정제했다. 이는 사용자 파일 결함이 아닌 운영 사전점검 결함이다.
- 같은 기존 사설 번들을 사람이 열람하지 않는 외부 일회성 러너로 다시 사전점검하고, 모든 보호 조건이 통과할 때만 승인된 현재 로컬 DB에 기존 `user_consents` 패치를 정확히 한 번 적용ㆍ검증한다.

[SCOPE]

- In:

  - 평면 JSON, 비어 있지 않은 datasource 값 3개, JDBC MySQL loopback, 포트 `3306`, 데이터베이스 `atstudio` 조건의 비공개 엄격 검증
  - 검증 후 승인된 현재 로컬 DB 하나에만 연결하여 `user_consents` 부재를 증명하고, `scripts/database/patches/WI-20260809-ATS-068-user-consents.sql`만 정확히 한 번 적용
  - 적용 뒤 구조 비교로 `user_consents`만 추가되고 제거ㆍ예상 밖 추가가 없음을 정제된 증거로 확인

  - 앱/런타임/브라우저/Git/외부 서비스 호출, 재시도, 롤백, `DROP`, 데이터 삭제, 추가 SQL 또는 대상 확대
  - 일회용 43-테이블 증명. 이는 원래의 별도 `WI-20260816-ATS-002`가 계속 관할한다.

[SUCCESS CRITERIA (DoD)]

- 외부 일회성 러너는 `$Host`를 사용하지 않으며, 사전점검 실패 시 DB 연결과 SQL 전에 중단하고 정제된 실패 사유만 남긴다.
- 사전점검은 번들 값ㆍ경로ㆍ식별자를 출력하거나 영속화하지 않고 모든 형식ㆍ완전성ㆍ범위 조건을 통과해야 한다.
- 통과 뒤에도 승인된 현재 로컬 DB 하나만 연결 가능하며, `user_consents=ABSENT`가 아니면 SQL을 실행하지 않는다.
- 허용 SQL은 기존 패치 파일 하나뿐이고, 적용은 최대 한 번이다.
- 사후 구조 검증은 `user_consents=PRESENT`, 제거 `0`, 예상 밖 추가 `0`만 통과로 인정한다.
- 실패ㆍ모호성ㆍ불일치에서는 SQL, 재시도, 롤백, 삭제 없이 중단하고 비밀값 없는 증거를 기록한다.
