# 개인정보 처리 흐름과 후속 보완 준비

가입·소셜 로그인·인증 메일·사업자 인증·다운로드·라이선스·결제·브라우저 저장이 어디에 남고 탈퇴 때 어떻게 처리되는지 소스 근거로 정리했습니다. 기존 HWP 검토를 재사용했고 원문이나 코드는 바꾸지 않았습니다. 2026-10-26 로컬 확인이며 서버·실제 고객정보·공급자 계정은 조회하지 않았습니다.

가장 먼저 고칠 방향을 정해야 할 부분은 **탈퇴 후 기록 처리**입니다. 현재는 회원정보에 삭제 표시를 하고 이메일·전화·비밀번호 해시 등은 남기는 반면, 다운로드·라이선스 기록은 삭제합니다. 따라서 전부 지우는 방식도, 전부 남기는 방식도 바로 적용하면 안 됩니다. 클라이언트가 기존 콘텐츠의 계속 사용권을 보장한다면 개발자는 이를 입증할 최소 기록을 남기고, 목적이 끝난 개인정보는 별도로 지우거나 최소화하도록 바꿔야 합니다.

| 먼저 준비한 내용 | 다음 작업과 연결되는 점 |
|---|---|
| 필수·조건부·선택 수집항목을 구분한 흐름표 | 약관 답변이 오면 실제 수집항목 설명을 바로 맞출 수 있습니다. |
| 회원·연동·동의·증빙·라이선스·채널·결제별 탈퇴 처리 목록 | 각 기록의 보존 목적과 기간을 확정하면 개발자가 삭제·분리 보관·외부 해제 범위를 정할 수 있습니다. |
| 동의 철회·메일 토큰·브라우저 저장의 확인 지점 | 동의 저장과 철회/발송 제외, 토큰 유효기간과 실제 삭제, 로그아웃과 재생 이력 삭제를 각각 검증하게 됩니다. |
| 변경 후에만 수행할 8개 집중 검증 시나리오 | 기존 1단계 전체 시험을 반복하지 않고 바뀐 탈퇴·동의·복원 동작에 집중할 수 있습니다. |

**Toss 유지 결정도 반영했습니다.** KG이니시스로 전환할 개발은 필요하지 않습니다. 계약·LIVE 검증과 NCP 실제 전환은 아직 남아 있습니다.

상세 산출물: [처리 흐름표](../../build/WI-20261026-ATS-002/privacy-data-map.md), [보완 순서·담당·검증안](../../build/WI-20261026-ATS-002/remediation-and-verification.md). 기록별 보유기간이나 법적 근거를 임의로 정하지 않았고 실제 개인정보 삭제·백업·앱 실행은 하지 않았습니다.
