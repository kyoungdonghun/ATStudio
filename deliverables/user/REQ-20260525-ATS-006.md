[GOAL / WHY]
- 결제 운영 기능은 환불, 권한 보정, 영수증 근거, 운영 감사 로그까지 backend admin API로 구현되었다.
- 현재 `/admin/payments` 화면은 주문, 자동결제, 결제내역, 대사 Incident만 제공하므로 운영자는 환불/권한보정/영수증/감사로그를 API로 직접 호출해야 한다.
- 먼저 남은 문서 표현을 현행 코드 기준으로 정리하고, 관리자 결제 운영 화면에서 backend-only 기능을 사용할 수 있게 한다.

[SCOPE]
- In:
  - `payment-integration-design.md`와 `payment-refund-receipt-settlement-policy.md`의 낡은 표현을 현행 구현 기준으로 보정한다.
  - `/admin/payments`에 영수증, 감사로그, 환불, 권한 보정 탭을 추가한다.
  - 환불 탭은 결제내역 기반 preview, request, approve, execute 흐름을 제공한다.
  - 권한 보정 탭은 성공 환불 기반 preview, request, approve, execute 흐름을 제공한다.
  - 위험한 mutation은 명확한 확인 문구와 운영자 메모 입력을 요구한다.
  - frontend API client 타입/호출 함수를 추가한다.
  - SR-93, UI 문서, 최종 인수 체크리스트를 현행화한다.
- Out:
  - settlement import/reconciliation 구현.
  - tax invoice request/admin workflow 구현.
  - cash receipt 발급/취소 자동화.
  - Toss webhook 구현.
  - multi-PG 확장.
  - multi-server scheduler lock.
  - backend 환불/권한보정 정책 변경.

[SUCCESS CRITERIA (DoD)]
- 문서가 현재 구현 상태와 모순되지 않는다.
- `/admin/payments`에서 영수증과 감사로그를 조회할 수 있다.
- `/admin/payments`에서 환불 preview/request/approve/execute를 수행할 수 있다.
- `/admin/payments`에서 성공 환불에 대한 권한 보정 preview/request/approve/execute를 수행할 수 있다.
- 화면과 API 타입은 raw billing key, authKey, customerKey, Toss secret, raw card data, raw provider payload를 표시하지 않는다.
- `npm run typecheck`, `npm run lint`, `npm run build`, 관련 backend tests, docs validation이 통과한다.
