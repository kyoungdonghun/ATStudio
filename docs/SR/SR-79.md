# SR-79 다운로드 기록 페이지 전면 개편 (구 다운로드 대기열)

> **우선 가치**: "다운로드 대기열"이라는 이름·개념이 실제 구독형 서비스 맥락과 맞지 않음. 구독자는 좋아요가 후보열 역할을 하므로, 이 페이지는 **실제로 다운로드를 완료한 곡들의 기록**만 보여주는 페이지로 전환한다. 재다운로드를 기본 상호작용으로 삼고, 정렬·검색·페이징·태그 표기 등 음원 목록 수준의 탐색성을 제공한다.

## 환경

- PC, 모바일 공통

## 배경 및 개념 전환

- 현행: "다운로드 대기열" 페이지는 다운로드 전/후 상태를 함께 보여주는 구조
- 변경: 구독으로 구매한 모델 특성상, **미다운로드 = 후보열**이라는 개념은 불필요
  - 후보열 역할은 이미 **좋아요** 목록이 담당
  - 따라서 본 페이지는 **"이미 다운로드한 기록"** 만 노출하는 단일 목적 페이지로 전환

## 수정 내용

### 1. 라벨 변경 (UI 한정)

- 상단 내비게이션(GNB), 페이지 타이틀, 관련 버튼 텍스트: **"다운로드 대기열" → "다운로드 기록"**
- **DB 테이블/엔티티명(`download_queue`)은 변경하지 않음** — 내부 코드 레벨 리네임 불필요, 사용자 노출 문구만 정리
- 필요 시 프론트엔드 타입/메뉴 라벨 상수만 정리

### 2. 목록에서 미다운로드 개념 제거

- 다운로드 완료된 항목만 조회 — 미다운로드 필터/탭/뱃지/상태 표시 제거
- 관련 UI 요소(상태 칩, "미다운로드" 라벨 등) 정리

### 3. 음원 목록과 동일한 정보 표기

- 곡 제목, 썸네일, **태그 영역** 등을 음원 목록(`TrackRow` 등 재사용)과 동일한 수준으로 노출
- 태그는 SR-80에서 확정되는 태그 영역 폭 정책과 **일관**되게 적용

### 4. 정렬

- **최신순 / 오래된순** 정렬 옵션 추가 (기본: 최신순)
- 다운로드 완료 시각 기준

### 5. 페이징

- **페이지당 20건** (음원 목록과 동일한 정책)
- 기존 `Pagination` 공용 컴포넌트 재사용

### 6. 선택 / 전체 체크박스 → 재다운로드 액션

- 각 행에 개별 체크박스 + 헤더에 전체 선택 체크박스 추가
- 액션 버튼:
  - **선택 재다운로드** (체크된 항목만)
  - **전체 재다운로드** (필터 결과 전체, 페이지가 아니라 조건 전체 기준)
- **삭제 기능은 제공하지 않음** — 구독으로 구매한 기록이므로 사용자 판단으로 삭제할 필요 없음 (클라이언트 요청)
- 기존 단일 다운로드 버튼(아래 화살표)도 유지 — 개별 재다운로드용

### 7. 검색란

- 상단에 검색 입력 추가
- 검색 대상: **제목 + 태그** (아티스트는 SR-81에 따라 비노출이므로 제외)
- 디바운스 + 서버 사이드 필터 (페이징과 결합 고려)

## 확인 사항

- 백엔드 API: 기존 `download_queue` 조회 API에 정렬/검색/페이징 파라미터가 있는지 확인 후, 부족하면 `se`에 위임하여 확장
- 일괄 재다운로드 시 **ADMIN bypass**, **구독 일일 한도**, **동시 다운로드 수** 정책이 어떻게 적용되는지 `pg`/`se` 검토 필요
- 재다운로드 시 통계(다운로드 카운트) 중복 증가 여부 정책 결정 (이미 받은 곡 재요청 시 카운트 미증가 권장)

## 연관 SR

- SR-80: 태그 영역 폭 정책
- SR-81: 아티스트 숨김 (검색 대상에서 제외되는 이유)
