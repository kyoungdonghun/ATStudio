# SR-98 음원 썸네일 업로드 비율 안내와 잘림 미리보기 추가
> **우선 가치**: 정사각형 카드의 일관성을 유지하되, 업로드 전에 실제 화면에서 잘릴 범위를 운영자가 알 수 있게 한다. 종횡비를 깨는 강제 늘림은 사용하지 않고, 단일 운영자 환경에서는 복잡한 크롭 편집기보다 명시적인 1:1 계약과 동일 미리보기를 먼저 적용한다.

## 환경

- 크리에이터 음원 업로드·수정 화면
- 음원 상세, 목록, 하단 플레이어, 관리자 음원 목록의 썸네일
- PC, 모바일 공통

## 인수 테스트에서 확인된 현상

- 음원 썸네일로 올린 사진의 일부가 여러 화면에서 잘려 보임.
- 인수 테스트 시점의 실환경 `track 1`은 설명에 `이미지의 비율 관련 ux 확인(세로로 김)`이라고 기록되어 있었음.
- 해당 썸네일 파일은 HTTP 조회 기준 564×1404px의 세로 이미지였고, 화면에서는 정사각형 카드로 표시됨.

## 원인 구분

1. 현재 음원 업로드 화면은 `image/*`와 10MB 파일 크기만 검사하며, 종횡비·해상도 안내, 파일 선택 직후 미리보기, 정사각형 검증을 제공하지 않음.
2. 현재 `TrackService`는 음원 썸네일을 원본 파일 그대로 저장함. 플레이리스트 등 일부 이미지 경로에서 사용하는 기존 정규화 서비스가 음원 썸네일에는 적용되지 않음.
3. 음원 상세, 목록, 하단 플레이어, 관리자 음원 목록은 정사각형 또는 고정 박스와 `object-fit: cover`를 사용함.
4. `cover`는 원본 비율을 유지한 채 박스를 가득 채우므로, 세로 이미지에서는 넘치는 위·아래 영역이 잘림.

따라서 현재 현상은 **리사이즈로 이미지가 찌그러진 것이 아니라, 세로 원본이 정사각형 `cover` 영역에서 비율을 유지한 채 잘린 것**임.

## 처리 방식 비교

| 방식 | 비율 보존 | 잘림 | 여백 | 왜곡 | 용도 |
| --- | --- | --- | --- | --- | --- |
| 비율 보존 리사이즈 | 예 | 없음 | 저장 파일에는 해당 없음 | 없음 | 용량·해상도 최적화. 정사각형 변환은 아님 |
| `cover` 크롭 표시 | 예 | 있음 | 없음 | 없음 | 크기가 일정한 카드. 잘림 미리보기 필요 |
| `contain` 표시 | 예 | 없음 | 비율이 다르면 있음 | 없음 | 원본 전체 노출이 우선인 화면 |
| 패딩 추가 | 예 | 없음 | 지정한 배경으로 채움 | 없음 | 정사각형 파일이 필요하지만 전체를 보존할 때 |
| `fill` 강제 늘림 | 아니오 | 없음 | 없음 | 있음 | 이미지가 찌그러지므로 권고하지 않음 |

- **리사이즈**는 가로·세로에 같은 배율을 적용해 비율을 보존하며 파일 크기와 해상도를 줄이는 처리임.
- **크롭**은 비율을 보존하지만 출력 영역 밖의 일부를 보여 주지 않는 처리임.
- **왜곡**은 가로·세로를 서로 다른 배율로 늘여 원본 비율을 깨뜨리는 처리이며 사용하지 않음.

## 권고안

### 1차 최소안 — 단일 운영자 환경 권고

- 음원 썸네일의 필수 종횡비를 **1:1**로 정의함.
- 업로드 안내에는 JPEG/PNG, 1:1, 현행 10MB 이하를 명시함.
- **2048×2048px은 권장 규격**으로 안내함. 이 값은 일반적인 정사각형 상품 이미지 사례와 기존 이미지 정규화 서비스의 최대 출력 변 길이에 맞춘 권고이며, 별도 정책 결정 없이 필수 픽셀값으로 강제하지 않음.
- 파일 선택 직후 실제 음원 카드와 같은 정사각형 컨테이너, `object-fit: cover`, 기본 중앙 위치로 미리보기를 표시함.
- 1:1이 아닌 파일은 예상 잘림을 즉시 보여 주고, 제출을 막는 명확한 필드 오류를 제공함.
- 프론트엔드 검사는 빠른 안내용으로 사용하고, 백엔드가 디코딩된 실제 가로·세로 기준으로 1:1을 최종 검증함.
- 음원 생성과 수정에 같은 규칙을 적용함.

이 접근은 클라이언트 한 명이 운영하는 환경에서 작업 절차를 단순하게 유지하면서도 업로드 전에 결과를 예측할 수 있게 함. 현재 `cover` 표시를 `contain`으로 일괄 변경하면 잘림은 없어지지만 카드마다 여백이 생기고 기존 정렬이 달라지므로 1차안으로 권고하지 않음.

### 저장 리사이즈와 정규화

- 기존 이미지 정규화 서비스를 음원 썸네일 생성·수정에도 재사용하여 실제 JPEG/PNG 검증, 비율 보존 축소, 최대 변 제한을 일관되게 적용함.
- 작은 이미지는 확대하지 않고, 큰 이미지만 같은 배율로 축소함.
- 이 처리는 저장 안전성과 용량 최적화를 위한 것으로, 세로·가로 이미지를 자동으로 정사각형으로 만들거나 잘림을 해결하는 기능으로 설명하지 않음.
- 종횡비를 깨는 `fill`식 강제 늘림은 적용하지 않음.

### 후속 확장안

- 비정사각형 원본을 반복해서 받아야 하는 운영 요구가 확인되면 단순 1:1 크롭 위치 선택이나 초점 위치 저장을 추가 검토함.
- 자동 중앙 크롭은 피사체나 글자를 자를 수 있으므로 실제 결과 미리보기 없이 적용하지 않음.
- 원본 전체 노출이 핵심 요구로 바뀌면 `contain` 또는 서버 패딩을 별도의 디자인 결정으로 검토함.

## 기존 데이터 처리

- 현재 저장된 비정사각형 음원 썸네일은 새 업로드 규칙을 적용해도 자동으로 바뀌지 않음.
- 구현 전에 기존 파일을 1:1 이미지로 교체할지, 기존 파일에는 현재 `cover` 표시를 유지할지, 관리자 화면에 교체 필요 표시를 할지 결정함.
- 인수 테스트에 사용한 `track 1`도 정책 결정 전 임의로 수정하거나 덮어쓰지 않음.

## 현재 구현 상태 (2026-08-09)

- **상태**: WI-20260808-ATS-020에서 신규/교체 파일의 프론트·백엔드 계약과
  집중 테스트 완료. 실제 브라우저 시각 점검은 후속 QA 범위이므로 SR은
  `OPEN`을 유지함.
- `TrackThumbnailField.tsx`는 JPEG/PNG, 10MB, 1:1을 검사하고 2048x2048을
  권장하며 실제 카드와 같은 중앙 `cover` 미리보기를 제공함. 빠른 파일
  교체의 오래된 load/error 결과와 객체 URL lifecycle을 제어함.
- `CanonicalImageService.canonicalizeSquareTrackThumbnail(...)`이 백엔드 최종
  1:1 검사, 비율 유지 축소, no-upscale, JPEG 정규화를 담당함.
- Track Edit는 기존 이미지를 그대로 표시하고 비정사각형이면 경고만 함.
  새 파일을 고르지 않은 저장 요청에는 thumbnail을 넣지 않으므로 기존
  행/파일은 변경되지 않음. 자동 crop/일괄 교체는 수행하지 않음.
- 근거는 [WI-020 summary](../../deliverables/user/WI-20260808-ATS-020-summary.md)와
  [Evidence Pack](../../deliverables/agent/WI-20260808-ATS-020-evidence-pack.md)에 있음.

## 완료 조건

- [x] 파일 선택 직후 상세·목록 등 실제 사용 화면과 같은 정사각형 `cover` 미리보기가 표시됨.
- [x] 세로·가로 비정사각형 파일이 프론트엔드에서 안내되고 백엔드에서도 최종 거절됨.
- [x] 음원 생성과 수정이 같은 이미지 검증·정규화 계약을 사용함.

- [ ] 음원 상세, 목록, 하단 플레이어, 관리자 음원 목록의 표시가 업로드 미리보기와 일치함.
- [x] 기존 비정사각형 썸네일은 보존하고 명시적 교체 경고만 제공함.
