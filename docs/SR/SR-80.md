# SR-80 음원 목록 레이아웃 정리 (Buy 버튼 제거 + 태그 영역 폭 고정/확대)

> **우선 가치**: 음원 목록에서 Buy 버튼은 이미 존재하는 다운로드 버튼과 역할이 겹치므로 제거한다. 또한 제목 길이가 행마다 달라 태그 영역이 들쭉날쭉한 문제를 **퍼센트 기반 고정 폭** 으로 해결하고, 클라이언트 요청에 따라 태그 영역 폭을 **현재 대비 상대 +10%** 로 확대한다.

## 환경

- PC, 모바일 공통
- 영향 범위: 음원 목록이 노출되는 모든 화면 — 메인, 음원 목록, 앨범 상세, 좋아요 목록, 검색 결과, 다운로드 기록(SR-79), 재생목록 등 `TrackRow` 또는 동등 컴포넌트를 사용하는 모든 곳

## 수정 내용

### 1. Buy 버튼 제거

- 다운로드 버튼(아래 화살표 아이콘)이 있는 **모든 위치**에서 "Buy" 버튼 제거
- 사유: 다운로드 버튼이 이미 구매/획득 동작을 수행하므로 중복 UI
- 관련 클릭 핸들러, 모달 트리거, 상태 관리 로직 정리 (dead code 제거)

### 2. 태그 영역 폭을 % 기반 고정으로 전환

#### 현상

- 현재 곡 제목 영역이 가변이고 제목 길이에 따라 태그 영역이 축소/확장됨 → 행별로 태그 표시 개수가 들쭉날쭉
- CSS 폭 정의가 일관되지 않아 시각적 리듬이 깨짐

#### 조치

- `TrackRow` 및 동등 컴포넌트에서 **제목 / 태그 / 액션(다운로드 등) 컬럼 폭을 % 기반 고정**으로 선언
- 제목은 긴 경우 **말줄임(ellipsis)** 처리 — 폭 초과가 태그 영역을 침범하지 않도록
- **현재 태그 영역 폭 기준 상대 +10%** 확대 (예: 30% → 33%)
  - 정확한 현재 값은 구현 시점에 `TrackRow.module.css` 등에서 측정 후 기록
  - 확보된 폭은 제목 영역 축소로 충당

#### 반응형

- 모바일에서도 동일 원칙 적용 — 태그 가시성 확보를 우선
- 모바일의 기존 숨김/축약 정책이 있다면 유지하되, 폭 기반 일관성은 동일하게 확보

### 3. 영향 컴포넌트 점검 리스트 (구현 시 확인)

- `frontend/src/components/TrackRow*` (공용)
- 음원 목록 페이지들의 해당 컴포넌트 소비처
- 앨범 상세 내 트랙 리스트
- 좋아요 트랙 목록
- 다운로드 기록(SR-79 적용 후)
- 검색 결과 리스트

## 확인 사항

- 현재 태그 영역 폭 % 값 측정 → SR 구현 단계에서 before/after 수치 기록
- 제목 말줄임 적용 시 hover tooltip 제공 여부 검토 (사용성)

## 연관 SR

- SR-79: 다운로드 기록에서도 동일 태그 폭 정책 적용
- SR-81: 아티스트 숨김으로 확보된 추가 폭을 태그/제목에 분배 가능 — 구현 시 함께 고려
