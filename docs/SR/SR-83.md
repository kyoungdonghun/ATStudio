# SR-83 플레이어 Next 버튼을 음원 목록 컨텍스트 기반으로

> **우선 가치**: 작업 전, 현재 플레이어 Next 버튼이 playerStore의 queue에 의존한다는 것과 키보드 ↓ 이벤트는 TrackListPage 내부에서 로컬로 동작한다는 것을 파악한다.

## 환경

- PC, 모바일 공통
- 영향 범위: `playerStore`, `PlayerBar`, 트랙 목록이 있는 모든 페이지 (TrackListPage, AlbumDetailPage, PlaylistDetailPage, LikeListPage, DownloadQueuePage 등)

## 현상

- 현재 플레이어 Next 버튼은 `playerStore.next()` → 큐/shuffle/repeat 기반 다음 곡
- 사용자 기대: Next 버튼 = "지금 보고 있는 음원 목록의 다음 곡" (키보드 ↓ 방향키와 동일)
- 현재 키보드 ↓은 TrackListPage 내부 `tracksRef`를 참조 → 다른 페이지에선 작동 안 함

## 수정 내용

### 1. playerStore에 `trackListContext` 공유 상태 추가

```ts
trackListContext: TrackListItem[];
setTrackListContext: (tracks: TrackListItem[]) => void;
```

### 2. next()/prev() 메서드 재구성

- `trackListContext`가 있으면 그 목록 기준으로 현재 곡 index 찾아서 다음/이전 곡 재생
- `trackListContext`가 비어있으면 fallback: 기존 queue 로직 유지 (호환성 유지)

### 3. 각 트랙 목록 페이지에서 context 설정

트랙 리스트가 보이는 페이지들은 tracks가 로드될 때 `setTrackListContext(tracks)` 호출:
- TrackListPage (이미 로컬 로직 존재, 공유 상태로 이관)
- AlbumDetailPage
- PlaylistDetailPage
- LikeListPage
- DownloadQueuePage
- (기타 트랙 목록 표시 페이지)

페이지 이동 시 해당 페이지의 tracks로 context가 자연스럽게 교체됨.

### 4. 키보드 ↓/↑ 동작 일원화

- TrackListPage의 로컬 keyboard handler 제거 또는 공유 로직으로 변경
- 키보드 ↓/↑와 Next/Prev 버튼이 동일한 `trackListContext` 참조

## 확인 사항

- 빈 컨텍스트(트랙 목록 없는 페이지)에서 Next 버튼 동작 — fallback(기존 queue)으로 폴백 여부
- 페이지 전환 시 이전 페이지의 context가 유지되는지 vs 교체되는지 — 교체 권장
- 모바일 플레이어의 Next 버튼도 동일 적용
