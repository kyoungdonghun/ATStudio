# SR-101 재생 지연 안내와 집계 화면 waveform 전달 누락 개선

> **우선 가치**: 짧은 정상 버퍼링을 재생 장애처럼 경고하지 않고, 모든 재생 진입점이 실제 Track 길이와 분석된 waveform peak를 동일하게 전달해야 한다. 화면별로 `duration: 0`이나 `waveformData: null`을 임의 생성하지 않으며, 목록 건수만큼 상세 요청하는 방식도 피한다.

## 환경

- 하단 플레이어
- 앨범 상세 > 전체 재생·개별 재생
- 재생목록, 좋아요, 다운로드 기록, 재생기록과 대기열·이전곡·다음곡
- PC, 모바일 공통

## 인수 테스트에서 확인된 현상

- 음원 재생 시작 시 `재생이 지연되고 있습니다. 연결을 확인한 뒤 다시 시도해 주세요.` 문구가 표시됨.
- 공개 앨범 `/albums/2`에서 `전체 재생`을 누르면 문구가 즉시 나타났다가 약 1.8초 안에 정상 재생으로 전환됨.
- 같은 앨범의 전체 재생에서는 하단 플레이어에 실제 waveform이 나타나지 않고 평평한 선만 표시됨.

두 현상은 서로 다른 원인임. 첫 번째는 짧은 native media 대기 이벤트를 즉시 노출하는 UX 문제이고, 두 번째는 앨범 Track 계약에서 실제 waveform 데이터를 전달하지 않는 데이터 계약 문제임.

## 재생 지연 안내의 현재 조건

- 플레이어 상태는 `HTMLAudioElement`의 `waiting` 또는 `stalled` 이벤트가 발생하면 경과 시간 검사 없이 즉시 `isStalled=true`로 바꿈.
- `timeupdate`, `canplay`, `playing`, 정상적인 `play()` 완료, 일시정지, 재시도 초기화, 미디어 오류에서 상태를 해제함.
- 현재 문구는 일정 시간 이상 멈췄거나 재생에 실패했다는 판정이 아니라, 현재 Track에서 native `waiting`·`stalled`이 한 번 발생했다는 뜻임.
- `/albums/2`의 약 1.8초 재현은 정상 시작 과정의 짧은 버퍼링이 즉시 경고로 보인 사례이며 재생 실패로 판단하지 않음.

## 지연 안내 수정 내용

- `waiting`·`stalled` 발생 시 곧바로 문구를 표시하지 않고 `buffering-pending` 상태와 시작 시각을 기록함.
- 약 2초 지속을 초기 표시 기준으로 사용함. 이 값은 1.8초 재현을 정상 시작으로 흡수하기 위한 제안값이며, 느린 모바일·네트워크 검증 후 제품 상수로 확정함.
- `timeupdate`, `canplay`, `playing`, 일시정지, 재시도, Track 변경 또는 오류가 먼저 발생하면 대기 타이머를 취소함.
- 빠른 이전곡·다음곡 이동에서 이전 Track의 타이머가 새 Track에 문구를 표시하지 않도록 재생 시도별 generation 또는 token을 검증함.
- 기준을 넘긴 버퍼링은 재시도 가능한 비치명적 상태로 안내하고, `audio.error`나 `audio.play()` 거절은 별도의 실제 오류 상태로 표시함.
- 장시간 지속 기준과 안내 강도는 후속 설계에서 정하되, 일시적 버퍼링을 재생 실패로 기록하지 않음.

## 앨범 waveform 누락 원인

| 단계 | 현재 동작 | 결과 |
| --- | --- | --- |
| 앨범 API DTO | Track ID, 제목, 아티스트, 썸네일, 순서만 전달 | duration과 waveformData 없음 |
| 앨범 상세 매핑 | 목록 컨텍스트, 전체 재생, 개별 재생에서 `duration: 0`, `waveformData: null` Track을 직접 생성 | 플레이어에 peak 전달 불가 |
| 플레이어 | peak 배열이 없으면 단일 평평한 선을 fallback으로 그림 | 실제 파형처럼 보이지 않음 |
| 동일 Track 상세 API | Track 2의 `duration=229`, 실제 waveformData 존재 | 업로드 분석 실패가 아니라 전달 누락임 |

- 2026-08-08 공개 API에서 앨범 2의 Track 항목에는 duration과 waveformData가 없었음.
- 같은 Track 2의 상세 API에는 1,201-character waveform peak 문자열이 존재함.
- 따라서 평평한 선은 진폭이 낮은 실제 파형이 아니라 **보유한 peak 데이터를 앨범 경로에서 누락한 fallback**임.

## 다른 화면과 대기열 영향

| 진입점 | 축약 방식 | 영향 |
| --- | --- | --- |
| 앨범 상세 | duration 0, waveform null | 컨텍스트·전체 재생·개별 재생 모두 누락 |
| 재생목록 상세 | duration 0, waveform null | 컨텍스트·개별 재생·대기열 모두 누락 |
| 좋아요 목록 | duration 0, waveform null | 컨텍스트·개별 재생 누락 |
| 다운로드 기록 | API duration은 유지하지만 waveform을 null로 만듦 | 플레이어 파형 누락 |
| 플레이어 Drawer의 재생목록·좋아요 | duration 0, waveform 미전달 | Drawer에서 다시 재생해도 누락 |
| 로컬 재생기록 | ID·제목·썸네일만 저장 | 재생기록 재생과 재로딩 후 누락 |

- 전체 재생은 축약 Track 객체를 그대로 대기열에 저장하고, 이전곡·다음곡도 컨텍스트·대기열 객체를 상세 보강 없이 바로 재생함.
- 축약 객체가 플레이어 저장 상태에 남을 수 있으므로 화면 이동이나 새로고침 후에도 평평한 fallback이 지속될 수 있음.
- 공개 음원 목록·상세는 이미 duration과 waveform을 전달하는 정상 비교 경로임.

## 공통 재생 데이터 계약 개선

### 권고: 공통 `PlayableTrack` 계약

- 재생 가능한 집계 DTO와 프론트엔드 mapper에 최소 공통 계약을 둠.

```text
PlayableTrack = id + title + artistName + duration + thumbnail + waveformData
```

- 앨범·재생목록·좋아요처럼 결과 수가 제한되고 현재 repository가 Track을 함께 가져오는 경로는 이 projection을 응답에 포함하여 한 번에 완전한 대기열을 만듦.
- 다운로드 기록처럼 페이징과 연관 조회 위험이 있는 경로는 안전한 projection·batch 조회를 사용하고 쿼리 수를 검증함.
- 매우 큰 컬렉션에서 waveform payload가 부담되면 `trackIds` 기반 단일 batch hydration과 캐시를 대안으로 사용함.
- 행마다 `GET /api/tracks/{id}`를 호출하는 상세 요청 반복은 HTTP·DB N+1과 다음곡 지연을 만들므로 사용하지 않음.
- 모든 화면이 공통 mapper를 사용하고 임의의 `duration: 0`, `waveformData: null`을 만들지 않게 함.
- 기존 로컬 플레이어·재생기록의 축약 저장값은 상태 버전 마이그레이션 또는 재생 전 batch hydration으로 보강함.

## SR-90과의 경계

- [SR-90](SR-90.md)은 하단 플레이어를 실제 음원 분석 기반 waveform 디자인으로 전환하는 요구이며 현재 `OPEN`을 유지함.
- 이 SR은 장식용 파형을 새로 만들거나 SR-90을 대체하지 않음.
- 실제 peak가 존재하면 모든 재생 진입점이 그 데이터를 전달하고, 실제 peak가 정말 없을 때만 명시적인 평평한 fallback을 사용하는 교차 화면 계약을 다룸.

## 현재 구현 상태 (2026-08-09)

- **상태**: WI-20260808-ATS-018/019에서 버퍼링 상태와 PlayableTrack
  hydration/persistence를 구현하고 집중 자동화 검증 완료. 전체 브라우저
  인수와 큰 실제 payload 성능 측정은 후속 QA 범위이므로 SR은 `OPEN`을 유지함.
- `playerStore.ts`는 2초 threshold와 generation fence를 사용하고 recovery,
  pause, retry, Track 변경, error에서 pending timer를 취소함. `PlayerBar.tsx`는
  지속 버퍼링을 polite status, 실제 오류를 assertive alert로 분리함.
- `POST /api/tracks/batch`는 public, 최대 100 positive ID, active-only,
  최초 요청 ID 순 `dataList`를 반환함. Track과 Tag를 bounded query로 읽고
  행별 상세 HTTP 요청을 만들지 않음.
- album/playlist/likes/download DTO와 frontend mapper가 duration/waveform을
  포함한 공통 PlayableTrack을 사용함. `playerState` v2와 `playHistory`는 ID를
  저장하고 batch hydrate하며 snapshot/generation으로 stale 결과를 차단함.
- 집중 backend 80 tests 및 frontend player/persistence/race 테스트 근거는
  [WI-018 summary](../../deliverables/user/WI-20260808-ATS-018-summary.md),

- [x] 약 1.8초 안에 재생이 정상화되는 재현에서는 지연 문구가 노출되지 않음.
- [x] `timeupdate`, `canplay`, `playing`, 일시정지, 재시도, Track 변경, 오류가 pending 타이머를 취소함.

- [x] 일시적 버퍼링, 지속 버퍼링, 실제 재생 오류가 서로 다른 상태·문구로 처리됨.

- [x] 재생목록, 좋아요, 다운로드 기록, Drawer, 로컬 재생기록도 같은 공통 재생 계약을 사용함.

## 2026-08-09 Active Membership Repair

- `WI-20260809-ATS-010` aligns Playlist list counts, detail rows, and owner
  reorder with the same active Track membership set. Inactive membership rows
  are preserved after the reordered active rows and receive deterministic,
  duplicate-free orders.
- Public Album counts, detail rows, and `trackCount` ordering now use active
  Track memberships only. Existing all-membership administrative totals remain
  unchanged.

## 2026-08-09 Frontend Playback Contract Repair

- `WI-20260809-ATS-011` accepts omitted aggregate `thumbnail`, `thumbnailUrl`,
  and `waveformData` keys. The shared mapper still rejects non-positive or
  non-integer IDs and normalizes omitted or null nullable media fields to
  explicit `null`.
- Album, playlist, and like API-shaped inputs now have mapper, component, and
  persisted-player regressions for omitted nullable keys.
- `playerStore.play(track)` sets the selected Track duration in the same state
  transition as `currentTrack` and `currentTime = 0`. Browser `loadedmetadata`
  may replace that duration only for the current media source.
- PlayerBar coverage verifies that an immediate Track switch exposes no prior
  duration, progress, seek scale, or range ARIA values. Focused evidence is in
  the [WI-011 summary](../../deliverables/user/WI-20260809-ATS-011-summary.md)
  and
  [Evidence Pack](../../deliverables/agent/WI-20260809-ATS-011-evidence-pack.md).
