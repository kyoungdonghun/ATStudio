# SR-82 플레이어 대기열 → 재생기록 교체 + 플레이어바 인터랙션 개선

> **우선 가치**: 플레이어 내부 큐(셔플/반복) 로직은 유지하되, 사용자에게 보이는 "대기열" 패널 UI는 실질적 가치가 낮다. 이를 **재생기록** 패널로 교체하여 "방금/최근에 들은 곡으로 돌아가기" 사용성을 강화한다. 또한 플레이어바의 곡 상세 진입 동선을 제목과 썸네일 모두에서 가능하도록 확장한다.

## 환경

- PC, 모바일 공통
- 플레이어 관련 파일: `frontend/src/store/playerStore.ts`, 하단 플레이어바 컴포넌트, 플레이어 확장 패널 컴포넌트

## 수정 내용

### 1. 플레이어 패널: 대기열 → 재생기록 교체 (UI 한정)

#### 범위

- **UI 패널만 교체** — `playerStore` 내부의 큐/셔플/리피트(off/all/one) 로직은 **유지**
- 큐 기반 자동 다음곡 재생, 셔플, 반복 동작은 기존과 동일하게 작동해야 함
- 사용자에게 보이는 "대기열" 탭/패널/리스트 UI만 제거하고, 그 자리에 **재생기록 패널**을 배치

#### 재생기록 패널 동작

- 최근에 재생한 곡 목록을 최신 → 오래된 순으로 표시
- 각 항목 클릭 시 해당 곡 재생 (기존 재생 동선과 동일)
- 곡 제목/썸네일/태그 등 음원 목록과 일관된 정보 노출 (SR-80/SR-81 정책 준수 — 아티스트 제외)

### 2. 재생기록 저장 정책 (localStorage)

#### 저장 위치

- **localStorage** (기존 `playerState` 키와 별도로, 예: `playerHistory`)
- `utils/safeStorage.ts` 래퍼 사용 필수 (iOS Private 모드 대응 — 메모리 Lessons Learned)

#### 정책

- **보관 기간: 30일** — 30일 초과 항목은 로드 시점에 정리
- **최대 건수: 50건** — 초과 시 가장 오래된 항목부터 제거
- **중복 재생 시: 기존 항목의 타임스탬프 갱신** (새 항목 추가 아님) → 목록 내 곡 수는 유지되고 순서만 최상단으로 이동
- 저장 필드(최소): `trackId`, `title`, `thumbnailUrl`, `tags`, `lastPlayedAt`
- 사용자 로그아웃/계정 전환 시 동작 정책 검토 — 기존 `SR-33` 원칙(로그아웃 시 플레이어+전역 상태 초기화)과 정합성 맞춤

#### 현행 확인 필요

- 본 SR 구현 전, **현재 재생기록이 어떻게 저장되고 있는지** 코드 확인 필수
  - `playerStore`에 history 관련 상태가 이미 있는지
  - localStorage 키 현황
- 기존 자산 재활용 가능하면 재활용, 없으면 신규 구현

### 3. 플레이어바 곡 상세 진입 — 썸네일 클릭 추가

#### 현상

- 현재 플레이어바에서 **곡 제목을 클릭해야만** 트랙 상세 페이지로 이동
- 썸네일 이미지는 클릭해도 반응 없음

#### 조치

- **썸네일 클릭 시에도 트랙 상세로 이동** — 제목 클릭과 동일 동작
- 접근성: `role="button"`, `aria-label`, 키보드 포커스/Enter 처리 추가
- 모바일 터치 타겟 크기(최소 44x44px) 확보

## 확인 사항

- `playerStore` 내부 큐 로직에 의존하는 곳(드래그 앤 드롭 순서 변경 등, SR-11 참고)이 있다면, UI 제거 후에도 내부 로직 동작 보장
- 재생기록과 "좋아요", "최근 재생" 등 기존 기능 간 중복/충돌 점검
- localStorage 저장 용량 — 50건 × 평균 필드 크기 추정하여 안전 확인
