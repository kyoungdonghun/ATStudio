# SR-100 메인 태그 탐색을 Usage 우선 통합 탐색으로 개편
> **우선 가치**: 쇼츠용 음원을 찾는 구매자가 사용 장면을 먼저 선택할 수 있도록 `USAGE`를 우선하되, 장르·분위기·악기 네 종류의 Tag를 하나의 일관된 탐색 계약으로 제공한다. 등록된 Tag와 실제 활성 Track 검색 결과가 있는 Tag를 구분하여 결과 없는 진입점을 만들지 않는다.

## 환경

- 메인 화면 > 장르별 탐색·분위기별 탐색
- 공개 음원 목록의 Tag 필터
- PC, 모바일 공통

## 인수 테스트에서 확인된 현상

- 메인 화면에는 `장르별 탐색`과 `분위기별 탐색`만 있음.
- Tag 검색 기능의 범주인 `INSTRUMENT` 탐색이 없고, 쇼츠 활용 장면을 설명하는 `USAGE` 탐색도 없음.
- 기능 장애는 아니지만, 구매자의 목적 기반 탐색을 지원하는 정보 구조가 일부 Tag 유형에만 연결된 상태임.

## 현재 데이터와 기능 교차검증

2026-08-08 공개 API와 현재 코드를 확인한 결과임.

| Tag 유형 | 등록 수 | 활성 Track 연결·검색 상태 | 현재 메인 노출 | 공개 음원 목록 연결 |
| --- | ---: | --- | --- | --- |
| `GENRE` | 5 | 검색 가능 | 있음 | 있음 |
| `MOOD` | 4 | 검색 가능 | 있음 | 있음 |
| `INSTRUMENT` | 4 | `instrument03`이 Track 2·3에 연결되고 백엔드 검색이 2건을 반환함 | 없음 | 백엔드는 지원하지만 화면이 URL·필터 상태를 읽지 않음 |
| `USAGE` | 1 | `#비가오면`이 등록되어 있으나 활성 Track 연결은 0건 | 없음 | URL·API·선택 상태는 지원함 |

- `USAGE` 데이터 자체가 없는 것은 아니며, 현재 활성 Track과 연결된 Usage Guide Tag가 없는 상태임.
- `INSTRUMENT`는 실제 결과와 백엔드 지원이 있지만 공개 음원 목록 페이지가 `instrument` 조건을 읽고 보존하지 않음.
- 따라서 메인에 악기 링크만 먼저 추가하면 `/tracks?instrument=...` 이동 후 조건이 유실되는 교차 레이어 결함이 생김.

## 정보 구조 제안

### 권고안: Usage 우선 단일 `태그별 탐색` 모듈

- 장르·분위기·악기를 별도 세로 섹션으로 계속 추가하지 않고 하나의 `태그별 탐색` 모듈로 통합함.
- 범주 순서는 `용도(USAGE) -> 장르(GENRE) -> 분위기(MOOD) -> 악기(INSTRUMENT)`로 둠.
- `USAGE`는 License가 아니라 Track의 예상 콘텐츠 활용 장면을 설명하는 **Usage Guide Tag**로 표시함.
- 탭 또는 동등한 범주 선택 UI를 사용하여 홈 높이를 고정하고 모바일 세로 과밀화를 줄임.
- 좁은 화면에서는 범주 선택을 가로 스크롤 가능한 한 줄로 제공하고, Tag 칩은 초기 노출 수를 제한한 뒤 `더보기`를 제공함.

### Usage 연결 0건의 처리

- Usage를 우선 범주로 유지하되, 현재처럼 등록 Tag는 있으나 활성 Track 연결이 0건이면 정상 검색 진입점처럼 표시하지 않음.
- `사용 가능한 용도 태그가 아직 없습니다`와 같은 명시적 빈 상태를 제공하거나, 첫 결과 보유 범주를 처음 표시하면서 Usage 탭은 그대로 노출함.
- 최종 기본 탭 규칙은 후속 디자인에서 확정하되, 결과가 없다는 이유로 Usage 범주 자체를 조용히 숨기지 않음.
- 홈의 Tag 소스는 `/api/tags/available` 또는 동등한 결과 보유 계약을 우선 사용하여 dead-end 링크를 줄임.

### 네 유형의 검색 계약 통일

- Tag 클릭 시 각각 `/tracks?usage=...`, `/tracks?genre=...`, `/tracks?mood=...`, `/tracks?instrument=...`로 이동함.
- 공개 음원 목록은 네 유형 모두에 대해 URL 복원, API 전달, 선택 칩, 필터 모달, 페이지·정렬 유지, 전체 초기화를 동일하게 지원함.
- `INSTRUMENT`를 공개 음원 목록과 가용 Tag API의 요청·상태 계약에 추가함.
- 공백, 쉼표, `#`, 한글 등 URL 인코딩이 필요한 Tag 이름도 선택과 복원 과정에서 원문을 유지함.
- 여러 Tag 선택은 값마다 반복 파라미터를 사용하고 CSV로 합치지 않으며,
  백엔드는 같은 유형 내부와 유형 사이를 모두 AND로 결합함.

## 대안 비교

| 방식 | 장점 | 문제 | 판단 |
| --- | --- | --- | --- |
| 네 개 독립 섹션 | 기존 장르·분위기 UI를 단순 반복 가능 | 홈이 길어지고 모바일 과밀화·빈 섹션 위험 증가 | 비권고 |
| 유형별 단일 통합 탭 | 네 의미를 유지하고 Usage 우선순위와 빈 상태를 표현하며 높이를 제한 | 접근 가능한 탭·필터 정합성 구현 필요 | 권고 |
| 유형 없는 혼합 Tag 모음 | 가장 작은 화면 공간 | 장르·용도·악기 의미가 섞여 검색 결과 예측이 어려움 | 비권고 |

## SR-04와의 경계

- [SR-04](SR-04.md)는 장르 섹션만 있던 시점에 동일 구조의 분위기 탐색을 추가한 완료 기록이며 `DONE`을 유지함.
- 이 SR은 SR-04를 재개하거나 실패로 판정하지 않음.
- 이미 제공된 장르·분위기를 유지하면서 네 Tag 유형을 하나의 정보 구조로 재편하고, Usage 우선순위, Instrument 검색 연결, 빈 상태, 모바일 밀도를 새 범위로 다룸.

## 현재 구현 상태 (2026-08-09)

- **상태**: WI-20260808-ATS-021에서 Home, TrackList, API, available query와
  집중 자동화 검증 완료. 실제 모바일/키보드/스크린리더 브라우저 인수는
  후속 QA 범위이므로 SR은 `OPEN`을 유지함.
- Home은 Usage, Genre, Mood, Instrument 순 단일 tablist이며 범주당 8개와
  더보기/접기를 제공함. Usage 결과가 없으면 첫 결과 보유 범주를 최초
  선택하지만 Usage 탭은 숨기지 않음.
- 등록 Tag와 active-Track 결과 Tag를 분리하고, Tag 없음/결과 없음/API
  실패/정상 결과를 구분함. API 실패는 모듈에 retry를 표시하고 Home
  나머지를 유지함.
- TrackList와 backend는 네 범주의 반복 query parameter를 사용하고 모든
  선택을 AND로 결합함. available 실패 시 전체 등록 선택지를 표시하며
  stale availability를 적용하지 않음. paginated Track 응답은
  `dataList/pageInfo`임.
- Usage Guide Tag는 License가 아니며 `#`는 표시 접두사임. 근거는
  [WI-021 summary](../../deliverables/user/WI-20260808-ATS-021-summary.md)와
  [Evidence Pack](../../deliverables/agent/WI-20260808-ATS-021-evidence-pack.md)에 있음.

## 완료 조건

- [x] 메인에 하나의 `태그별 탐색` 모듈이 있고 범주가 Usage, Genre, Mood, Instrument 순으로 제공됨.
- [x] 활성 Track에 연결된 Usage Guide Tag가 있을 때 Usage가 우선 탐색으로 정상 동작함.
- [x] 현재처럼 Usage 등록은 있지만 활성 Track 연결이 0건인 경우 결과 보유 범주 fallback이 표시되고 Usage 탭은 유지됨.
- [x] Instrument와 Usage 모두 홈 이동부터 음원 목록 URL 복원, API 전달, 선택 칩, 필터 적용·초기화까지 연결됨.
- [x] `/api/tags/available`이 네 Tag 유형과 교차 필터를 일관되게 처리함.
- [x] 공백·쉼표·`#`·한글 Tag 이름이 정확히 인코딩되고 선택 상태로 복원됨.
- [x] 여러 Tag 선택의 AND 검색 의미가 유지됨.
- [x] 키보드·스크린리더 범주 전환, 포커스, 모바일 가로 스크롤과 `더보기` 계약이 자동화 검증됨.
- [x] Tag 없음, 등록됐지만 결과 없음, API 실패, 정상 결과 상태가 서로 구분되어 테스트됨.
- [x] SR-04는 `DONE` 기록으로 유지되고 Usage Tag를 License로 표현하지 않음.

## 후속 설계에서 결정할 사항

- [x] 결과 보유 Usage Tag가 0건이면 첫 결과 보유 범주로 전환하고 Usage 탭은 유지함.
- [x] 홈은 범주당 8개를 먼저 보여 주고 `더보기`/`접기`를 제공함.
- [x] 가용 Tag API는 네 유형의 반복 파라미터와 `dataList` 응답을 사용함.

## 2026-08-09 Pagination Repair

- `WI-20260809-ATS-010` bounds public Track search to `page >= 1` and
  `1 <= size <= 100` at the service boundary.
- Invalid pagination returns 400 `INVALID_ARGUMENT` before Track repository
  access. Valid responses preserve the documented 1-based `pageInfo` contract.

## 2026-08-09 Frontend Taxonomy Failure Repair

- `WI-20260809-ATS-011` loads Genre, Mood, Instrument, and Usage independently.
  One failed taxonomy request exposes a retry action only for that taxonomy and
  does not hide successful taxonomy options.
- Active repeated URL values are merged into each visible selected-chip model
  even when a taxonomy request fails or omits the selected value. These fallback
  chips remain removable and use stable, type-scoped keys.
- URL and Track API parameters keep raw Tag values. Usage receives the `#`
  prefix only in rendered labels. Reset and individual removal update both the
  URL and subsequent Track API arrays.
- Focused evidence is recorded in the
  [WI-011 summary](../../deliverables/user/WI-20260809-ATS-011-summary.md) and
  [Evidence Pack](../../deliverables/agent/WI-20260809-ATS-011-evidence-pack.md).
