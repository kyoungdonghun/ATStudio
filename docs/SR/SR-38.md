# SR-38 권한·인증 알림 시스템 전수조사 및 구축

> **SR 작성 원칙**: 본 문서는 "무엇을 해야 하는가" 중심으로 작성되었다. 기술 구현 세부사항은 단정하지 않으며, 클로드 코드가 실제 코드를 확인한 후 결정하도록 여지를 남긴다. 단, 클로드 코드는 문서를 참고하되, 검토를 통해 더 나은 방향 혹은 제안하는 방향이 있다면 적극적으로 제안한다.

## 배경

현재 ATStudio 프론트엔드의 라우트 가드(ProtectedRoute, SubscriberRoute)는 권한이 부족한 사용자를 **무통보 리다이렉트**로 처리한다. 로그인이 필요하면 `/login`으로, 구독이 필요하면 `/subscriptions`로 조용히 이동시키되, 사용자에게 **왜 이동되었는지 알려주지 않는다**.

이로 인해 사용자는 "내가 왜 갑자기 로그인 화면에 와 있지?"라는 혼란을 겪게 되며, 특히 SubscriberRoute는 구독 상태 확인 중 **빈 화면(blank)**을 보여준 뒤 리다이렉트하므로 UX가 불명확하다.

## 목적

사전 조건(로그인, 구독, 권한 등)이 필요한 **모든 액션과 화면 진입 시점**에서 사용자에게 명시적 피드백(토스트, 배너, 인라인 알림 등)을 제공하는 알림 시스템을 설계하고 구축한다.

## 범위

### Phase 1 — 전수조사

현재 프론트엔드 코드와 문서를 기반으로, 사전 조건이 필요한 모든 지점을 식별한다.

#### 1-A. 라우트 가드 레벨 (화면 진입 차단)

현재 라우트 가드별 대상 화면과 리다이렉트 동작:

| 가드 | 대상 라우트 | 현재 동작 | 알림 여부 |
|------|-----------|----------|----------|
| ProtectedRoute (USER) | `/profile`, `/likes`, `/play-history`, `/licenses*`, `/subscriptions/payment`, `/subscriptions/manage`, `/company-certification/*`, `/questions*`, `/complete-profile` | 미인증 → `/login`, 권한 부족 → `/` | ❌ 없음 |
| SubscriberRoute | `/playlists*`, `/download-queue`, `/whitelist-channels` | 미인증 → `/login`, 구독 비활성 → `/subscriptions` | ❌ 없음 |
| ProtectedRoute (ADMIN) | `/admin/*` 전체 (14개 라우트) | 미인증 → `/login`, 비관리자 → `/` | ❌ 없음 |

#### 1-B. 액션 레벨 (화면 내 특정 동작 차단)

공개 화면에서도 특정 기능은 인증/구독이 필요한 경우:

| 화면 | 액션 | 사전 조건 | 현재 처리 방식 | 알림 필요 |
|------|------|----------|--------------|---------|
| 트랙 목록/상세 (공개) | 좋아요 | 로그인 | 미확인 (조사 필요) | ✅ |
| 트랙 상세 (공개) | 재생목록에 추가 | 구독 | 미확인 (조사 필요) | ✅ |
| 트랙 상세 (공개) | 다운로드 큐에 추가 | 구독 | 미확인 (조사 필요) | ✅ |
| 앨범 상세 (공개) | 앨범 좋아요 | 로그인 | 미확인 (조사 필요) | ✅ |
| 구독 플랜 (공개) | 구독 결제 진행 | 로그인 | 미확인 (조사 필요) | ✅ |
| GNB | 장바구니/내정보 등 | 로그인 | GNB 분기로 메뉴 자체가 안 보임 | — (별도 처리 불필요) |

> **조사 항목**: 위 "미확인" 항목들은 실제 코드에서 어떻게 처리되는지 확인해야 함. 현재 API 401/403 응답을 Axios 인터셉터가 잡아서 리다이렉트하는 방식일 가능성 있음.

#### 1-C. API 인터셉터 레벨

현재 `api/client.ts`의 응답 인터셉터:

| 상황 | 현재 동작 | 알림 여부 |
|------|----------|----------|
| 401 (토큰 만료) | 자동 토큰 갱신 시도 → 성공 시 원래 요청 재시도 | ❌ (무통보, 정상) |
| 401 (갱신 실패) | 토큰 삭제, `/login` 리다이렉트 | ❌ 없음 |
| 403 (권한 부족) | 미확인 (조사 필요) | ❌ 없음 |
| 409 (리소스 충돌) | 일부 화면에서 토스트 표시 | ⚠️ 부분적 |

### Phase 2 — 알림 시스템 설계

전수조사 결과를 바탕으로, 알림 유형별 표준 패턴을 설계한다.

#### 2-A. 현재 토스트 시스템 현황

- 위치: `store/toastStore.ts`, `components/ui/ToastContainer.tsx`
- 지원 타입: `success`, `error` (2종만)
- 자동 소멸: 3초 고정
- 액션 버튼: 없음

#### 2-B. 필요한 확장

1. **토스트 타입 추가**: `warning`, `info` 타입이 필요함. 권한 부족은 error보다 warning이 적절.
2. **리다이렉트 전 알림**: 라우트 가드가 리다이렉트 하기 전에 토스트를 표시하고, 리다이렉트된 화면에서도 해당 토스트가 유지되어야 함 (리다이렉트 시 토스트 state가 소실되지 않도록).
3. **메시지 표준화**: 상황별 메시지 템플릿 정의.

#### 2-C. 알림 시나리오 매트릭스 (설계 시 기준)

| 시나리오 | 알림 타입 | 메시지 예시 | 동작 |
|---------|----------|-----------|------|
| 비로그인 → 로그인 필요 화면 접근 | warning 토스트 | "로그인이 필요한 기능입니다." | 토스트 표시 → `/login` 리다이렉트 |
| 비구독자 → 구독 필요 화면 접근 | warning 토스트 | "구독이 필요한 기능입니다." | 토스트 표시 → `/subscriptions` 리다이렉트 |
| 권한 부족 (일반 → 관리자 영역) | warning 토스트 | "접근 권한이 없습니다." | 토스트 표시 → `/` 리다이렉트 |
| 공개 화면에서 좋아요 클릭 (비로그인) | warning 토스트 | "로그인 후 이용 가능합니다." | 토스트 표시 → `/login` 리다이렉트 |
| 공개 화면에서 재생목록 추가 (비구독) | warning 토스트 | "구독 후 이용 가능합니다." | 토스트 표시 → `/subscriptions` 리다이렉트 |
| 세션 만료 (토큰 갱신 실패) | error 토스트 | "세션이 만료되었습니다. 다시 로그인해주세요." | 토스트 표시 → `/login` 리다이렉트 |
| API 403 응답 | warning 토스트 | "해당 기능에 대한 권한이 없습니다." | 토스트 표시, 화면 유지 또는 리다이렉트 |
| 다운로드 한도 초과 (409) | info 토스트 | "다운로드 한도 초과. {nextResetAt} 초기화" | 토스트 표시, 화면 유지 |

### Phase 3 — 구현 및 적용

#### 3-A. 토스트 시스템 확장

- `toastStore.ts`에 `warning`, `info` 타입 추가
- `ToastContainer.tsx`에 타입별 스타일 추가
- 리다이렉트 간 토스트 유지 메커니즘 (토스트 state가 navigate 후에도 살아있도록)

#### 3-B. 라우트 가드 수정

- `ProtectedRoute.tsx`: 리다이렉트 전 토스트 호출 추가
- `SubscriberRoute.tsx`: 리다이렉트 전 토스트 호출 추가, 로딩 중 빈 화면 대신 로딩 표시

#### 3-C. API 인터셉터 수정

- `api/client.ts`: 토큰 갱신 실패 시 토스트 표시 후 리다이렉트
- 403 응답에 대한 표준 토스트 처리 추가

#### 3-D. 공개 화면 내 액션 가드

- 좋아요, 재생목록 추가, 다운로드 큐 추가 등 개별 액션 호출부에서 사전 조건 체크 및 토스트 표시
