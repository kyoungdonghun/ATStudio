# SR-34

## 대상 화면

- 앨범 페이지 (카드 뷰 / 리스트 뷰 / 상세 페이지)
- 개인 페이지 > D-1 좋아요 목록

---

## 개요

현재 좋아요 기능(`/api/likes`)은 트랙 단위에만 존재하며(`likes` 테이블: `user_id` + `track_id` 복합 PK), 앨범 단위의 좋아요 기능은 제공되지 않는 상태임.

앨범 좋아요 기능 추가를 위해 다음 영역에 걸친 전방위 작업이 필요하다.

- DB 스키마 신규 테이블 추가
- 백엔드 API 신규 개발 (Section 10 Likes 확장)
- 프론트엔드 UI 적용 (앨범 카드/리스트/상세)
- 기존 D-1 좋아요 목록 화면 구조 개편 (트랙 뷰 / 앨범 뷰 탭 분리)

> 해당 작업은 DB 설계 → API 설계 → UI 구현 → 기존 화면 개편까지 포함하는 전체 피처 개발 작업으로 진행한다.

---

## 수정 내용

### 1. DB 스키마 — 앨범 좋아요 테이블 신규 추가

#### 1-1. 현재 구조

`db-schema.md` 기준 현재 `likes` 테이블 구조는 다음과 같음.

| Column | Type | Constraints |
|--------|------|-------------|
| `user_id` | BIGINT | PK, FK(users.id) |
| `track_id` | BIGINT | PK, FK(tracks.id) |
| `created_at` | DATETIME | NOT NULL, DEFAULT CURRENT_TIMESTAMP |

- Composite PK: (`user_id`, `track_id`)
- 트랙 전용 구조로, 앨범 좋아요를 저장할 수 없음

#### 1-2. 앨범 좋아요 전용 테이블 신규 생성 (방향 A 권장)

기존 `likes` 테이블과의 마이그레이션 영향 최소화를 위해 **앨범 전용 테이블을 별도로 생성**하는 방향을 권장한다.

```sql
CREATE TABLE album_likes (
  user_id    BIGINT   NOT NULL,
  album_id   BIGINT   NOT NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (user_id, album_id),
  FOREIGN KEY (user_id)  REFERENCES users(id)  ON DELETE CASCADE,
  FOREIGN KEY (album_id) REFERENCES albums(id) ON DELETE CASCADE
);
```

- Composite PK: (`user_id`, `album_id`) — 중복 좋아요 방지
- `albums` 삭제 시 연관 `album_likes` CASCADE 삭제
- `users` 탈퇴 시 연관 `album_likes` CASCADE 삭제 (기존 `likes` 정책과 동일하게 적용)

> `db-schema.md` 테이블 목록에 `album_likes` (Mapping 타입) 항목을 추가한다.

### 2. 백엔드 API 신규 개발

기존 `api-spec.md` **Section 10 Likes** 구조를 참고하여 앨범 좋아요 API를 동일한 패턴으로 설계한다.

#### 2-1. 앨범 좋아요 등록

| Field | Value |
|-------|-------|
| **URL** | `POST /api/likes/albums/{albumId}` |
| **Auth** | auth required |

**Response** `201 Created`

**Error Cases**
```json
{ "status": 409, "error": "Conflict", "errorCode": "ALBUM_ALREADY_IN_LIKES", "message": "이미 좋아요한 앨범입니다." }
```

#### 2-2. 앨범 좋아요 취소

| Field | Value |
|-------|-------|
| **URL** | `DELETE /api/likes/albums/{albumId}` |
| **Auth** | auth required |

**Response** `204 No Content`

**Error Cases**
```json
{ "status": 404, "error": "Not Found", "errorCode": "ALBUM_NOT_IN_LIKES", "message": "좋아요 목록에 없는 앨범입니다." }
```

#### 2-3. 좋아요한 앨범 목록 조회

| Field | Value |
|-------|-------|
| **URL** | `GET /api/likes/albums` |
| **Auth** | auth required |

**Response** `200 OK`
```json
{
  "dataList": [
    {
      "albumId": 1,
      "title": "Summer Collection",
      "thumbnailUrl": "/albums/thumbnail/summer.jpg",
      "trackCount": 8,
      "createdAt": "2026-03-01T10:00:00"
    }
  ]
}
```

> 기존 `GET /api/likes` 응답 구조(`dataList` 배열)와 동일한 패턴을 따른다.

#### 2-4. 앨범 목록/상세 응답에 좋아요 정보 추가

- `GET /api/albums` (15.2) 및 `GET /api/albums/{id}` (15.3) 응답에 다음 필드를 추가한다.
  - `likeCount`: 해당 앨범의 전체 좋아요 수
  - `isLiked`: 현재 로그인한 사용자의 좋아요 여부 (비로그인 시 `false`)

### 3. 프론트엔드 UI 적용

#### 3-1. 앨범 카드 뷰

- 앨범 카드에 좋아요 버튼(하트 아이콘)을 추가한다.
- 기존 음원 목록(`[3 음원 목록]`)의 좋아요 버튼 위치 및 스타일을 참고하여 일관된 UI로 구성한다.
- 좋아요 상태(활성/비활성)에 따라 아이콘 색상이 전환되도록 구현한다.

#### 3-2. 앨범 리스트 뷰

- 테이블 내 액션 영역에 좋아요 버튼을 통합한다.
- 카드 뷰와 동일한 좋아요 상태 전환 동작을 적용한다.

#### 3-3. 앨범 상세 페이지

- 앨범 타이틀 또는 정보 영역 근처에 좋아요 버튼 및 `likeCount`를 표시한다.

#### 3-4. 공통 처리

- 비로그인 상태에서 좋아요 버튼 클릭 시 `[A-1 로그인]`으로 리다이렉트 처리한다. (`screen-flow.md` 로그인 필요 화면 접근 패턴과 동일)
- API 호출 성공/실패 시 기존 `ToastContext`를 통해 토스트 메시지를 표시한다.
- 좋아요 등록/취소는 기존 음원 좋아요와 동일한 인터랙션 패턴(토글, 화면 유지)을 유지한다.

### 4. D-1 좋아요 목록 화면 구조 개편

#### 4-1. 현재 구조

`atstudio-front-list.md` 기준 현재 D-1 화면은 다음과 같이 정의됨.

| No | 화면명 | 관련 API | 인증 |
|----|--------|---------|------|
| D-1 | 좋아요 목록 | `10.1~10.3 /api/likes` | auth required |

- 현재 트랙 좋아요 목록만 표시하는 단일 뷰 구조

#### 4-2. 탭 분리 구조로 개편

D-1 화면을 다음 두 가지 탭으로 분리한다.

| 탭 | 표시 내용 | 연결 API |
|----|----------|---------|
| 음원 | 좋아요한 트랙 목록 | `GET /api/likes` (기존 10.2) |
| 앨범 | 좋아요한 앨범 목록 | `GET /api/likes/albums` (신규) |

- 기본 진입 탭은 **음원 탭**으로 설정하여 기존 사용자 경험을 유지한다.
- 각 탭은 독립적인 데이터 로딩 및 빈 상태(Empty State)를 가진다.
  - 음원 탭 빈 상태: `screen-flow.md`의 "좋아요 0개" 기준 빈 상태 메시지 적용
  - 앨범 탭 빈 상태: "좋아요한 앨범이 없습니다." 메시지 표시

#### 4-3. 모달 추가 (M-29 신규)

기존 `modal-list.md`에 앨범 좋아요 취소 확인 모달을 추가한다.

| ID | 발생 화면 | 트리거 | 내용 | 컴포넌트 | API |
|----|---------|--------|------|----------|-----|
| M-29 | D-1 (좋아요 목록 > 앨범 탭) | "좋아요 취소" 클릭 | "좋아요를 취소하시겠습니까?" | ConfirmModal | `DELETE /api/likes/albums/{albumId}` |

> 기존 M-23(트랙 좋아요 취소 확인 모달) 패턴과 동일하게 구성한다.
