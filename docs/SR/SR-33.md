# SR-33

## 대상 화면

하단 음원 재생바 (큐바 플레이어) > 세션 전환 시 상태 초기화

---

## 수정 내용

큐바 플레이어가 활성화된 상태에서 로그아웃을 수행해도 재생바가 그대로 유지되는 문제가 있음.
또한 해당 상태에서 다른 계정으로 로그인해도 이전 계정의 재생 상태(재생 중인 음원, 대기열, 재생 위치 등)가 그대로 노출되는 문제가 발생함.

이는 단순 UI 잔존 문제가 아닌 **세션 전환 시점에 클라이언트 상태가 초기화되지 않는 구조적 문제**로, 계정 분리 관점에서도 반드시 수정이 필요하다.

---

### 배경: 현재 로그아웃 구조

`screen-flow.md` 기준으로 현재 로그아웃 처리는 다음과 같이 정의되어 있음.

> [로그아웃] 클라이언트 측 토큰 삭제 (서버 무효화 엔드포인트 없음 — 초기 버전) → [1 메인] (비로그인 상태)

즉 로그아웃은 **클라이언트 토큰 삭제 후 메인 이동**으로만 처리되며, 큐바 플레이어를 포함한 전역 상태의 초기화 흐름이 연결되어 있지 않은 상태임.

---

### 확인 및 수정 범위

#### 1. 로그아웃 시점 처리

`frontend-standards.md` 기준으로 인증 상태는 `AuthContext`의 `logout()` 함수로 관리됨.

```tsx
interface AuthContextValue {
    logout: () => void;
    // ...
}
```

- `logout()` 호출 시 AccessToken(메모리) 및 RefreshToken(httpOnly cookie) 삭제와 함께 큐바 플레이어 상태를 즉시 초기화하도록 처리한다.
- 초기화 대상은 다음을 포함한다.
  - 현재 재생 중인 음원 정보
  - 재생 대기열 (Queue)
  - 재생 위치 (Progress)
  - 재생/일시정지 상태

#### 2. 로그인 전환 시점 처리

- 로그아웃 후 다른 계정으로 로그인 시 이전 계정의 큐바 상태가 이어지지 않도록 한다.
- `login()` 시점에 큐바 상태를 새 계정 기준으로 초기화 또는 해당 계정의 저장된 상태로 재구성한다.

#### 3. 클라이언트 전역 상태 초기화 구조 점검

- 큐바 플레이어 상태가 전역 Context 또는 별도 Store로 관리되고 있는 경우, `AuthContext`의 `logout()` 실행 시 해당 상태가 함께 초기화되는 흐름이 연결되어 있는지 확인한다.
- `logout()` → 큐바 상태 초기화 → UI 반영의 흐름이 일관되게 동작하도록 수정한다.

#### 4. 관련 시점 문제 전수 점검

큐바 플레이어 외에도 세션 전환 시점에 상태가 잔존할 수 있는 영역을 함께 점검한다.

점검 대상 예시는 다음과 같다.

- 좋아요(`/api/likes`) 상태 — 트랙 목록에서 하트 활성 여부
- 재생 목록 캐시 — TanStack Query 캐시로 관리되는 경우 계정 전환 시 무효화 여부
- 다운로드 큐(`/api/download-queue`) 상태
- 구독 여부 기반 UI 렌더링 조건 (GNB 메뉴, 버튼 노출 등)
- `GET /api/utils/subscription-status`, `GET /api/utils/download-count` 등 utils API 캐시

세션이 변경되었음에도 이전 상태가 화면에 남아있는 케이스를 모두 확인하고 일관된 초기화 정책을 적용한다.

---

### 처리 방향 정의

로그아웃 및 계정 전환은 **클라이언트 상태 전체의 리셋 기준점**으로 정의한다.
`AuthContext.logout()` 실행 시 사용자 종속적인 모든 상태(큐바, 캐시, UI 조건 등)는 초기화되어야 하며, 새 세션 기준으로만 상태가 구성되어야 한다.

> 해당 작업은 단순 버그 수정이 아닌 세션 생명주기(Session Lifecycle) 기반의 클라이언트 상태 초기화 구조 개선 작업으로 진행한다.
> `AuthContext`, 큐바 플레이어 상태 관리, TanStack Query 캐시 무효화 전략을 함께 점검한다.
