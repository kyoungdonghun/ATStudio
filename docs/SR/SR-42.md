# SR-42 외부 테스트 환경 구축 (ngrok 기반 로컬 서버 공개)

## 2026-07-16 Current Safety Addendum

This historical SR described an ngrok-based local sharing option. The current supported topology is still one frontend origin on port 5173 with Vite proxying `/api` and `/uploads` to the backend on port 8080; the tunnel vendor is an operational choice, not a product contract.

Do not expose a Vite development server publicly unless the operator confirms a compatible patched dependency state or uses an access-controlled alternative. The active development branch resolves Vite 6.4.3 and both production-only and unfiltered npm audits report 0. The frozen `codex/client-demo-stable` branch was inspected read-only and remains at Vite 6.4.1 with 5 production and 13 total audit findings. It was not modified and is not an approved public dev-server target without user authorization.

Before sharing any URL, verify local frontend/backend health, verify the public origin and `/api/tracks`, use test accounts/data only, restrict the audience, and stop the tunnel when the session ends. A generated public URL is not evidence of release readiness.

## 목적

로컬 개발 환경에서 실행 중인 ATStudio(백엔드 + 프론트엔드)를 외부 클라이언트가 인터넷을 통해 접속할 수 있도록 공개하여, 즉각적인 피드백 수집이 가능한 테스트 환경을 구축한다.

## 중요가치

클라이언트가 실제로 만져보면서 피드백을 줄 수 있어야 한다. 별도 클라우드 배포 없이, 로컬 개발 환경을 최소 비용으로 외부에 노출하는 것이 핵심이다.

## 선택 도구: ngrok

| 항목 | 내용 |
|------|------|
| 도구 | ngrok (무료 플랜) |
| 이유 | 설치 1분, 설정 최소, HTTPS 자동, 별도 인프라 불필요 |
| 제한 | 무료: URL 재시작 시 변경, 동시 터널 1개 |
| 대안 | Cloudflare Tunnel (무료, 영구 URL 가능), localtunnel, Tailscale |

## 아키텍처

```
클라이언트 (외부)
    ↓ HTTPS
ngrok 터널 (1개)
    ↓
localhost:5173 (Vite 개발서버)
    ├── 정적 파일 (React SPA)
    ├── /api/* → 프록시 → localhost:8080 (Spring Boot)
    └── /uploads/* → 프록시 → localhost:8080
```

**핵심: 터널 1개로 충분.** Vite가 이미 `/api`와 `/uploads`를 백엔드로 프록시하고 있으므로, 프론트 포트만 ngrok으로 열면 백엔드까지 자동 연결된다. CORS 설정 변경이나 프론트 환경변수 수정이 불필요하다.

## 작업 절차

### Phase 1 — ngrok 설치 및 계정 설정

1. [ngrok 공식 사이트](https://ngrok.com)에서 회원가입 후 authtoken 발급
2. ngrok 설치 (Windows: `choco install ngrok` 또는 공식 ZIP 다운로드)
3. authtoken 등록: `ngrok config add-authtoken <YOUR_TOKEN>`

### Phase 2 — 로컬 서버 실행

1. 백엔드 실행: IntelliJ에서 Spring Boot 실행 (포트 8080)
2. 프론트 실행: `cd frontend && npm run dev -- --host` (포트 5173)
   - `--host` 옵션으로 외부 접근 허용

### Phase 3 — ngrok 터널 오픈

```bash
ngrok http 5173
```

발급된 HTTPS URL 확인 (예: `https://abcd-1234.ngrok-free.app`)

이것만으로 프론트엔드 + 백엔드 API + 파일 업로드/다운로드 모두 접근 가능.

### Phase 4 — 클라이언트에게 공유 및 테스트

1. 클라이언트에게 ngrok URL 공유
2. 접속 시 ngrok 무료 플랜 경고 페이지 → "Visit Site" 클릭 안내
3. 주요 플로우 확인: 회원가입, 로그인, 음원 검색/재생, 앨범, 구독 등

## 주의사항

- **터미널 유지**: ngrok 프로세스 종료 시 URL이 무효화됨 — 테스트 세션 동안 터미널 유지
- **URL 변경**: 무료 플랜은 재시작마다 URL 변경 — 고정 URL은 유료($8/월) 또는 Cloudflare Tunnel(무료)
- **소셜 로그인 제한**: Google OAuth2 redirect URI가 localhost로 고정되어 있어, ngrok URL에서는 소셜 로그인 불가. 테스트 시 일반 로그인 사용 (소셜 로그인 테스트 필요 시 Google Console에 ngrok URL 추가 필요하나, URL이 매번 바뀌므로 비실용적)
- **보안**: 테스트 완료 후 ngrok 프로세스 반드시 종료하여 외부 접근 차단
- **성능**: ngrok 무료 플랜은 속도 제한이 있으므로 대용량 파일 업로드/다운로드는 느릴 수 있음
