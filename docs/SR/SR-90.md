# SR-90 음원 플레이어바 디자인 개편 (파형 기반 + 컨트롤 재배치)

> **우선 가치**: 작업 수행 전, 다음을 명확하게 파악한다.
> (1) 현재 플레이어바의 컴포넌트 구조와 재생 상태 관리 방식(진행률, 재생/일시정지, seek 등이 어떤 store/hook으로 동작하는지).
> (2) 현재 "한곡반복, 이전곡, 다음곡" 컨트롤이 어떤 이벤트/상태와 연결되어 있고, 다른 페이지(음원 목록, 앨범 상세, 좋아요, 재생목록)와 어떻게 상호작용하는지.
> (3) 음원 파일에서 파형 데이터를 추출하는 방법과 성능 영향(업로드 시 1회 추출 vs 재생 시 매번 분석 vs 캐싱 전략 등)과, 기존 업로드 파이프라인에 미치는 영향.
> (4) 모바일 환경에서의 플레이어바 레이아웃 대응 상태.
>
> 문제 해결에 더 나은 방향이나 추가 제안이 있다면 적극적으로 제안한다. 특히 파형 데이터 추출/저장 방식, 캐싱 전략, 컨트롤 배치의 UX는 구현 전 제안을 우선한다.

## 환경
- PC (모바일은 레이아웃 영향 여부 확인 필요)

## 배경
- 현재 음원 플레이어바는 상단에 "한곡반복 / 이전곡 / 재생 / 다음곡 / ..." 컨트롤이 있고, 그 아래(또는 함께)에 단순한 재생 진행바(progress bar)가 있음.
- 시각적으로 밋밋하고, 음원 서비스 특성상 파형(waveform) 기반 플레이어바가 제품 성격과 더 잘 맞음.
- 동시에 재생 관련 컨트롤의 위치를 재정비하여, 플레이어바 영역을 파형 중심으로 단순화하고자 함.

## 현상
- 재생바가 일반 progress bar 형태로, 음원 서비스로서의 시각적 정체성이 약함.
- 재생 컨트롤(반복/이전/다음)이 재생바와 분리된 공간을 차지하고 있어, 플레이어바가 파형으로 전환되면 배치가 어색해짐.

## 수정 내용

### 1. 재생바 → 파형(waveform) 디자인 전환
- 현재의 단순 progress bar를 **실제 음원 분석 기반 파형**으로 교체.
- 파형은 해당 음원의 실제 진폭 데이터를 반영해야 함 (장식용 가짜 파형 아님).
- **재생된 부분은 진한 색, 남지 않은 부분은 연한 색**으로 시각적으로 구분 (진행 상태 강조).
- 다크/라이트 모드 모두 일관되게 대응.
- **Seek 동작 유지**: 파형의 특정 위치를 클릭하면 해당 시간으로 이동 (현재 재생바의 seek 기능과 동일하게 동작).

> **구현 여지 (클로드 코드가 제안):**
> - 파형 데이터 추출 시점(업로드 시 1회 생성·저장 vs 재생 시 실시간 분석 vs 하이브리드).
> - 파형 데이터 저장 위치/포맷(별도 파일, DB 컬럼, CDN 등).
> - 파형 해상도(peak 개수)와 렌더링 방식.
> - 기존 음원에 대한 파형 데이터 마이그레이션 필요 여부.
> 위 항목은 코드베이스와 성능을 확인한 뒤, 장단점과 함께 제안 후 결정한다.

### 2. 재생 컨트롤(반복/이전/다음) 위치 이동
- 기존 플레이어바 상단의 "한곡반복, 이전곡, 다음곡, ..." 컨트롤을 **다운로드, 좋아요 버튼 쪽 영역**으로 이동.
- **기존 다운로드/좋아요 버튼 순서는 유지**하고, 그 옆(혹은 함께 묶인 액션 영역)에 반복/이전/다음 컨트롤을 추가 배치.
- 이동 후에도 각 컨트롤의 동작과 상태(반복 모드, 이전/다음 트리거 등)는 현재와 동일하게 동작해야 함.
- **플레이/일시정지 버튼**이 함께 이동할지 여부는 현재 플레이어 구조를 확인한 뒤 제안 (파형 위/옆에 두는 편이 UX상 자연스러울 수 있음).

### 3. 기존 기능 보존 (회귀 금지)
- 재생/일시정지, 이전/다음, 반복 모드(한곡/전체/끄기 등 현재 단계 그대로), seek, 볼륨, 현재 재생 시간/총 시간 표시 등 **기존 플레이어의 모든 기능은 유지**.
- 각 페이지(음원 목록, 앨범 상세, 좋아요, 재생목록)에서 플레이어바와의 연동(현재 재생 곡 표시, next 동작 등)도 그대로 동작해야 함.
- 키보드 방향키 이동(SR-40 및 SR-79)과의 상호작용 회귀 없어야 함.

### 4. 모바일 대응
- 모바일 레이아웃에서도 파형 + 재배치된 컨트롤이 깨지지 않도록 대응.
- 공간 제약이 심한 경우, 컨트롤 우선순위와 축소 방식을 제안.

## 작업 전 필수 확인 사항 (클로드 코드에게)
1. 현재 플레이어바 컴포넌트 구조와 상태 관리(어느 store/hook에서 재생 상태를 관리하는지).
2. 음원 파일 업로드/저장 파이프라인 (파형 추출을 끼워 넣을 적절한 지점).
3. 파형 추출 방식 후보별 비용·성능 비교 (클라이언트 추출 vs 업로드 시 서버 추출 vs 사전 생성).
4. 이동될 컨트롤이 현재 어떤 이벤트를 발생시키는지, 위치만 바꿔도 문제 없는지.
5. 기존 CSS/레이아웃이 모바일에서 어떻게 대응되고 있는지.

위 확인 결과를 바탕으로, **구현 착수 전에 파형 전략과 컨트롤 재배치 안을 제안하고 확인받은 뒤 작업**한다.
