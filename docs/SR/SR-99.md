# SR-99 음원 길이 오출력과 저장 메타데이터 정합성 개선

> **우선 가치**: 카탈로그에 표시하는 음원 길이와 실제 재생 길이는 동일한 미디어 분석 결과를 사용해야 한다. 파일 크기와 고정 비트레이트로 길이를 추정하지 않고, 최초 업로드와 오디오 교체에 같은 분석 계약을 적용하며 기존 저장값도 검증 가능한 절차로 보정한다.

## 환경

- 메인 화면 > 신규 음원
- 공개 음원 목록·상세 및 하단 플레이어
- 관리자 음원 조회·수정과 다운로드 기록
- PC, 모바일 공통

## 인수 테스트에서 확인된 현상

- 메인 화면의 `Space Oddity - T0Ro, MELE - 경동훈 (2)`는 `18:10`으로 표시됨.
- 같은 음원을 재생하면 브라우저가 실제 미디어 메타데이터를 읽은 뒤 약 `7:26`으로 표시함.
- 최초 관찰만 보면 해당 곡 파일의 문제로 보일 수 있으나, 공개된 세 음원을 교차검증한 결과 모두 같은 유형의 오차가 있음.

## 공개 데이터 교차검증

2026-08-08 공개 API의 저장 길이, 한 바이트 Range 응답의 전체 파일 크기, 브라우저 재생 메타데이터를 비교함.

| Track ID | 제목 | API·메인 표시 | 실제 미디어 길이 | 오차 | 파일 크기 | 현재 128 Kibit/s 계산 | 실제 평균 비트레이트 추정 |
| ---: | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 시골마을의 전학생 | 229초 (`3:49`) | 93초 (`1:33`) | +136초 | 3,756,312 bytes | 229초 | 약 323.1kbps |
| 2 | 시골마을의 전학생 | 229초 (`3:49`) | 93초 (`1:33`) | +136초 | 3,756,312 bytes | 229초 | 약 323.1kbps |
| 3 | Space Oddity - T0Ro, MELE - 경동훈 (2) | 1,090초 (`18:10`) | 446초 (`7:26`) | +644초 | 17,863,782 bytes | 1,090초 | 약 320.4kbps |

- 세 API 값은 모두 `floor(fileBytes / (128 * 1024 / 8))` 계산 결과와 정확히 일치함.
- 실제 길이와 파일 크기로 계산한 평균 비트레이트는 약 320kbps임. 이 수치만으로 각 파일이 CBR인지 VBR인지는 확정하지 않음.
- 따라서 특정 곡 하나의 손상이나 메인 화면 포맷 문제가 아니라, MP3를 128 Kibit/s로 고정 추정하여 저장한 공통 메타데이터 결함임.

## 원인과 화면별 차이

1. 최초 업로드에서 MP3 길이를 파일 크기와 128 Kibit/s 가정으로 계산하여 `tracks.duration`에 저장함.
2. 메인 신규 음원, 공개 음원 목록·상세, 관리자 음원 API, 다운로드 기록은 이 저장값을 그대로 전달함.
3. 메인과 음원 목록은 저장값만 포맷하므로 `18:10`, `3:49`처럼 잘못 표시함.
4. 하단 플레이어는 처음에는 저장값을 사용하지만 `loadedmetadata` 이후 브라우저의 실제 `audio.duration`으로 교정하므로 재생 중에는 `7:26`, `1:33`으로 바뀜.
5. 스트림·다운로드는 실제 파일 bytes를 전달하므로 저장된 duration 값 때문에 재생 파일이 잘리는 현상은 아님.
6. 관리자 오디오 파일 교체 경로는 waveform은 다시 만들지만 duration은 다시 계산하지 않음. 새 파일로 교체해도 이전 파일 길이가 남을 수 있음.

현재 테스트도 32,768-byte MP3를 128 Kibit/s 가정으로 2초라고 기대하므로, 테스트 통과는 실제 미디어 길이의 정확성을 보장하지 않고 기존 결함 계약을 고정함.

## 수정 내용

### 1. 실제 미디어 기반 단일 분석 결과

- 파일 크기와 고정 비트레이트를 이용한 duration 추정을 제거함. 128을 320으로 바꾸는 방식도 사용하지 않음.
- MP3의 프레임·컨테이너 메타데이터 또는 decoded PCM frame 수와 sample rate를 이용해 CBR, VBR, ID3 메타데이터가 포함된 파일의 실제 길이를 계산함.
- 현재 waveform 생성이 오디오를 PCM으로 읽으므로, 가능하면 한 번의 분석으로 `durationSeconds`와 실제 peak 배열을 함께 반환하여 서로 다른 파일을 설명하는 값이 저장되지 않게 함.
- 정수 초 변환의 반올림 방식과 브라우저 길이와의 허용 오차를 API 계약으로 고정함.
- 지원하지 않거나 손상된 파일의 분석에 실패하면 추정값이나 0을 저장하지 않고 명시적인 업로드 검증 오류로 거절함.

### 2. 생성·오디오 교체의 동일 계약과 원자성

- 최초 생성과 관리자 오디오 파일 교체가 같은 분석기를 사용함.
- 교체 전에 새 파일의 duration과 waveform을 모두 분석·검증함.
- 파일 경로, duration, waveform은 하나의 논리적 변경으로 함께 성공하거나 함께 실패해야 하며, 실패 시 기존 파일과 메타데이터를 유지함.
- 제목·설명·태그처럼 오디오가 바뀌지 않는 수정은 기존 duration과 waveform을 유지함.

### 3. 기존 데이터 dry-run과 backfill

- active와 inactive를 포함한 전체 보존 Track을 대상으로 먼저 읽기 전용 dry-run을 수행함.
- 보고서에는 Track ID, 파일 존재·읽기 상태, 기존 duration, 실제 추출 duration, 차이, 파서 결과, 제안 작업을 포함함.
- 허용 오차와 대상 건수를 확인한 뒤 별도 승인으로만 배치 갱신함. 이 SR 작성 과정에서는 DB와 공개 데이터를 수정하지 않음.
- backfill은 재실행 가능하고 실패 항목을 격리해야 하며, 변경 전 값을 보존하여 롤백할 수 있어야 함.
- 갱신 후 공개 목록·상세, 관리자 목록·상세, 다운로드 기록 API의 duration을 교차검증하고 변경·성공·실패 건수를 대조함.

## 현재 구현 상태 (2026-08-09)

- **상태**: WI-20260808-ATS-016에서 단일 PCM 분석, 생성/교체 원자성,
  읽기 전용 dry-run API와 집중 테스트를 구현함. 실제 보존 Track을 대상으로
  한 dry-run과 기존 행 backfill은 실행하지 않았으며 별도 승인 대상임.
- `AudioAnalysisService.java`는 MP3/WAV를 한 번 디코딩해 rounded duration과
  200-point waveform을 생성함. 손상/미지원/빈 파일은
  `AUDIO_ANALYSIS_FAILED`로 storage/DB 변경 전에 거절함.
- `TrackService.java`는 생성과 교체에서 같은 분석기를 쓰고, 교체 시 storage
  key/duration/waveform을 하나의 논리적 변경으로 적용함. metadata-only
  수정은 기존 값을 보존함.
- `GET /api/admin/tracks/audio-analysis/dry-run`은 active/inactive를 포함해
  ID 오름차순, page size 1~100으로 보고하며 storage key를 노출하거나
  repository save/update/delete를 호출하지 않음.
- 합성 fixture는 PCM WAV, 128/320 CBR MP3, Xing+ID3v2 VBR을 포함함. VBRI,
  unusual container/encoder, 실제 운영 파일은 미검증 경계임. 근거는
  [WI-016 summary](../../deliverables/user/WI-20260808-ATS-016-summary.md)와
  [Evidence Pack](../../deliverables/agent/WI-20260808-ATS-016-evidence-pack.md)에 있음.

## 완료 조건

- [ ] 128 Kibit/s·320kbps CBR, VBR(Xing/VBRI), ID3v2·앨범아트 포함 MP3에서 실제 길이가 허용 오차 이내로 추출됨.
- [x] 기존 WAV 길이와 waveform 생성에 회귀가 없음.
- [x] 손상·오표기·읽기 불가 파일은 명시적 오류로 거절되고 DB와 스토리지에 부분 저장되지 않음.
- [x] 최초 생성이 동일 분석 결과의 duration과 waveform을 함께 저장함.
- [x] 오디오 교체가 파일·duration·waveform을 함께 갱신하고, 분석·저장 실패 시 기존 값을 모두 유지함.
- [x] 오디오가 바뀌지 않는 수정은 기존 duration과 waveform을 유지함.
- [ ] 메인과 음원 목록이 93초를 `1:33`, 446초를 `7:26`으로 표시함.
- [ ] 목록·상세·관리자·다운로드 기록 API가 같은 보정값을 반환함.
- [ ] 재생 전 표시와 브라우저 `loadedmetadata` 이후 길이가 허용 오차 내에서 일치하고 seek·진행률이 정상 동작함.
- [ ] dry-run, 부분 실패, 재실행, 승인된 backfill, 롤백을 포함한 기존 데이터 보정 절차가 검증됨.

## 후속 설계에서 결정할 사항

- [ ] 정수 초 반올림 방식과 서버·브라우저 간 허용 오차
