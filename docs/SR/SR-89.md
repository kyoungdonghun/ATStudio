# SR-81 재생기록 localStorage 전환 (기존 대기열 방식 참고)

> **우선 가치**: 작업 수행 전, 다음을 명확하게 파악한다: (1) 현재 재생기록이 어떻게 저장/조회되는지 (API + DB), (2) 기존 대기열이 localStorage로 어떻게 구현되어 있는지 (데이터 구조, 용량 관리, 동기화 방식), (3) 재생기록을 localStorage로 옮겼을 때 기존 API/DB와의 관계. 문제 해결에 추가 정보나 좋은 제안이 있다면 적극적으로 제안한다.

## 환경

- PC

## 배경

- 현재 재생기록은 서버(API + DB)에 저장되는 구조
- 기존 "대기열"은 localStorage로 관리되는 것처럼, 재생기록도 localStorage로 전환하고자 함
- 기존 API와 DB는 삭제하지 않고 유지 (향후 활용 가능성 대비)

## 수정 내용

- 재생기록 저장/조회 로직을 localStorage 기반으로 전환
- 기존 대기열의 localStorage 구현 방식을 참고하여 일관성 유지
- 재생기록 관련 API와 DB 테이블은 **삭제하지 않고 유지**
- 프론트엔드에서 해당 API 호출 제거 또는 비활성화
- localStorage 용량 한계 고려한 기록 개수 제한 정책 필요 (구체 수치는 검토 후 제안)
