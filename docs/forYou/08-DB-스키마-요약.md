# 08. DB 스키마 요약

> ATStudio 데이터베이스의 전체 구조를 설명합니다.
> MySQL 8.x 기반, 총 **23개 테이블**로 구성되어 있습니다.

---

## 공통 규칙

모든 테이블에 아래 컬럼이 포함됩니다:

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `created_at` | DATETIME | 생성 시각 (자동) |
| `updated_at` | DATETIME | 수정 시각 (자동 갱신) |

**타입 규칙:**
- PK: `BIGINT AUTO_INCREMENT`
- FK: `BIGINT` (PK와 동일 타입)
- Boolean: `TINYINT(1)` (0/1)
- 금액: `DECIMAL(10,2)`
- 날짜: `DATETIME` 또는 `DATE`

## 그룹별 상세 설명

### A. 사용자 관련 (3개 테이블)

#### users — 사용자 계정

**목적**: 모든 회원(비회원 제외)의 계정 정보를 저장하는 핵심 테이블

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `id` | BIGINT PK | 사용자 식별자 |
| `nickname` | VARCHAR(20) UNIQUE | 닉네임 |
| `email` | VARCHAR(100) UNIQUE | 로그인 이메일 |
| `password` | VARCHAR(255) NULL | BCrypt 해시. 소셜 로그인 전용 계정은 NULL |
| `phone_company` | VARCHAR(20) NULL | 회사 전화번호 (기업 회원용) |
| `phone_personal` | VARCHAR(20) NULL | 개인 전화번호. 소셜 로그인 시 NULL → 프로필 완성 단계에서 입력 |
| `is_verified` | TINYINT(1) | 이메일/전화 인증 여부 (0/1) |
| `role` | ENUM('USER','ADMIN') | 역할. 기본값: USER |
| `job` | ENUM('EDITOR','ARTIST','FREELANCER') NULL | 직업. 소셜 로그인 시 NULL |
| `user_type` | ENUM('INDIVIDUAL','BUSINESS') | 개인/기업. 기본값: INDIVIDUAL |
| `is_deleted` | TINYINT(1) | 소프트 삭제 플래그 (0/1) |

**소셜 로그인 2단계 등록 플로우:**
1. 첫 소셜 로그인 → 최소 정보(email, nickname)로 레코드 생성
2. `password`, `phone_personal`, `job`이 NULL → 미완성 프로필 상태
3. 프론트엔드가 `isProfileComplete` 플래그를 체크하여 프로필 완성 화면으로 리다이렉트
4. 프로필 완성 후 전체 기능 이용 가능

**일일 다운로드 한도 처리:**
- `download_remain` 컬럼 없음 (COUNT 쿼리 방식)
- `track_downloads` 테이블에서 `WHERE user_id = ? AND DATE(downloaded_at) = CURDATE()` 로 카운트
- 구독 플랜의 `download_per_day`와 비교하여 제한

#### social_accounts — 소셜 로그인

**목적**: Google/Kakao/Naver 소셜 로그인 계정 연동 정보

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `id` | BIGINT PK | 식별자 |
| `user_id` | BIGINT FK → users | 연동된 사용자 |
| `provider` | ENUM('GOOGLE','KAKAO','NAVER') | 소셜 제공자 |
| `provider_id` | VARCHAR(255) | 소셜 서비스가 부여한 사용자 ID |

- UNIQUE: (`provider`, `provider_id`)
- 한 사용자가 여러 소셜 계정 연동 가능 (1:N)

#### whitelist_channels — 화이트리스트 채널

**목적**: 구독자가 등록한 YouTube 채널. 라이선스 적용 범위를 한정.

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `id` | BIGINT PK | 식별자 |
| `user_id` | BIGINT FK → users | 등록한 사용자 |
| `channel_url` | VARCHAR(255) | YouTube 채널 URL |
| `channel_name` | VARCHAR(100) | 채널 표시 이름 |

- 등록 가능 채널 수는 구독 플랜의 `max_whitelist_channels`로 제한

### B. 구독 관련 (3개 테이블)

#### subscriptions — 구독 플랜 정의

**목적**: STANDARD/DELUXE/PREMIUM 등 구독 상품 정의 (시드 데이터)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `id` | BIGINT PK | 식별자 |
| `name` | VARCHAR(30) | 플랜명 (STANDARD/DELUXE/PREMIUM) |
| `user_type` | ENUM('INDIVIDUAL','BUSINESS') | 대상 사용자 유형 |
| `price_monthly` | DECIMAL(10,2) | 월간 가격 |
| `price_yearly` | DECIMAL(10,2) | 연간 가격 |
| `download_per_day` | INT | 일일 다운로드 한도 (-1 = 무제한) |
| `max_whitelist_channels` | INT | 최대 화이트리스트 채널 수 |
| `is_active` | TINYINT(1) | 사용자 선택 가능 여부 |

- UNIQUE: (`name`, `user_type`)

**시드 데이터 구성:**

| 플랜 | 대상 | 일일 다운로드 | 최대 채널 |
|------|------|------------|----------|
| STANDARD | 개인 | 5 | 1 |
| DELUXE | 개인 | 20 | 2 |
| PREMIUM | 개인 | 무제한 | 2 |
| DELUXE | 기업 | 50 | 2 |
| PREMIUM | 기업 | 무제한 | 2 |

#### user_subscriptions — 사용자 구독 상태

**목적**: 각 사용자의 현재 구독 상태를 1:1로 관리

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `id` | BIGINT PK | 식별자 |
| `user_id` | BIGINT FK → users, UNIQUE | 사용자 (1인 1구독) |
| `subscription_id` | BIGINT FK → subscriptions | 현재 구독 플랜 |
| `billing_cycle` | ENUM('MONTHLY','YEARLY') | 결제 주기 |
| `status` | ENUM('ACTIVE','CANCELLED','EXPIRED') | 구독 상태 |
| `started_at` | DATE | 현재 기간 시작일 |
| `expires_at` | DATE | 현재 기간 종료일 |
| `pending_subscription_id` | BIGINT FK → subscriptions, NULL | 다운그레이드 예약 플랜 |
| `pending_billing_cycle` | VARCHAR(10) NULL | 다운그레이드 예약 결제 주기 |

**구독 변경 처리:**
- **업그레이드** (더 비싼 플랜): 즉시 적용. 결제 금액 = 새 플랜 가격 - 현재 플랜 잔여 일할 금액
- **다운그레이드** (더 저렴한 플랜): 예약 처리. `pending_subscription_id`에 저장, 현재 기간 만료 시 적용
- **취소**: status = CANCELLED, `expires_at`까지 서비스 유지 (유예)

#### subscription_payments — 구독 결제 기록

**목적**: 모든 구독 결제 이력 보관 (PG 연동 포함)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `id` | BIGINT PK | 식별자 |
| `user_id` | BIGINT FK → users | 결제 사용자 |
| `user_subscription_id` | BIGINT FK → user_subscriptions | 연결된 구독 세션 |
| `subscription_id` | BIGINT FK → subscriptions | 결제 대상 플랜 |
| `billing_cycle` | ENUM('MONTHLY','YEARLY') | 결제 주기 |
| `amount` | DECIMAL(10,2) | 결제 금액 (업그레이드 시 일할 계산 금액) |
| `payment_status` | ENUM('READY','DONE','REFUND') | 결제 상태 |
| `pg_transaction_id` | VARCHAR(100) NULL | PG사 거래 ID |

### C. 음원 관련 (5개 테이블)

#### tracks — 음원

**목적**: 서비스의 핵심 콘텐츠. 크리에이터가 업로드한 배경음악

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `id` | BIGINT PK | 식별자 |
| `title` | VARCHAR(100) | 음원 제목 |
| `thumbnail` | VARCHAR(255) NULL | 썸네일 파일명 |
| `bpm` | INT | 빠르기 (Beats Per Minute) |
| `tonality` | VARCHAR(10) | 키/조성 (예: C, Am, F#m) |
| `description` | TEXT NULL | 음원 설명 |
| `audio_file` | VARCHAR(255) | 원본 오디오 파일 경로 (다운로드용) |
| `preview_file` | VARCHAR(255) NULL | 미리듣기용 저품질 파일 (NULL이면 audio_file 사용) |
| `user_id` | BIGINT FK → users | 저작권자 (크리에이터) |
| `is_active` | TINYINT(1) | 공개 여부. 기본값: 0 (관리자 승인 후 1로 전환) |
| `play_count` | BIGINT | 재생 횟수. 기본값: 0 |

#### albums — 앨범

**목적**: 관리자가 큐레이션한 음원 묶음 (컬렉션)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `id` | BIGINT PK | 식별자 |
| `title` | VARCHAR(100) | 앨범 제목 |
| `description` | TEXT NULL | 설명 |
| `thumbnail` | VARCHAR(500) NULL | 앨범 커버 이미지 URL |
| `created_by` | BIGINT FK → users | 생성자 (ADMIN) |
| `is_active` | TINYINT(1) | 소프트 삭제. 기본값: 1 |

#### album_tracks — 앨범-음원 매핑

**목적**: 앨범에 포함된 음원과 순서를 관리하는 중간 테이블

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `album_id` | BIGINT PK, FK → albums | 앨범 |
| `track_id` | BIGINT PK, FK → tracks | 음원 |
| `track_order` | INT | 정렬 순서. 기본값: 0 |

- 복합 PK: (`album_id`, `track_id`)

#### tags — 태그

**목적**: 음원을 분류하는 태그 (분위기/장르/악기)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `id` | BIGINT PK | 식별자 |
| `name` | VARCHAR(50) UNIQUE | 태그 이름 |
| `type` | ENUM('MOOD','GENRE','INSTRUMENT') | 태그 유형 (분위기/장르/악기) |

#### track_tags — 음원-태그 매핑

**목적**: 음원과 태그의 N:M 관계를 풀어주는 중간 테이블

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `track_id` | BIGINT PK, FK → tracks | 음원 |
| `tag_id` | BIGINT PK, FK → tags | 태그 |

- 복합 PK: (`track_id`, `tag_id`)
- 태그 수정 시 `tracks.updated_at`도 갱신

### D. 재생목록 관련 (2개 테이블)

#### playlists — 재생목록

**목적**: 구독자가 생성하는 음원 모음 (최대 3개 제한)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `id` | BIGINT PK | 식별자 |
| `title` | VARCHAR(50) | 재생목록 제목 |
| `description` | TEXT NULL | 설명 |
| `thumbnail` | VARCHAR(255) NULL | 썸네일 이미지 |
| `user_id` | BIGINT FK → users | 생성자 |
| `is_active` | TINYINT(1) | 활성 여부. 기본값: 1 |

- 활성 구독(ACTIVE) 상태인 사용자만 재생목록 기능 사용 가능 (앱 레벨 체크)

#### playlist_tracks — 재생목록-음원 매핑

**목적**: 재생목록에 포함된 음원과 순서를 관리

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `playlist_id` | BIGINT PK, FK → playlists | 재생목록 |
| `track_id` | BIGINT PK, FK → tracks | 음원 |
| `track_order` | INT | 정렬 순서 |

- 복합 PK: (`playlist_id`, `track_id`)
- 수정 시 `playlists.updated_at` 갱신

### E. 라이선스 (1개 테이블)

#### licenses — 음원 사용 라이선스

**목적**: 음원 다운로드 시 자동 발급되는 저작권 증명 라이선스

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `id` | BIGINT PK | 식별자 |
| `user_id` | BIGINT FK → users | 라이선스 보유자 |
| `track_id` | BIGINT FK → tracks | 대상 음원 |
| `license_code` | VARCHAR(50) UNIQUE | UUID 기반 라이선스 코드 |

- UNIQUE: (`user_id`, `track_id`) — 사용자당 음원당 1개 라이선스
- 같은 음원 재다운로드 시 기존 라이선스 유지 (중복 발급 없음)
- `created_at`을 API 응답에서 `issuedAt`으로 매핑

### F. 활동 기록 (3개 테이블)

#### track_downloads — 다운로드 이력

**목적**: 음원 다운로드 기록. 일일 다운로드 한도 계산에 사용

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `id` | BIGINT PK | 식별자 |
| `user_id` | BIGINT FK → users | 다운로드한 사용자 |
| `track_id` | BIGINT FK → tracks | 다운로드한 음원 |
| `downloaded_at` | DATETIME | 다운로드 시각 |

- 같은 음원을 여러 번 다운로드 가능 (이력 기록)
- INDEX: (`user_id`, `downloaded_at`) — 일일 카운트 쿼리 성능 보장

#### play_histories — 재생 이력

**목적**: 음원 재생 기록. 최근 재생 목록 표시에 활용

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `id` | BIGINT PK | 식별자 |
| `user_id` | BIGINT FK → users | 재생한 사용자 |
| `track_id` | BIGINT FK → tracks | 재생한 음원 |
| `played_at` | DATETIME | 재생 시각 |

- 같은 음원 반복 재생 시 매번 기록
- `tracks.play_count` 증가와 연동 (앱 레벨)

#### likes — 좋아요

**목적**: 사용자의 음원 좋아요 표시 (토글 방식)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `user_id` | BIGINT PK, FK → users | 사용자 |
| `track_id` | BIGINT PK, FK → tracks | 음원 |

- 복합 PK: (`user_id`, `track_id`)
- 좋아요 취소 시 레코드 삭제 (물리 삭제)

#### download_queue — 다운로드 큐

**목적**: 여러 음원을 모아서 일괄 다운로드하는 "장바구니" 역할

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `user_id` | BIGINT PK, FK → users | 사용자 |
| `track_id` | BIGINT PK, FK → tracks | 음원 |

- 복합 PK: (`user_id`, `track_id`)
- 기존 `cart_items` → `download_queue`로 이름 변경 (구매 개념 없이 큐 방식)

### G. 기업 인증 (1개 테이블)

#### company_certifications — 기업 인증

**목적**: 기업 회원(100인 이상)의 인증 신청 및 관리자 심사

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `id` | BIGINT PK | 식별자 |
| `user_id` | BIGINT FK → users | 신청자 (기업 회원) |
| `status` | ENUM('PENDING','APPROVED','REVISION_REQUESTED','REJECTED') | 심사 상태 |
| `admin_note` | TEXT NULL | 관리자 메모 (수정 요청 사유 등) |
| `document_path` | VARCHAR(500) | 서류 파일 저장 경로 |
| `certification_code` | VARCHAR(50) UNIQUE, NULL | 승인 시 발급되는 UUID 기반 인증 코드 |
| `approved_at` | DATETIME NULL | 승인 시각 |

**심사 프로세스:**
1. 기업 회원이 구독 플랜 선택 → 서류 제출 (status: PENDING)
2. 관리자가 검토 → 수정 요청(REVISION_REQUESTED) 또는 승인(APPROVED)
3. 승인 시 `certification_code` 발급 → 구독 결제 가능 상태

---

### H. 커뮤니티 (4개 테이블)

#### notices — 공지사항

**목적**: 관리자가 작성하는 공지사항

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `id` | BIGINT PK | 식별자 |
| `user_id` | BIGINT FK → users | 작성자 (ADMIN) |
| `title` | VARCHAR(200) | 제목 |
| `content` | TEXT | 내용 |
| `is_pinned` | TINYINT(1) | 상단 고정 여부. 기본값: 0 |

#### questions — 1:1 문의

**목적**: 사용자의 1:1 문의 등록 및 관리

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `id` | BIGINT PK | 식별자 |
| `user_id` | BIGINT FK → users | 작성자 |
| `title` | VARCHAR(200) | 제목 |
| `content` | TEXT | 내용 |
| `category` | ENUM('DOWNLOAD','PAYMENT','COPYRIGHT','PRODUCTION','OTHER') | 카테고리 |
| `is_public` | TINYINT(1) | 공개/비공개. 기본값: 0 (비공개) |
| `status` | ENUM('OPEN','IN_PROGRESS','RESOLVED','CLOSED') | 상태. 기본값: OPEN |

**비공개 문의 정책:** `is_public = 0`인 문의는 **작성자 + ADMIN**만 조회 가능 (앱 레벨 권한 체크)

**상태 흐름:**
```
OPEN → IN_PROGRESS (관리자 첫 답변 시) → RESOLVED (해결) → CLOSED (종료)
OPEN → CLOSED (관리자가 답변 없이 종료)
```

#### answers — 문의 답변

**목적**: 문의에 대한 대화형 답변 (사용자 ↔ 관리자 1:N)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `id` | BIGINT PK | 식별자 |
| `question_id` | BIGINT FK → questions | 대상 문의 |
| `user_id` | BIGINT FK → users | 답변 작성자 (사용자 또는 관리자) |
| `content` | TEXT | 답변 내용 |

- 새 답변 등록 시 `questions.updated_at` 갱신

#### question_attachments — 문의 첨부파일

**목적**: 문의에 첨부된 파일 관리

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `id` | BIGINT PK | 식별자 |
| `question_id` | BIGINT FK → questions | 대상 문의 |
| `original_name` | VARCHAR(255) | 업로드 시 원본 파일명 |
| `file_path` | VARCHAR(500) | 서버 저장 경로 |
| `file_size` | BIGINT | 파일 크기 (bytes) |

- 1개 문의에 여러 첨부파일 가능 (1:N)

## 주의할 점 (개발 시 참고)

### 복합 PK 테이블

아래 테이블들은 복합 Primary Key를 사용합니다:

| 테이블 | PK 구성 |
|--------|---------|
| `track_tags` | (track_id, tag_id) |
| `playlist_tracks` | (playlist_id, track_id) |
| `album_tracks` | (album_id, track_id) |
| `likes` | (user_id, track_id) |
| `download_queue` | (user_id, track_id) |

> **주의**: JPA에서 복합 PK 엔티티는 `save()` 호출 시 `merge()` 동작을 함.
> 신규 생성인지 확인하려면 `existsById()` 체크가 필수입니다.
> (프로젝트 Lessons Learned 참고)

### N:M 관계 중간 테이블

| 관계 | 중간 테이블 | 추가 컬럼 |
|------|-----------|----------|
| tracks ↔ tags | `track_tags` | 없음 |
| playlists ↔ tracks | `playlist_tracks` | `track_order` (정렬) |
| albums ↔ tracks | `album_tracks` | `track_order` (정렬) |
