## 최상위 폴더별 역할

### `src/` — 백엔드 (Spring Boot)

Java 17 기반의 Spring Boot 4.x 백엔드 소스 전체가 위치합니다. REST API 서버로서 MySQL 8.x 데이터베이스와 연결되며, JWT 기반 인증, 이메일 발송, 파일 저장(로컬) 기능을 포함합니다. 패키지는 `com.atstudio.atstudio` 루트 아래에 역할별로 분리되어 있습니다 (자세한 내용은 아래 백엔드 섹션 참조).

### `frontend/` — 프론트엔드 (React + TypeScript)

React 18 + TypeScript 5.6 + Vite 6 기반의 SPA(Single Page Application) 소스 전체가 위치합니다. CSS Modules와 CSS Variables(`tokens.css`)를 사용해 스타일을 관리하며, Tailwind CSS 및 styled-components는 사용하지 않습니다. Axios 인터셉터가 JWT를 자동으로 요청 헤더에 첨부합니다.

### `docs/` — 프로젝트 문서

단순한 읽기용 문서가 아니라, AI 에이전트가 작업 시 주입(inject)하는 **실행 가능한 컨텍스트 자산**입니다. Tier 0(헌법/표준)부터 Tier 2(가이드/템플릿)까지 계층화되어 있으며, 각 에이전트는 작업 유형에 따라 필요한 문서만 선택적으로 로드합니다.

### `deliverables/` — REQ/WI 산출물 추적 시스템

모든 개발 작업은 REQ(요구사항)와 WI(Work Item) 단위로 추적됩니다.
- `user/`: 사용자가 확인하고 승인하는 보고서 (REQ 초안, WI 요약)
- `agent/`: AI 에이전트가 다음 작업 시 참조하는 상세 추적 문서 (WI 핸드오프 패킷, Evidence Pack)

### `.claude/` — AI 에이전트 시스템

ATStudio 개발에 활용되는 멀티에이전트 협업 시스템의 설정 파일이 위치합니다. 11개의 에이전트(ps, eo, sa, se, re, pg, tr, uv, docops, qa, cr)가 각각 전문 역할을 담당하며, 스킬(Skills)은 반복 작업을 표준 절차로 패키징합니다. 에이전트 시스템을 처음 접하는 팀원은 10번 문서(Claude 에이전트 가이드)를 참조하세요.

## 백엔드 패키지 구조 심층 설명

패키지 루트: `com.atstudio.atstudio`

### `common/`

프로젝트 전반에서 공유하는 공통 요소:
- `common/entity/BaseEntity.java`: 모든 JPA 엔티티가 상속하는 기반 클래스. `created_at`, `updated_at` 필드를 자동 관리합니다.
- `common/exception/GlobalExceptionHandler.java`: 모든 예외를 한 곳에서 처리합니다. `BusinessException`, `TechnicException`을 분기 처리하며, `AccessDeniedException`은 반드시 catch-all 이전에 별도 분기해야 합니다 (Spring Security 특성).
- `common/dto/`: `ResponseDTO`, `PageInfo`, `ExceptionResponseDTO` 등 응답 래퍼 클래스.

### `config/`

Spring 설정 클래스 모음:
- `SecurityConfig`: Spring Security 6 필터 체인, 엔드포인트별 접근 권한 정의
- `JwtConfig`: JWT 시크릿 키, 만료 시간 설정
- `CorsConfig`: 프론트엔드(`localhost:5173`)에서의 Cross-Origin 요청 허용
- `WebConfig`: 정적 파일 서빙 경로 등 웹 MVC 설정
- `AppConfig`: ModelMapper, PasswordEncoder 등 공통 Bean 정의
- `JpaConfig`: JPA Auditing 활성화

### `controller/`

REST API 엔드포인트를 정의하는 17개의 Controller 클래스. 각 Controller는 얇게 유지하는 것이 원칙입니다 — 요청을 받아 Service에 위임하고, Service의 결과를 `ResponseEntity`로 감싸 반환합니다. 직접적인 비즈니스 로직을 포함하지 않습니다.

주요 Controller: `AuthController`, `TrackController`, `AlbumController`, `UserController`, `SubscriptionController`, `UserSubscriptionController`, `PlaylistController`, `LicenseController`, `TagController`, `NoticeController`, `QuestionController`, `CompanyCertificationController`, `WhitelistChannelController`, `LikeController`, `DownloadQueueController`, `PlayHistoryController`, `UtilController`

### `dto/`

Controller와 Service 간 데이터 전달에 사용하는 DTO(Data Transfer Object). Java record 타입을 적극 활용합니다. 엔티티를 Controller에서 직접 반환하지 않으며, 반드시 DTO로 변환합니다.

구조 예: `dto/track/TrackResponse.java`, `dto/auth/LoginRequest.java`, `dto/user/UserResponse.java`

### `entity/`

JPA 엔티티 클래스 (23개 테이블과 매핑). 모든 테이블명과 컬럼명은 `snake_case`를 사용하며, PK는 `BIGINT AUTO_INCREMENT`입니다. 복합 키를 사용하는 엔티티(Like, DownloadQueue, PlaylistTrack 등)는 `entity/key/` 하위에 별도 복합키 클래스를 정의합니다.

복합 PK 엔티티 주의사항: `save()` 호출 시 merge() 동작을 하므로, 중복 체크가 필요한 경우 `existsById()`를 명시적으로 먼저 호출해야 합니다.

### `repository/`

Spring Data JPA의 `JpaRepository` 인터페이스. 간단한 CRUD는 메서드 이름 기반 쿼리를 사용하고, 복잡한 동적 검색은 `Specification` 패턴을 활용합니다. Spring Data 4.x에서 `Specification.where(null)` 사용 시 `IllegalArgumentException`이 발생하므로, `addSpec()` 헬퍼 패턴을 사용합니다.

### `security/`

JWT 인증 처리:
- `JwtTokenProvider.java`: 토큰 생성, 파싱, 검증
- `JwtAuthenticationFilter.java`: 요청마다 Authorization 헤더에서 JWT를 추출하고 검증
- `CustomUserDetailsService.java`: DB에서 사용자 조회
- `CustomUserDetails.java`: Spring Security의 `UserDetails` 구현

### `service/`

비즈니스 로직의 핵심. 모든 Service 클래스에 `@Transactional`을 적용합니다. Controller → Service → Repository 방향으로만 의존하며, 역방향 의존은 금지합니다.

### 레이어 의존 방향

```
Controller → Service → Repository → Entity
    ↕            ↕
   DTO          DTO
```

Controller와 Service는 각각 DTO를 통해 데이터를 주고받습니다. Entity 객체는 Service 레이어 안에서만 다루며, Controller에 노출되지 않습니다.

## 프론트엔드 src/ 구조 심층 설명

### `pages/`

화면 단위의 React 컴포넌트. 역할에 따라 5개 그룹으로 분류됩니다:

| 그룹 | 경로 | 설명 | 화면 수 |
|------|------|------|---------|
| public | `pages/public/` | 비회원도 접근 가능한 공개 화면 | 9개 |
| auth | `pages/auth/` | 로그인, 회원가입, 이메일 인증 등 | 6개 |
| subscriber | `pages/subscriber/` | 로그인 필요 (구독자 기능) | 19개 |
| creator | `pages/creator/` | 관리자 전용 (트랙/앨범 관리) | 5개 |
| admin | `pages/admin/` | 관리자 전용 (운영 관리) | 10개 |
| error | `pages/error/` | 404, 500 에러 화면 | 2개 |

접근 제어는 `router/ProtectedRoute.tsx`에서 `minRole` prop으로 처리합니다. `USER` 역할 이상이면 구독자 페이지에 접근 가능하고, `ADMIN` 역할이어야 크리에이터/관리자 페이지에 접근 가능합니다.

### `api/`

백엔드 API 호출 함수를 엔드포인트 도메인별로 모듈화:
- `client.ts`: Axios 인스턴스 + JWT 자동 첨부 인터셉터 + 토큰 갱신 로직
- `auth.ts`: 로그인, 회원가입, 소셜 로그인
- `tracks.ts`: 트랙 목록, 상세, 업로드, 다운로드
- `albums.ts`: 앨범 목록, 상세, 생성
- `playlists.ts`: 재생목록 CRUD
- `subscriptions.ts`: 구독 플랜 목록
- `userSubscriptions.ts`: 구독 결제, 상태 관리
- `licenses.ts`: 라이선스 조회
- `tags.ts`: 태그 목록, 관리자 태그 CRUD
- `notices.ts`: 공지사항 조회, 작성
- `admin.ts`: 관리자 전용 (사용자, 기업인증, 대시보드 등)

### `components/`

여러 페이지에서 재사용하는 UI 컴포넌트:
- `ui/`: 범용 기본 컴포넌트 (Button, Badge, Tag, FilterChip, Modal)
- `track/`: 트랙 표시 컴포넌트 (TrackRow — 리스트 방식 전용)
- `album/`: 앨범 표시 컴포넌트 (AlbumCard — 이미지 카드 방식)

### `layouts/`

모든 페이지를 감싸는 레이아웃 컴포넌트:
- `MainLayout.tsx`: 페이지 전체 레이아웃 구조 (Header + 본문 + PlayerBar)
- `Header.tsx`: 상단 내비게이션 바 (로그인 상태에 따라 메뉴 변경)
- `PlayerBar.tsx`: 하단 고정 음원 플레이어

### `router/`

- `index.tsx`: 48개 화면의 라우트 정의. `authRequired()`, `adminOnly()` 헬퍼 함수로 접근 제어를 선언적으로 적용
- `ProtectedRoute.tsx`: 비로그인 또는 권한 부족 시 리디렉션 처리

### `store/`

Zustand 기반 글로벌 상태 관리:
- `authStore.ts`: 로그인 사용자 정보, JWT 토큰, 로그인/로그아웃 액션
- `playerStore.ts`: 현재 재생 중인 트랙, 재생/일시정지 상태

### `styles/`

- `tokens.css`: CSS 변수 기반 디자인 토큰 (색상, 간격, 폰트 크기 등). 모든 컴포넌트는 하드코딩 대신 이 변수를 참조합니다. 라이트/다크 모드 전환도 이 파일에서 관리합니다.

### `types/`

- `index.ts`: 프로젝트 전체에서 공유하는 TypeScript 타입 정의 (User, Track, Album, Playlist, Subscription, License 등)

### 데이터 흐름

```
사용자 액션 → Page 컴포넌트 → api/ 모듈 → Axios (JWT 자동 첨부) → 백엔드 API
                  ↕
             Zustand Store (글로벌 상태: 로그인 정보, 플레이어 상태)
```

페이지 컴포넌트는 직접 Axios를 호출하지 않고, 반드시 `api/` 모듈의 함수를 통해 백엔드와 통신합니다. 글로벌 상태(로그인 여부, 현재 재생 트랙 등)는 Zustand store를 통해 관리하며, 컴포넌트 간 prop drilling을 최소화합니다.

## 핵심 설정 파일 안내

### `src/main/resources/application.yml`

백엔드 서버의 핵심 설정:
- **DB 연결**: `spring.datasource.url`, `username`, `password` (로컬 기본값: `root` / `1234`)
- **JWT**: 시크릿 키, 액세스 토큰 만료 시간(1시간), 리프레시 토큰 만료 시간(7일)
- **파일 업로드**: 임시 저장 경로 설정
- **메일 서버**: SMTP 설정 (이메일 인증 발송용)
- **서버 포트**: 기본값 8080

> 보안 주의: JWT 시크릿과 DB 비밀번호는 운영 환경에서 반드시 환경변수로 관리해야 합니다. 현재 기본값은 로컬 개발 전용입니다.

### `frontend/vite.config.ts`

프론트엔드 개발 서버 설정:
- 개발 서버 포트: 5173
- `/api/*` 경로의 요청을 `http://localhost:8080`으로 프록시합니다. 이로 인해 프론트엔드 코드에서 CORS 없이 백엔드 API를 호출할 수 있습니다.
- `@/` 경로 별칭: `src/` 디렉터리를 가리킵니다 (`import '@/components/ui/Button'` 형식으로 사용).

### `build.gradle`

백엔드 빌드 설정:
- Java 17 toolchain 지정
- Spring Boot 4.0.2, Spring Data JPA, Spring Security 6, Spring MVC
- JJWT 0.12.5 (JWT 처리)
- Springdoc OpenAPI 3.0.2 (Swagger UI, Spring Boot 4.x 호환 버전)
- Lombok (코드 자동 생성)
- ModelMapper 3.2.0 (DTO 변환)
- 테스트 DB: H2 (인메모리, 테스트 실행 시에만 사용)
- 운영 DB: MySQL 8.x (runtime)
