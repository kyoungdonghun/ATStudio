# 로컬 환경 셋업 — 처음부터 서버 띄우기

> **이 문서의 목표:** 아무것도 없는 상태에서 이 가이드만 따라하면 백엔드와 프론트엔드가 모두 실행되도록 안내합니다.

---

## 사전 조건 — 먼저 설치해야 할 도구

아래 도구가 모두 설치되어 있어야 합니다. 각 명령어로 설치 여부를 먼저 확인하세요.

| 도구 | 필요 버전 | 확인 명령어 | 다운로드 |
|------|---------|-----------|---------|
| Java JDK | 17 이상 | `java -version` | [adoptium.net](https://adoptium.net) |
| Node.js | 18 이상 | `node -version` | [nodejs.org](https://nodejs.org) |
| npm | 9 이상 | `npm -version` | Node.js와 함께 설치됨 |
| MySQL | 8.x | `mysql --version` | [mysql.com](https://www.mysql.com/downloads/) |
| Git | 최신 | `git --version` | [git-scm.com](https://git-scm.com) |
| IDE | - | - | IntelliJ (백엔드), VS Code (프론트엔드) 추천 |

> **Windows 주의:** Java 설치 후 환경변수 `JAVA_HOME`이 설정되어 있어야 Gradle이 정상 동작합니다. 설치 프로그램에서 "환경변수 설정" 옵션을 체크하세요.

## 1단계: 저장소 클론

```bash
git clone <repo-url>
cd ATStudio
```

클론 후 디렉터리 구조:

```
ATStudio/
├── src/              ← Spring Boot 백엔드
├── frontend/         ← React 프론트엔드
├── build.gradle      ← 백엔드 빌드 설정
└── gradlew.bat       ← Gradle 래퍼 (Windows)
```

## 2단계: MySQL 설정

### 2-1. MySQL 접속

```bash
mysql -u root -p
# 비밀번호 입력 후 MySQL 프롬프트 진입
```

### 2-2. 데이터베이스 생성 및 스키마 로드

**방법 A: 직접 로드 (추천)**

```bash
# 1. DB 생성 + 스키마 한번에 적용
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS atstudio CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci"
mysql -u root -p atstudio < src/main/resources/schema.sql
```

`schema.sql`에 23개 테이블 전체 DDL이 포함되어 있으므로, 이 한 줄로 DB 구조가 완성됩니다.

**방법 B: Claude에게 맡기기**

Claude Code를 사용 중이라면 그냥 아래처럼 말하면 됩니다:
```
"로컬 MySQL에 atstudio DB 만들고 schema.sql 로드해줘"
```
Claude가 명령어를 생성·실행해줍니다.

**방법 C: JPA 자동 생성 (최소 셋업)**

DB만 생성하고 스키마는 Spring Boot에 맡기는 방법입니다:
```sql
CREATE DATABASE atstudio
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;
EXIT;
```
`application.yml`에 `ddl-auto: update`가 설정되어 있어 백엔드 실행 시 테이블이 자동 생성됩니다.
단, 인덱스·코멘트 등 세부 사항은 schema.sql 대비 누락될 수 있으므로 **방법 A를 권장**합니다.

> **참고**: 스키마 파일 위치: `src/main/resources/schema.sql` (git에 포함되어 있음)

### 2-2b. 시드 데이터 로드 (선택)

구독 플랜 5개, 기본 태그 23개, 관리자 계정 1개가 포함된 초기 데이터입니다:

```bash
mysql -u root -p atstudio < src/main/resources/seed.sql
```

로드 후 관리자 계정으로 바로 로그인할 수 있습니다:
- 이메일: `admin@atstudio.com`
- 비밀번호: `admin123`

> **참고**: 시드 데이터 파일 위치: `src/main/resources/seed.sql` (git에 포함되어 있음)

### 2-3. application.yml 설정 확인

`src/main/resources/application.yml`의 기본 설정:

| 항목 | 기본값 | 환경변수 |
|------|-------|---------|
| DB URL | `jdbc:mysql://localhost:3306/atstudio` | - |
| DB 사용자 | `root` | `SPRING_DATASOURCE_USERNAME` |
| DB 비밀번호 | `1234` | `SPRING_DATASOURCE_PASSWORD` |
| JWT 만료 | 3600000ms (1시간) | `JWT_EXPIRATION` |
| 리프레시 만료 | 1209600000ms (14일) | `JWT_REFRESH_EXPIRATION` |

**개발 환경에서는 기본값(비밀번호 1234)을 그대로 사용할 수 있습니다.** MySQL 비밀번호가 다르다면 환경변수를 설정하거나 yml 파일을 직접 수정하세요.

> 프로덕션에서는 반드시 환경변수를 통해 비밀번호를 주입하세요. yml에 직접 적지 마세요.

## 3단계: 백엔드 실행

프로젝트 루트 디렉터리(`ATStudio/`)에서 실행합니다.

### 바로 실행 (권장)

```bash
# Windows
gradlew.bat bootRun
```

### 빌드 후 실행

```bash
# 테스트 제외 빌드
gradlew.bat build -x test

# 빌드된 jar 실행
java -jar build/libs/atstudio-0.0.1-SNAPSHOT.jar
```

### 실행 성공 확인

터미널에 아래 메시지가 뜨면 성공입니다:

```
Started AtStudioApplication in X.XXX seconds
```

| 확인 URL | 예상 결과 |
|---------|---------|
| `http://localhost:8080` | 응답 있음 (200 또는 리디렉션) |
| `http://localhost:8080/swagger-ui/index.html` | Swagger API 문서 화면 |

> **첫 실행 시:** `spring.jpa.hibernate.ddl-auto: update` 설정에 의해 테이블이 자동 생성됩니다. MySQL에서 `USE atstudio; SHOW TABLES;`로 확인할 수 있습니다.

## 4단계: 프론트엔드 실행

새 터미널을 열고 `frontend/` 디렉터리로 이동합니다.

```bash
cd frontend

# 패키지 설치 (최초 1회 또는 package.json 변경 시)
npm install

# 개발 서버 시작
npm run dev
```

실행 성공 시:

```
  VITE v6.x.x  ready in XXX ms

  ➜  Local:   http://localhost:5173/
  ➜  Network: use --host to expose
```

### 프록시 설정 (자동)

`vite.config.ts`에 프록시가 이미 설정되어 있어, `/api/*` 요청은 자동으로 `http://localhost:8080`으로 전달됩니다. 별도 설정 없이 백엔드와 연동됩니다.

```
프론트엔드 (localhost:5173)
  └─ /api/* 요청 → 자동 프록시 → 백엔드 (localhost:8080)
```

## 자주 발생하는 문제

### Q: MySQL 연결 오류 (Communications link failure / Access denied)

1. MySQL 서비스가 실행 중인지 확인
   - Windows: 작업 관리자 → 서비스 → MySQL80 상태 확인
2. 데이터베이스 `atstudio`가 생성됐는지 확인
   ```sql
   SHOW DATABASES;
   ```
3. `application.yml`의 비밀번호와 MySQL 비밀번호가 일치하는지 확인
   - 기본값: `1234` (MySQL 설치 시 설정한 비밀번호와 달라도 됨)

---

### Q: Gradle 빌드 실패 (Could not find tools.jar / Java 버전 오류)

```bash
java -version
# "17.x.x" 이상이어야 함
```

Java 버전이 맞다면 클린 빌드를 시도합니다:

```bash
gradlew.bat clean build -x test
```

---

### Q: npm 명령어를 찾을 수 없어요 (Windows Bash 환경)

Git Bash나 WSL에서 실행하는 경우 PATH를 먼저 추가하세요:

```bash
export PATH="$PATH:/c/Program Files/nodejs"
npm -version  # 이제 동작해야 함
```

---

### Q: 포트가 이미 사용 중이에요 (Address already in use)

```bash
# 8080 포트를 사용 중인 프로세스 확인 (Windows)
netstat -ano | findstr 8080

# 5173 포트 확인
netstat -ano | findstr 5173

# 해당 PID 프로세스 종료
taskkill /PID <pid번호> /F
```

---

### Q: 프론트엔드에서 API 호출이 안 돼요 (CORS 오류 없는데 404)

백엔드가 실행 중인지 확인하세요. 프록시는 백엔드가 `localhost:8080`에서 동작할 때만 작동합니다.

---

### Q: HHH90003004 경고가 터미널에 나와요

`TrackRepository`에서 발생하는 Hibernate 경고입니다. 기능 동작에는 문제 없습니다. 데이터가 10,000건 이상이 되면 전환을 검토하면 됩니다.
