## 1. 핵심 비즈니스 흐름

### 흐름 A: 음원 업로드 및 공개 (관리자)

관리자가 새 음원을 등록하고 사용자에게 공개하는 과정입니다.

```
1. 관리자 로그인 (POST /api/auth/login)
2. 태그 확인 또는 생성 (GET /api/tags, POST /api/tags)
   - 태그는 음원에 연결할 장르/분위기/악기 카테고리
3. 음원 파일 업로드 (POST /api/tracks — multipart/form-data)
   - title, bpm, tonality, audioFile 필수
   - 업로드 직후 is_active=0 (비공개 상태)
   - 비동기로 preview_file 생성 시작 (저품질 미리듣기용)
4. 필요 시 앨범에 추가 (POST /api/albums/{id}/tracks)
5. 음원 활성화 (PUT /api/tracks/{id} with isActive: true)
   - 이 시점부터 공개 목록에 노출됨
```

**중요 사항:**
- 업로드만으로 음원이 공개되지 않습니다. `isActive: true`로 별도 활성화가 필요합니다.
- preview_file 생성 실패 시 NULL로 유지되며, 스트리밍 시 원본 audio_file을 폴백으로 사용합니다.

---

### 흐름 B: 음원 검색 및 미리듣기 (비회원 포함)

```
1. 음원 목록 조회 (GET /api/tracks — 비인증 가능)
   - 키워드, 태그, BPM 범위, 조성, 정렬 필터 적용 가능
   - is_active=1인 음원만 반환
2. 음원 상세 조회 (GET /api/tracks/{id} — 비인증 가능)
3. 음원 스트리밍 미리듣기 (GET /api/tracks/{id}/stream — 비인증 가능)
   - preview_file 있으면 저품질 파일 스트리밍
   - preview_file 없으면 원본 audio_file 폴백
4. 로그인 사용자: 재생 시작 시 재생기록 저장
   (POST /api/play-histories — 프론트엔드가 명시적으로 호출)
```

---

### 흐름 C: 구독 가입 및 음원 다운로드 (구독자)

```
1. 구독 플랜 목록 조회 (GET /api/subscriptions — 비인증 가능)
2. 구독 신청 (POST /api/user-subscriptions)
   - billingCycle: MONTHLY 또는 YEARLY
   - BUSINESS 타입 회원은 기업 인증 승인 후에만 가능
3. 구독 상태 확인 (GET /api/utils/subscription-status)
4. 다운로드 가능 횟수 확인 (GET /api/utils/download-count)
5. 음원 다운로드 (GET /api/tracks/{id}/download)
   - 일일 한도 초과 시 403 DOWNLOAD_LIMIT_EXCEEDED
   - 라이선스 자동 발급 (최초 다운로드 시만, 중복 발급 안 함)
6. 발급된 라이선스 확인 (GET /api/licenses/me)
```

**다운로드 시 내부 처리 순서:**
```
① 구독 상태 확인 (is_active = ACTIVE)
② 오늘 다운로드 수 COUNT 쿼리로 확인 vs plan.download_per_day 비교
③ audio_file 스토리지에서 조회
④ track_downloads 레코드 저장
⑤ licenses 테이블 기존 라이선스 확인 → 없으면 UUID 신규 발급
⑥ 파일 반환 (Content-Disposition: attachment)
```

---

### 흐름 D: 기업 인증 신청 (BUSINESS 회원)

BUSINESS 타입 회원이 기업 구독을 이용하려면 기업 인증 심사를 먼저 통과해야 합니다.

```
1. BUSINESS 타입으로 회원가입
2. 기업 인증 심사 신청 (POST /api/company-certifications)
   - 사업자등록증 등 서류 파일 업로드
   - 신청 직후 status: PENDING
3. 신청 상태 확인 (GET /api/company-certifications/me)
4. 관리자 심사:
   - 승인(APPROVED) → certification_code 자동 발급 → 구독 가능
   - 보완 요청(REVISION_REQUESTED) → adminNote에 사유 포함
   - 반려(REJECTED) → 관리자를 통해 재신청 안내
5. 승인 후 구독 신청 가능 (POST /api/user-subscriptions)
```

---

### 흐름 E: 재생목록 생성 및 관리 (구독자)

```
1. 재생목록 목록 조회 (GET /api/playlists)
   - 현재 보유 재생목록 수 확인 (최대 3개)
2. 재생목록 생성 (POST /api/playlists)
   - count >= 3이면 생성 버튼을 프론트엔드에서 미리 숨겨야 함
   - 서버에서도 3개 초과 시 409 PLAYLIST_LIMIT_EXCEEDED 반환
3. 트랙 추가 (POST /api/playlists/{id}/tracks)
   - 트랙 목록 또는 상세 화면의 "재생목록에 추가" 버튼에서 호출
4. 트랙 순서 변경 (PUT /api/playlists/{id}/tracks)
   - 드래그앤드롭 후 전체 순서를 배열로 전송
5. 재생목록 삭제 (DELETE /api/playlists/{id})
   - 포함된 playlist_tracks도 함께 삭제
```

---

### 흐름 F: 구독 변경 (업그레이드/다운그레이드)

```
1. 현재 구독 확인 (GET /api/user-subscriptions/me)
2. 변경 미리보기 (GET /api/utils/subscription-change-preview?subscriptionId=X&billingCycle=Y)
   - changeType: UPGRADE 또는 DOWNGRADE
   - proratedAmount: 추가 결제 또는 크레딧 금액
   - effectiveDate: 새 플랜 적용 일자
3. 구독 변경 요청 (PUT /api/user-subscriptions/me)
   - UPGRADE: 즉시 적용, proratedAmount 추가 결제
   - DOWNGRADE: 현재 기간 종료 후 자동 적용 (pending 저장)
```

**UPGRADE 흐름:**
```
변경 요청 → 새 플랜 즉시 적용 → proratedAmount PG 결제
→ subscription_payments 기록 → 즉시 새 혜택(다운로드 한도 등) 적용
```

**DOWNGRADE 흐름:**
```
변경 요청 → pendingSubscriptionId, pendingBillingCycle 저장
→ 현재 플랜 expiresAt까지 유지 → expiresAt에 자동 플랜 전환
```

---

### 흐름 G: 구독 취소

```
1. 구독 취소 (DELETE /api/user-subscriptions/me)
2. status가 CANCELLED로 변경되지만 expiresAt은 변경되지 않음
3. expiresAt까지 다운로드, 재생목록, 채널 등록 서비스 이용 가능
4. expiresAt 이후 자동 만료 (SUBSCRIBER 권한 소멸)
```

**취소 ≠ 즉시 서비스 종료.** expiresAt까지는 유예 기간으로 서비스가 유지됩니다.

---

### 흐름 H: 다운로드 큐 일괄 다운로드

```
1. 음원 목록/상세에서 "큐에 추가" (POST /api/download-queue/{trackId})
2. 큐 목록 확인 (GET /api/download-queue)
3. 큐 내 트랙을 순차적으로 다운로드:
   for each trackId in queue:
     GET /api/tracks/{trackId}/download
4. 다운로드 완료 후 큐에서 제거 (DELETE /api/download-queue/{trackId})
```

**중요:** 다운로드 중 페이지를 이탈하면 `beforeunload` 이벤트로 경고 표시. ZIP 일괄 다운로드는 미지원이며, 프론트엔드가 개별 API를 순차 호출합니다.

## 3. 구독 상태 머신

```
없음(미구독)
    │
    ▼ [구독 신청: POST /api/user-subscriptions]
    │
ACTIVE ────────────────────────────────────────┐
    │                                           │
    ├──[업그레이드: PUT /api/user-subscriptions/me]  │
    │   → 즉시 새 플랜 적용 + proratedAmount 결제    │
    │   → ACTIVE 유지, 새 expiresAt                │
    │                                           │
    ├──[다운그레이드: PUT /api/user-subscriptions/me]│
    │   → pendingSubscriptionId 저장            │
    │   → 현재 플랜 expiresAt까지 유지           │
    │   → expiresAt 도달 시 자동 새 플랜 적용    │
    │   → ACTIVE 유지                           │
    │                                           │
    └──[취소: DELETE /api/user-subscriptions/me]│
        ↓                                       │
    CANCELLED ←────────────────────────────────┘
        │
        │ (expiresAt까지 서비스 이용 가능 — 유예기간)
        │
        ▼ [expiresAt 도달]
    만료 (구독 혜택 소멸)
```

### 상태별 의미

| 상태 | 설명 | 다운로드 가능 | 재생목록 접근 |
|------|------|-------------|-------------|
| 없음 | 구독한 적 없거나 만료 후 | X | X |
| ACTIVE | 정상 구독 중 | O | O |
| CANCELLED | 취소했지만 유예기간 내 | O (expiresAt까지) | O (expiresAt까지) |

### 구독 변경 비용 계산 (UPGRADE 시)

```
proratedAmount = (newDailyRate - oldDailyRate) × 남은 일수

dailyRate = priceMonthly / 30  또는  priceYearly / 365
남은 일수 = expiresAt - 오늘 날짜
```

사전 확인: `GET /api/utils/subscription-change-preview`로 결제 전 금액을 먼저 확인할 수 있습니다.

## 4. 기업 인증 상태 머신

```
없음 (미신청)
    │
    ▼ [신청: POST /api/company-certifications]
    │
PENDING (검토 대기)
    │
    ├──[관리자 승인: PUT /api/company-certifications/{id}]
    │   status: "APPROVED"
    │       ↓
    │   APPROVED (승인 완료)
    │   certification_code 발급
    │   → BUSINESS 구독 신청 가능
    │
    ├──[관리자 보완 요청: PUT /api/company-certifications/{id}]
    │   status: "REVISION_REQUESTED"
    │       ↓
    │   REVISION_REQUESTED
    │   adminNote에 사유 포함
    │   → 관리자가 이메일 또는 1:1 문의로 재신청 안내
    │
    └──[관리자 반려: PUT /api/company-certifications/{id}]
        status: "REJECTED"
            ↓
        REJECTED
        → 관리자가 이메일 또는 1:1 문의로 재신청 안내
```

**주의:** 현재 REVISION_REQUESTED/REJECTED 상태에서 자동 재신청 UI는 제공하지 않습니다. 사이트 안정화 후 자동화 예정입니다.

## 5. 문의 상태 흐름

```
OPEN (접수됨)
    │
    ├──[관리자 최초 답변: POST /api/questions/{id}/answers]
    │       ↓ 자동 전환
    │   IN_PROGRESS (처리 중)
    │       │
    │       └──[관리자 완료 처리: PUT /api/questions/{id}/status]
    │               status: "RESOLVED"
    │                   ↓
    │               RESOLVED (해결됨)
    │                   │
    │                   └──[관리자 종결: PUT /api/questions/{id}/status]
    │                           status: "CLOSED"
    │                               ↓
    │                           CLOSED (종결)
    │
    └──[관리자 직접 종결: PUT /api/questions/{id}/status]
            status: "CLOSED"
                ↓
            CLOSED
```

**삭제 규칙:** 사용자는 OPEN 상태인 본인 문의만 삭제할 수 있습니다. 관리자는 모든 상태의 문의를 삭제 가능합니다.

## 6. 도메인 개념 정리

### Track (음원) vs Album (앨범) vs Playlist (재생목록)

| 개념 | 생성자 | 관계 | 특징 |
|------|--------|------|------|
| Track | 관리자 | 단독 존재 가능 | 플랫폼의 핵심 상품 |
| Album | 관리자 | 여러 Track 묶음 | 테마/아티스트별 큐레이션 |
| Playlist | 구독자 (본인) | 구독자가 직접 선택한 Track 묶음 | 개인 큐레이션, 최대 3개 |

- Album은 관리자가 기획하는 공식 컬렉션입니다.
- Playlist는 구독자가 개인적으로 만드는 컬렉션입니다.

### License (라이선스) vs Company Certification (기업 인증)

| 개념 | DB 테이블 | 트리거 | 목적 |
|------|----------|--------|------|
| License | `licenses` | 트랙 다운로드 시 자동 발급 | 트랙 사용 권한 증명 |
| Company Certification | `company_certifications` | BUSINESS 회원 수동 신청 | 기업 구독 자격 심사 |

두 개념은 완전히 별개입니다. 혼동하지 마세요.

### Download Queue (다운로드 큐) vs Cart (장바구니)

다운로드 큐는 구매 개념이 없습니다. 결제 없이 여러 트랙을 모아서 순차 다운로드하는 임시 컬렉션입니다. "장바구니"라고 부르지 않습니다.

### isActive 패턴 (소프트 삭제)

```
Track: is_active=0 → 공개 목록에서 숨겨짐 (실제 파일 보존)
User: is_deleted=1 → 탈퇴 처리 (소프트 삭제)
Subscription: status=CANCELLED → 유예기간 후 만료
```

실제 데이터를 삭제하지 않아 감사 추적과 복구가 가능합니다.

### 일일 다운로드 한도 리셋 시점

매일 자정(00:00:00)에 리셋됩니다. 정확한 리셋 시각은 `GET /api/utils/download-count` 응답의 `nextResetAt` 필드로 확인할 수 있습니다.
