# 관리자 기능 점검표

## 대시보드

- [ ] 전체 회원 수, 공개 음악 수, 활성 구독자 수가 보입니다.
- [ ] 최근 가입 회원 5명의 이메일, 닉네임, 역할, 가입일이 보입니다.
- [ ] 불러오기 실패 시 오류와 다시 시도 버튼이 보입니다.
- [ ] 빠르게 다시 시도해도 오래된 응답이 최신 화면을 덮지 않습니다.

## 회원과 구독

- [ ] 회원 목록 검색/페이지 이동과 상세 조회가 됩니다.
- [ ] 자기 강등과 마지막 관리자 강등이 화면과 서버에서 거절되고, 다른 관리자 강등 뒤 현재 권한 화면이 다시 동기화됩니다.
- [ ] 요금제 목록에는 비활성 요금제도 보입니다.
- [ ] 사용자 구독은 미리보기 → 요청 → 승인 → 실행으로 보정되고, 창을 닫았다 열어도 진행 중 건이 이어집니다.
- [ ] 구독 보정 사유와 전후 상태·결과가 감사에 남고, 같은 건이 중복 실행되지 않습니다.
- [ ] 일반 구독 관리와 결제 사고/환불 처리가 서로 섞이지 않습니다.

## 음악, 앨범, 태그

- [ ] 음악 업로드/수정 시 길이와 파형이 같은 분석 결과로 저장되고 손상 파일은 부분 저장 없이 거절됩니다.
- [ ] 새 썸네일은 1:1만 저장되며, 기존 비정사각형 썸네일은 교체 전까지 그대로 유지됩니다.
- [ ] 기존 음악 분석 dry-run은 읽기 전용 보고만 만들고 실제 backfill은 실행하지 않습니다.
- [ ] 앨범 생성/수정/음악 추가/삭제/순서 변경이 됩니다.
- [ ] 태그 생성/수정의 공백·문자 정규화와 중복 안내가 일치하고 실패 뒤 모달·목록·입력값이 유지됩니다.
- [ ] 비공개 저장 경로나 내부 파일 키가 화면에 보이지 않습니다.

## 문의와 공지

- [ ] 문의 목록, 답변, 상태 변경이 됩니다.
- [ ] 공지 작성/수정 뒤 공개 화면에 반영됩니다.
- [ ] 첨부파일은 권한 확인 뒤 내려받을 수 있습니다.

## 기업 인증

- [ ] 신청 목록과 상세 정보가 보입니다.
- [ ] 문서는 관리자 전용 경로로만 내려받을 수 있습니다.
- [ ] 승인/반려 처리와 최대 500자 사유가 기록됩니다.
- [ ] 같은 신청을 동시에 처리할 때 오래된 변경이 덮어쓰지 않습니다.
- [ ] 검토/문서 접근 감사 기록에는 파일 내용, 경로, 토큰, 민감 프로필이 들어가지 않습니다.

## 화이트리스트

- [ ] 상태/검색 조건으로 목록을 볼 수 있습니다.
- [ ] 허용된 상태 전이만 처리됩니다.
- [ ] CSV 내보내기와 기존 배치 다시 받기가 됩니다.
- [ ] 내보내기 배치는 생성 뒤 내용이 바뀌지 않습니다.
- [ ] CSV 수식으로 해석될 수 있는 값이 안전하게 처리됩니다.

## 결제 운영

- [ ] 주문, 자동결제, 결제내역, 사고, 영수증, 감사, 정산, 환불, 권한 보정 탭이 열립니다.
- [ ] 사고 목록에서 상태를 바꿔도 결제/구독 상태가 자동 변경되지 않습니다.
- [ ] 정산 CSV 검토는 회계 증거이며 구독/환불/결제사 상태를 변경하지 않습니다.
- [ ] 환불 요청, 승인, 실행이 같은 환불 건과 같은 키를 사용합니다.
- [ ] 환불 성공 뒤 권한 보정은 별도 미리보기/요청/승인/실행으로 진행됩니다.
- [ ] 카드번호, 결제 키, billing key, authKey, customerKey가 화면이나 메모에 보이지 않습니다.
- [ ] 결제사 원문 키 대신 `REF-`로 시작하는 지원 참조값만 보입니다.
- [ ] 영수증 탭에서 정상 HTTPS 주소만 `열기` 링크가 되고, 비정상 주소는 지원 참조값 또는 `링크 확인 필요`로 표시되며 클릭되지 않습니다.

## 사이트 설정

- [ ] `/admin/settings`에서 기업 인증 안내문을 불러옵니다.
- [ ] 저장하면 `COMPANY_CERT_GUIDE` 값이 생성 또는 변경됩니다.
- [ ] 값이 없을 때 빈 안내문으로 열리고 새 값을 저장할 수 있습니다.

## 운영 경계

- [ ] 실제 Toss 키나 실제 결제를 사용하지 않았습니다.
- [ ] 유지 중인 DB에 패치를 적용하지 않았습니다.
- [ ] 로컬 구독 보정을 Toss 결제·환불 성공으로 오인하지 않았습니다.
- [ ] 실제 Track backfill과 기존 썸네일 일괄 변경을 실행하지 않았습니다.
- [ ] 전체 브라우저 점검과 운영 배포를 구현 완료 근거와 구분했습니다.
- [ ] 공개 개발 서버는 운영 담당자가 승인한 안전한 브랜치/접근 방식만 사용했습니다.
- [ ] 자동 삭제 보존기간, 악성파일 검사, 소셜 전용 탈퇴는 정책 검토 중임을 결함과 구분했습니다.
