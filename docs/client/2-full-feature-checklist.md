# 2. 전체 기능 체크리스트

> 목적: 클라이언트가 ATStudio의 주요 기능을 빠짐없이 확인할 수 있게 정리합니다.

## 결과 표시

| 표시 | 의미 |
|------|------|
| 통과 | 기대한 대로 동작함 |
| 실패 | 깨졌거나 헷갈리거나 결과가 맞지 않음 |
| 보류 | 계정, 데이터, 설정이 없어 확인하지 못함 |
| 논의 | 동작은 하지만 정책/디자인 결정을 다시 논의하고 싶음 |

결제 항목은 승인된 테스트/인수 환경과 Toss 테스트 결제수단으로만 진행합니다. 실제 카드, 실제 금액, live key는 사용하지 않습니다.

## A. 비회원 공개 화면

### A-1. 홈

| 확인할 것 | 정상이라면 |
|-----------|------------|
| 홈 화면을 연다. | 화면이 깨지지 않고 열린다. |
| 상단 메뉴를 누른다. | 홈, 음원, 앨범, 구독, 공지, 로그인으로 이동한다. |
| 음원/앨범 영역을 본다. | 데이터가 있으면 보이고, 없으면 화면이 깨지지 않는다. |
| 하단 플레이어를 본다. | 재생 버튼과 진행 상태가 다른 버튼을 가리지 않는다. |

### A-2. 음원 목록과 검색

| 확인할 것 | 정상이라면 |
|-----------|------------|
| 음원 목록을 연다. | 행 단위 목록이 읽기 쉽다. |
| 곡 제목을 확인한다. | 제목이 명확히 보인다. |
| 제목 아래 용도/가이드 문구를 확인한다. | "유튜브용", "쇼츠용", 해시태그형 문구처럼 검색 힌트가 보인다. |
| 곡 제목으로 검색한다. | 맞는 곡이 나온다. |
| 용도/가이드 문구로 검색한다. | 맞는 곡이 나온다. |
| 장르/분위기/용도 필터를 누른다. | 목록이 바뀌고 화면이 깨지지 않는다. |
| BPM 필터를 누른다. | 조건에 맞는 곡이 있으면 목록에 반영된다. |
| 비로그인 상태에서 좋아요를 누른다. | 로그인이 필요하다고 안내한다. |
| 비구독 상태에서 다운로드를 누른다. | 구독이 필요하다고 안내한다. |

### A-3. 음원 상세와 플레이어

| 확인할 것 | 정상이라면 |
|-----------|------------|
| 음원 상세를 연다. | 곡 정보, 태그, 버튼이 보인다. |
| 상세에서 재생한다. | 하단 플레이어에 현재 곡이 반영된다. |
| 재생 중 다른 화면으로 이동한다. | 플레이어가 안정적으로 유지된다. |
| 구독 없이 다운로드를 시도한다. | 구독 안내가 나온다. |

### A-4. 앨범

| 확인할 것 | 정상이라면 |
|-----------|------------|
| 앨범 목록을 연다. | 앨범 카드 또는 빈 상태가 보인다. |
| 앨범 상세를 연다. | 앨범 정보와 포함 곡이 보인다. |
| 앨범 안의 곡을 누른다. | 곡 상세 또는 재생 동작이 정상이다. |

### A-5. 공지

| 확인할 것 | 정상이라면 |
|-----------|------------|
| 공지 목록을 연다. | 공지 목록 또는 빈 상태가 보인다. |
| 공지 상세를 연다. | 제목, 내용, 첨부 영역이 읽기 쉽다. |
| 첨부파일이 있으면 내려받는다. | 파일이 내려받아지거나 명확한 오류가 나온다. |

## B. 회원 기능

### B-1. 회원가입과 로그인

| 확인할 것 | 정상이라면 |
|-----------|------------|
| 개인 회원가입을 한다. | 필수값이 명확하고 가입할 수 있다. |
| 기업 회원가입을 한다. | 회사 정보 입력란이 나오고 회사명은 비워둘 수 없다. |
| 이메일/닉네임 중복을 확인한다. | 중복이면 이해할 수 있는 메시지가 나온다. |
| 이메일 인증 화면을 확인한다. | 성공/실패 상태가 명확하다. |
| 로그인한다. | 로그인 상태로 전환된다. |
| 잘못된 정보로 로그인한다. | 기술적인 내부 오류가 아니라 알기 쉬운 메시지가 나온다. |
| 로그아웃한다. | 로그인 상태와 플레이어 상태가 정리된다. |
| 비밀번호를 재설정한다. | 요청과 재설정 결과가 명확하다. |

### B-2. 프로필

| 확인할 것 | 정상이라면 |
|-----------|------------|
| 프로필을 연다. | 내 정보가 보인다. |
| 닉네임, 전화번호, 직무를 수정한다. | 새로고침 후에도 저장되어 있다. |
| 기업 회원의 회사명을 수정한다. | 수정할 수 있고, 빈 회사명은 막힌다. |
| 비밀번호를 바꾼다. | 성공/실패 안내가 나온다. |
| 회원 탈퇴를 시도한다. | 확인 절차가 있다. |
| 구독 중인 테스트 계정으로 회원 탈퇴한다. | 탈퇴가 끝나고 다음 자동 결제가 멈춘다. 이미 낸 금액은 자동 환불되지 않는다. |

### B-3. 좋아요와 재생 기록

| 확인할 것 | 정상이라면 |
|-----------|------------|
| 음원이나 앨범에 좋아요를 누른다. | 좋아요 목록에 나타난다. |
| 좋아요를 취소한다. | 목록에서 사라진다. |
| 곡을 재생한다. | 로그인 상태라면 재생 기록에 남는다. |
| 재생 기록을 삭제한다. | 선택 또는 전체 삭제가 반영된다. |

### B-4. 문의

| 확인할 것 | 정상이라면 |
|-----------|------------|
| 문의 목록을 연다. | 내가 작성한 문의가 보인다. |
| 문의를 작성한다. | 제목, 내용, 첨부 규칙이 이해된다. |
| 문의 상세를 연다. | 문의와 답변 영역이 보인다. |
| 문의를 삭제한다. | 삭제 전 확인이 나온다. |

## C. 구독자 기능

### C-1. 새 구독

| 확인할 것 | 정상이라면 |
|-----------|------------|
| 구독 플랜 화면을 연다. | 플랜, 월간/연간, 개인/기업 구분이 이해된다. |
| 플랜을 선택한다. | 결제 화면으로 이동한다. |
| Toss 카드 정기결제를 등록한다. | 카드 등록 흐름이 열린다. |
| 결제를 완료한다. | 구독이 활성화되고 내 구독 화면에 표시된다. |
| 결제 완료 뒤 새로고침하거나 같은 완료 주소를 다시 연다. | 구독과 완료 결제가 한 번만 반영된다. |
| 결제 화면을 벗어났다가 돌아온다. | 구독 화면에서 다시 시도할 수 있다. |
| 기업 인증 없이 기업 플랜을 시도한다. | 기업 인증이 필요하다고 안내한다. |

### C-2. 플랜 변경

| 확인할 것 | 정상이라면 |
|-----------|------------|
| 상위 플랜으로 변경한다. | 오늘 결제할 차액을 미리 보여준다. |
| 업그레이드를 확정한다. | 결제 성공 후 상위 플랜이 바로 적용된다. |
| 업그레이드 완료 뒤 새로고침하거나 같은 작업을 다시 누른다. | 이미 완료된 변경이 중복 결제로 이어지지 않는다. |
| 업그레이드하면서 월간/연간도 바꾼다. | 플랜은 바로 바뀌고, 결제 주기는 다음 결제일부터 바뀐다고 안내한다. |
| 하위 플랜으로 변경한다. | 즉시 결제 없이 다음 결제일부터 적용된다고 안내한다. |
| 월간/연간만 바꾼다. | 다음 결제일부터 적용된다고 안내한다. |
| 예약된 변경을 취소한다. | 현재 플랜과 결제 주기가 유지된다. |
| 결제수단이 없거나 만료된 상태에서 업그레이드한다. | 결제수단을 다시 등록하라고 안내한다. |

### C-3. 구독 취소와 재유지

| 확인할 것 | 정상이라면 |
|-----------|------------|
| 구독을 취소한다. | 다음 자동 결제는 중단되지만 만료일까지 이용 가능하다. |
| 취소 후 내 구독 화면을 본다. | 만료일까지 이용 가능하다는 설명이 보인다. |
| 만료 전 다시 유지한다. | 저장된 결제수단이 유효하면 활성 상태로 돌아온다. |
| 취소 상태에서 플랜 변경을 시도한다. | 변경 확정 시 구독 취소가 철회된다는 안내가 나온다. |

결제 트랜잭션, 동시성, MySQL 검증은 클라이언트가 직접 확인하지 않습니다. 내부 기술 근거는 [결제 무결성 종료 보고서](../audit/p1-payment-integrity-closure-20260715.md)를 봅니다.

### C-4. 구독자 전용 기능

| 확인할 것 | 정상이라면 |
|-----------|------------|
| 재생목록 화면을 연다. | 구독자는 접근할 수 있다. |
| 재생목록을 만든다. | 현재 플랜 한도를 따른다. |
| 곡을 재생목록에 추가한다. | 선택한 곡이 추가된다. |
| 음원을 다운로드한다. | 파일이 내려받아지고 일 다운로드 수가 반영된다. |
| 일 다운로드 한도를 넘긴다. | 한도 초과 안내가 나온다. |
| 다운로드 기록을 연다. | 내려받은 기록이 보인다. |
| 라이선스 목록과 상세를 연다. | 내용이 읽기 쉽다. |

## D. 화이트리스트 채널

| 확인할 것 | 정상이라면 |
|-----------|------------|
| 화이트리스트 채널 화면을 연다. | 유튜브 채널 정보를 저장하고 등록 요청할 수 있다는 설명이 보인다. |
| 채널명과 링크를 입력해 저장한다. | 초안 채널로 저장된다. |
| 유튜브 핸들을 입력한다. | 입력한 값이 저장된다. |
| 유튜브 채널 ID를 입력한다. | 입력한 값이 저장된다. |
| 잘못된 URL을 입력한다. | 올바른 링크 예시를 알려준다. |
| 여러 초안 채널을 저장한다. | 단순 저장은 등록 한도와 별개로 가능하다. |
| 대표 채널을 설정한다. | 대표 채널이 하나로 표시된다. |
| 구독 없이 등록 요청한다. | 구독이 필요하다고 안내한다. |
| 구독 상태에서 등록 요청한다. | 플랜 한도 안이면 요청/처리 상태가 된다. |
| 플랜 한도를 넘겨 등록 요청한다. | 한도 초과 안내가 나온다. |
| 처리 중이거나 등록된 채널을 수정한다. | 운영자 재확인이 필요한 상태로 안내되거나 전환된다. |
| 초안/반려 채널을 삭제한다. | 목록에서 제거된다. |
| 내보내기/등록 완료 채널을 삭제한다. | 바로 사라지지 않고 해제 요청 상태가 된다. |

## E. 기업 인증

| 확인할 것 | 정상이라면 |
|-----------|------------|
| 기업 회원이 구독 전 기업 인증 화면을 연다. | 신청 화면을 사용할 수 있다. |
| 개인 회원이 기업 인증 화면을 연다. | 접근이 막히거나 명확히 안내된다. |
| 서류를 제출한다. | 심사 중 상태가 된다. |
| 서류 없이 제출한다. | 필수 서류 안내가 나온다. |
| 지원하지 않는 파일을 제출한다. | 파일 형식 오류가 나온다. |
| 인증 상태를 확인한다. | 심사 중, 승인, 보완 요청, 반려 상태가 명확하다. |
| 관리자가 보완 요청한다. | 사용자가 사유를 보고 대체 서류를 제출할 수 있다. |
| 관리자가 반려한다. | 사용자가 사유를 보고 새 신청을 시작할 수 있다. |
| 관리자가 승인한다. | 인증 코드/상태가 보이고 기업 구독을 진행할 수 있다. |

## F. 오류와 사용성

| 확인할 것 | 정상이라면 |
|-----------|------------|
| 주요 화면을 새로고침한다. | 적절한 화면에 남거나 명확히 이동한다. |
| 로그아웃 상태로 보호된 화면을 연다. | 로그인 화면으로 안내된다. |
| 구독 없이 구독자 전용 화면을 연다. | 구독 안내로 이동한다. |
| 로딩이 필요한 화면을 연다. | 로딩 상태가 보인다. |
| 서버 오류가 발생한다. | 알기 쉬운 오류 화면이나 메시지가 나온다. |
| 모바일 화면을 본다. | 글자, 버튼, 플레이어, 입력폼이 겹치지 않는다. |
