## Withdrawal boundary — exact result of the inspected path

1. Password authentication, last-admin safeguard and pending-charge guard run before mutation (`UserService.java:155–186`).
2. Billing and active subscription cancellation can occur, and issued keys cause an after-commit external cleanup request (`:188–197`).
3. Track likes, downloads and licenses are deleted; channel cleanup depends on status (`:200–208`).
4. User row is marked deleted and refresh digest cleared; other profile fields remain (`:210`, `User.java:83`).
5. No cleanup invocation for social accounts, playlists, consents, certification documents/audits, token tables or payment/receipt records appears in this method. This observation does not settle whether a record should be removed or retained.

The mismatch has two directions: some identifying data remains while evidence that may support the proposed continuing-content rights is deleted. A single “delete everything” patch would create new problems. The next decision is a per-record treatment table, followed by a narrow coordinated implementation and restore check.
